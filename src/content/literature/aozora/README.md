# 정본 문학책 — 青空文庫 (아오조라)

설계: 아오조라 「책자」 재설계(2026-10-12 KST, 오너 결정 D1–D6). 이 폴더는 공개 책으로 게시할 퍼블릭 도메인
원작의 **원문 정본**과 **권리 기록**을 둔다. 원문은 리포에 두고, `scripts/build-literature.mjs`가 결정적으로
`chapters.json`(장별 `rawText`·저자 루비 잠금·크레딧)을 만든다. 게시(공개 `reading_materials` 삽입 →
관리자 1회 분석)는 별도 관리자 단계다 — 이 폴더의 파일만으로는 아무것도 공개되지 않는다.

같은 빌드가 루트에 두 파일을 더 만든다(손으로 고치지 않는다 — `--check`가 낡음을 잡는다):
- `index.generated.js` — 관리자 게시 API(`/api/admin/literature`)가 정적 import하는 책 목록(장 원문 포함, 서버 전용).
- `manifest.generated.json` — 뷰어 정본 대조표(장 원문 SHA-256 + 크레딧). 뷰어 출처 줄은 이 표로 그린다.

## 게시 (관리자) — 분석 → 검수·편집 → 공개 (P0-3 · P0-4)

1. 관리자 → **📚 정본 문학책** 탭에서 작품의 권리 근거(초출·몰년·관할·도서 카드)를 확인하고 「게시」.
   장마다 **비공개** 자료가 생기고(소유자 = 게시한 관리자, `status: pending`), 같은 화면이 장마다 한 번씩 바로 분석한다
   (뷰어 「이 챕터 분석하기」와 같은 경로 — 분석 말미에 저자 루비 잠금 + 검수 힌트). 화면을 닫으면 멈추고, 다시 열어 「이어서 분석」.
   같은 책을 다시 눌러도 없는 장만 넣는다(book key + 장 순서 멱등). 정본과 원문이 다른 장·중복 장이 있으면
   아무것도 넣지 않고 「확인 필요」로 보인다.
   준비 안 된 작품이 둘 이상이면 표 위 **「N편 모두 게시·분석」** 한 번으로 차례로 준비·분석한다(확인 창 한 번 — 작품 목록).
   멈췄다가 다시 누르면 남은 작품·남은 장부터. 검수·공개는 하지 않는다(작품마다 사람이 — 2·3단계).
2. **검수** — 장 링크를 열어 「뜻 확인 필요」 목록에서 문맥 뜻 제안을 고르거나(「문맥 제안」), 사전 뜻을 고르거나,
   그대로 두기로 확정한다. 단어 경계 묶기·나누기, 뜻·발음 교정도 이때 한다(원문은 고칠 수 없다). 확인이 0이 되면
   관리자 화면에서 그 장 「검수 완료」. 다시 분석하면 그 장은 다시 검수해야 한다.
3. 「공개」 — 모든 장이 분석·검수 완료일 때만 공개로 바뀌고 산책 › 함께 읽는 글에 책 카드로 보인다.
   사용자는 「분석 전」·「검수 전」 장을 보지 않는다. 분석·검수 결과는 모두가 같이 쓰고, 단어 상태만 사람마다 따로다.

### 검수 힌트 `review.json` (선택)

사전 검토자가 「사전 뜻만으로는 이 자리에서 틀리거나 부족한 낱말」에 문맥 뜻 제안을 단다(고어·사투리·한자 차용 표기·
의성어 등 — 예: 十米의 米 = 미터, お手々がちんちんする = 시려서 얼얼하다). 뜻 자체를 바꾸지 않고 「뜻 확인 필요」 표식과
제안만 붙는다 — 확정은 검수자가 한다.

```json
{ "schemaVersion": 1, "reviewedBy": "claude",
  "hints": [ { "chapter": 1, "form": "米", "nth": 1, "meaning": "미터(m)", "note": "十米 = 10미터" } ] }
```
- `form`은 그 장 본문에 있는 글자 그대로(공백 없음), `nth`는 그 장에서 몇 번째(기본 1). 빌드가 위치로 풀고, 원문에 없거나
  겹치면 빌드가 실패한다. 분석기가 그 범위와 같은 토큰(없으면 범위를 품은 토큰)에 붙인다.
- `meaning` ≤ 80자, `note` ≤ 120자(검수자용 근거 — 「뜻 확인 필요」 목록에만 보인다).

## 작품 추가 절차 (2026-10-14 KST 간결화 — 설계 `docs/literature-pipeline.md`)

```
npm run literature:candidates                       # ① 후보 — 공식 색인 + 접속 순위, 선정 기준 통과작만 유명한 순
npm run literature:add -- <作品ID> --level "N2 상급" --approve claude   # ② 받기·해시·변환·entry 초안·진단(한 번에)
#   ③ 사람 일: display.titleKo · cover(새 색) · motif(새 표지 문양) · (선택) review.json
npm run literature:build && npm test                # ④ 빌드·계약
```

- **① 후보**(`scripts/literature/candidates.mjs`): 青空文庫 공식 색인(`list_person_all_extended_utf8.zip`)과 2020–22년 접속 순위로
  선정 기준(아래)을 통과하는 작품을 유명한 순으로 보인다. `--all`이면 기준 밖 작품도 이유와 함께(왜 못 넣는지).
- **② 추가**(`scripts/literature/add-work.mjs`): 텍스트 zip 받기 → `sourceSha256` → Shift_JIS를 JIS X 0208 표준 대응으로
  UTF-8 변환(`source.txt`, 예전 iconv 절차와 바이트까지 같다) → `textSha256` → 원문 파싱으로 외자·경고·장 나눔 진단 →
  `entry.json` 초안(제목·저자·연도·주소·해시·읽기, 같은 작가의 `authorKo`). 진단이 하나라도 걸리면 아무것도 쓰지 않는다.
  - `--approve <역할>`은 1차 판정(일본 보호기간 — KR은 JP를 따름)이 만료일 때만 권리를 `approved`로 기록한다. 기록하는 사람은 도서 카드의
    초출·몰년을 본 뒤 붙인다(법률 판단을 대신하지 않는다 — 관리자 「게시」가 사람 확인 지점인 것은 그대로).
  - 색인·판권 어디에도 초출이 없으면(사후 출간작) `publishedYear`를 사람이 채운다(수록 표에 2차 출처라고 적는다).
- **선정 기준**(`aozoraJurisdictionVerdict` — 일본 보호기간 만료. 오너 개정 2026-10-15 KST 「일본에서만 끝나면 그만」):
   - 文字遣い種別 `新字新仮名`, 미해결 외자 0. **JIS X 0213 외자(「第3水準1-87-71」 등 면-구-점)는 이제 풀린다**
     (`src/lib/aozoraJisx0213.json`, `scripts/literature/gen-jisx0213.py` — JIS X 0213:2004 공식 대응). 번호 없이 설명만 있는 외자,
     Unicode에 없는 글자는 여전히 미해결이라 넣지 않는다. 외자에 걸린 루비도 풀린다.
     예외는 `AOZORA_SUBSTITUTED_GAIJI` 표의 작은 가나뿐이다(현재 `小書き平仮名ん` → 「ん」 — 오너 결정 2026-10-14 KST): 보통 크기로
     바꾸고 책 metadata 「우리가 바꾼 점」에 `small-kana-as-full`을 달아 뷰어 출처 줄이 「글꼴에 없는 작은 가나는 보통 크기로」를 밝힌다.
     표에 없는 이름은 fail-closed(미해결)이다.
   - **작가 1968년 이전 사망**(일본 보호기간 만료 — 1967년 이전 사망은 사후 50년으로 확정, 출판 연도는 보지 않는다.
     한국은 저작권법 제3조 제4항 상호주의라 일본에서 만료면 만료). 미국(URAA 회복)은 공개 조건이 아니다 — 개정 전에는
     JP·KR·US 셋 모두라 太宰治·坂口安吾가 막혔다. `add-work`는 미국 보호 가능성을 참고로만 출력한다.
     번역자·삽화가 없음(원작만). 판권에 `校正`이 없는 미교정 입력본(夢十夜)은 넣지 않는다.
   - 장은 10–15분 분량. 見出し 주석이 2개 이상이면 그 표제로 장을 나눈다 — 짧은 장이 생겨도 **목차대로**(합치지 않는다 — 오너 확정
     2026-10-14 KST, 예: ごん狐 6장). 한 見出し 장이 4,000자를 넘으면 **그 장만** 고르게 나눈다(「一 (1/3)」 — 坊っちゃん).
     첫 見出し 앞 500자 이하 머리말은 따로 한 장이 되지 않고 첫 장 머리에 붙는다(やまなし 「…青い幻燈です。」 21자).
     見出し가 없으면 장 수를 round(전체/3,000)로 정해 고르게 나눈다(짧은 꼬리 장 없음, 장 머리가 앞 대사의 이음 문단이 아닌 경계 —
     둘을 함께 못 맞추면 장 수를 하나 줄여서라도 고르고 깨끗한 경계를 먼저 고른다: 人間椅子 4장 3,7xx자).
   - 新字旧仮名(예: 杜子春의 다른 판)은 제외.
- **권리 기록 칸**: `status: "approved"`, `basis: "public-domain"`, `reviewedBy`(역할명 — 이메일·실명 금지, 공개 metadata에 실린다),
  `reviewedAt`(KST `YYYY-MM-DD`), `evidenceUrl`(도서 카드), `reviewedJurisdictions: ["JP", "KR"]`(개정 전 기록의 `US`는 그대로 둔다). ②가 모두 채운다.
- 빌드 진단: `mappedRubyCount`/`rubyCount`, `droppedRubyCount`(0), `midParagraphSplitCount`(0), `annotationRubyCount`, `resolvedGaijiCount`.
  `prebuild`에 `--check`가 걸려 있다.

### 시리즈 A 「布装·型押し + 題簽」 (2026-10-15 KST 오너 선택 · 색감은 당시 실물로 검증)

오너가 실제 책 표지 기준의 완성도를 요구해 두 시안(A 천 장정+題簽 / B 목판 口絵+겹줄 틀)을 같은 4권으로 비교했고, A를 골랐다.
- **틀**: 표지 = 작품 색의 천(布目), 그 위에 같은 색 계열 두 단(천 색에서 `color-mix`로 뽑는 --dk·--dd·--lt)으로 찍은 문양·장면 +
  강조색 1–2. 제목·작가는 오른쪽 위에 따로 붙인 題簽(생지 종이·子持ち罫) 위에만 — 대비 7:1 이상이라 그림이 판면 전체를 쓴다.
- **검수 기준**(통과 못 하면 반려): 題簽 자리·규격 동일 · 빈 사분면 없음, 원경·중경·근경 중 둘 이상(아이콘 하나짜리 금지) ·
  판색 2–3도 + 강조 1–2 · 전통 문양은 직접 그림 · 실제 크기(60×84)에서 제목 11px · 바탕색 CIELAB 색차 12 이상(계약) ·
  26권 격자에서 같은 구도·주제 반복 없음 · 원본 장정·삽화 참조/재현 없음, 사람 몸 없음 ·
  **題簽은 배경 문양만 덮는다** — 작품의 주제(그림에 `focal` 표시: 문·기차·누문·그림자·강조점)는 題簽과 둘레 3단위 안에 0%여야 한다
  (오너 지적 2026-10-15 「글자 프레임에 가려지는 부분」 → 실측: セロ 뻐꾸기 100%·注文 문 28%·又三郎 분교 19%·トロッコ 귤 25%·
  銀河 기차 3% 가림을 옮겨 26권 모두 0%). 측정은 실제 렌더에서 focal 도형을 격자 표본으로 찍어 題簽 사각형 안 비율을 센다.
- **색감 검증**(오너 「색감이 실제 당시 책의 색감과 유사한지 체크」): 초판 고서 사진·복각본 50여 장(書肆田高 등 고서점 실물,
  岩波 복각 『こゝろ』, 日本近代文学館 복각 『注文の多い料理店』)을 대조했다. 당시 문예서는 단색 천보다 **종이 표지·함에 인쇄 도안**이
  많고, 색은 생지·크림·회백, 朱·朱橙, 山吹·黄土, 紺 천, 臙脂, 짙은 녹, 墨이 대부분이었다. 이전 팔레트의 보라·라일락·마젠타·
  선명한 군청·파스텔은 그 시대 문예서에 거의 없어 **전통색 26색으로 갈았다**(literatureDisplay `LITERATURE_COVER_COLORS` 주석).
  초판 색이 확인된 작품은 그 계열(羅生門 紺 천 · 鼻 같은 책 함의 山吹 · 刺青 朱橙 · こころ 朱 · 人間失格 薄柿 · 注文 墨 ·
  山月記 鳥の子 · 斜陽 生成り). 남은 고서는 바래 있으니(크림→황갈, 노랑→황토, 朱橙→적갈) **새 책의 색**을 기준으로 삼았다.
  미검증: 檸檬(초판 「무지」 — 색 불명)·走れメロス·人間椅子·桜の森·手袋を買いに·ごん狐·やまなし는 시대 계열 안에서 골랐다.

```json
{
  "schemaVersion": 1,
  "personId": "000000",
  "workId": "0",
  "title": "작품명 — source.txt 첫 줄과 같아야 한다",
  "author": "저자명 — source.txt 머리 마지막 줄과 같아야 한다",
  "language": "ja",
  "charset": "新字新仮名",
  "publishedYear": 1900,
  "authorDeathYear": 1940,
  "level": "N2 상급",
  "cardUrl": "https://www.aozora.gr.jp/cards/000000/card0.html",
  "sourceFileUrl": "https://www.aozora.gr.jp/cards/000000/files/0_ruby_0.zip",
  "sourceFormat": "txt",
  "sourceSha256": "<zip SHA-256, 소문자 64자>",
  "textSha256": "<source.txt SHA-256, 소문자 64자>",
  "attribution": { "author": "저자명", "translator": null, "illustrator": null },
  "rights": {
    "status": "approved",
    "basis": "public-domain",
    "reviewedBy": "owner",
    "reviewedAt": "2026-10-12",
    "reviewedJurisdictions": ["JP", "KR"],
    "evidenceUrl": "https://www.aozora.gr.jp/cards/000000/card0.html"
  },
  "display": {
    "titleReading": "さくひんめい",
    "titleKo": "작품 한국어 제목",
    "authorKo": "작가 한국어 이름(외래어 표기법)",
    "cover": "ink",
    "motif": "ink-steam",
    "coverTitle": "여섯 자를 넘는\n제목만"
  }
}
```

- `level`은 편집 레벨 라벨(`JP_LEVELS` 중 하나, D6 — 개인 맞춤도 「아는 단어 N%」와 함께 보인다).
- `translator`·`illustrator`는 키를 빼지 말고 `null`로 적는다(빠뜨림 = 미검토로 보고 공개하지 않는다).
- `display`(AOZORA-P0-5)는 표지·카드 표기다. 원서 표지·삽화 이미지는 쓰지 않는다(IP 정책 §2.1 금지⑴) — 표지는 같은 틀에
  세로 제목과 작품 색만 바뀌는 타이포그래피 표지다. 빌드가 검사하고 대조표(`manifest.generated.json`)에 싣는다.
  - `titleReading`은 가나만. `cover`는 팔레트 이름(`snow`·`vermilion`·`forest`·`ink`·`cream`, `literatureDisplay.js`) —
    작품 이미지에 맞춰 고르고 이미 쓴 색과 겹치지 않게 한다. 새 색이 필요하면 CSS와 팔레트를 함께 늘리고 흰 글자 대비 4.5:1 이상을 지킨다.
  - `motif`는 표지 문양(`LITERATURE_COVER_MOTIFS` — `LiteratureCoverArt`의 자작 SVG). 원서 표지·기존 삽화·알려진 캐릭터를
    옮기지 않는다. 새 작품은 그 작품 분위기의 새 문양을 같은 틀(오른쪽 위 제목 자리 비움 · 아래·왼쪽에 주제 · 색은 CSS)로 그려 더한다.
  - 표지는 모든 작품이 같은 배치다: 제목(11px)이 오른쪽 위에서 한 줄로, 작가가 그 왼쪽 아래에. 제목은 한 줄 여섯 자까지 —
    넘는 제목만 `coverTitle`에 작품명 그대로 줄바꿈(`\n`)을 넣고 첫 줄을 길게(둘째 줄은 아래에 붙는다). 여섯 자 이하를
    나누거나 다른 글자를 넣으면 빌드 실패.
- 장 이름은 빌드가 정한다: 見出し가 있으면 그대로(「ごん狐 — 一」), 분량으로 나눈 장은 「1/2」(자료 제목 「鼻 (1/2)」),
  한 장이면 작품명만. 교재의 「과」·연재의 「편」은 쓰지 않는다(오너 확정 2026-10-14 KST). 카드의 장 줄은 장 첫 문장(incipit)을 단다.

## 산출물이 담는 것

- 장마다 `rawText`(문단 사이 빈 줄, 루비·주석 제거), `metadata.book`(책 묶음), `metadata.level`,
  `metadata.literature`(크레딧: 底本·親本·입력·교정·도서 카드·권리 기록, 우리가 바꾼 점, `rubyLocks`).
- `rubyLocks`는 그 장 `rawText` 기준 문자 범위다. 분석(`analyzeText`) 끝에서 토큰과 **정확히** 맞는 것만 사전
  독음을 덮는다. 우선순위는 사용자 교정 > 저자 루비 > 분석기.
- 뷰어는 `metadata.literature`로 출처 줄(青空文庫 · 底本 · 입력 · 교정 · 원작 퍼블릭 도메인 · 도서 카드)을 그린다.
