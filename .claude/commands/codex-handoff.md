## A. 발주 (태스크 프롬프트 체크리스트)

1. **배경** — 무엇을 왜(실측 · 오너 지시 인용).
2. **범위** — 번호로 열거. 애매어 금지("적절히", "필요 시" 금지).
3. **비범위** — Claude 세션이 맡는 부분을 명시(경계 분쟁 예방).
4. **exact allowlist** — 수정 허용 경로를 wildcard 없이 전부 나열. 신규 파일 · 테스트 파일 ·
   `docs/ai-tasks.md`(자기 항목만)를 빠뜨리지 말 것.
5. **게이트** — draft PR → 전체 vitest green(수치를 본문에) → 검수 → squash merge.
   구현이면 계약 테스트 요구, RFC-first면 **"코드 변경 0, 구현 착수 금지"**를 굵게.
6. **하드리밋 재확인** — `AGENTS.md` 하드리밋(DB 스키마 · 시크릿 · 콘텐츠 카피 · Claude 소유 파일 ·
   world 자산 재생성 · IP 정책 포인터).
7. **allowlist 확장 절차** — 기존 계약 테스트가 깨지면 임의 수정 금지, PR 본문에 exact 경로 요청 → 승인 후 수정.
- 기록: 보드에 발주 항목을 남긴다. 제안 · 백로그 성격이면 이슈 #1077.
- 회수: **30분 내 착수 표식이 없으면 회수**해 직접 수행한다(CLAUDE.md 세션 편성).

## B. 구현 PR 검수

1. **자기 보고 대조** — head/base/allowlist 주장을 실제와 맞춘다:
   `git fetch origin <branch> main && git diff origin/main...origin/<branch> --stat`
   → 변경 경로가 allowlist와 **1:1**인지(초과 · 누락 모두 위반). `git merge-base`로 base 정합 확인.
2. **보완 지시 반영** — 승인 때 붙인 보완 항목이 코드에 실재하는지 `grep`으로 하나씩 확인.
3. **신뢰 경계** — 외부 모델 응답을 쓰는 코드면 검증(길이 · 화이트리스트 · 후보 소속)과
   **실패 시 현행 동작 수렴**을 확인. 실패가 사용자에게 새 오류로 새면 반려.
4. **하드리밋** — AGENTS.md 하드리밋 무변경.
5. **독립 재현** — 브랜치를 체크아웃해 **병합 트리에서** 전체 vitest를 직접 돌린다(Node 24).
   자기 보고 수치를 믿지 않는다 — 재현이 검수의 본체다.
6. **병합** — `/pr-cycle` §5-1 병합 직전 점검 → 검증한 head SHA로 squash merge.
7. **검수 회신** — PR에 통과 근거를 항목별로, 반려면 **정확히 무엇을 고칠지**를 적는다.
   잘한 설계는 명시적으로 인정한다(다음 발주 품질에 직결).

## C. RFC 검수

1. **주장 실측 대조** — RFC의 "현행은 이렇다" 표를 코드로 직접 확인한다.
2. **설계 평가** — 스키마 무변경 하드리밋, 기존 선례(null-marker · 위치 무관 스캔 · graceful fallback)
   재사용, 호출 수 · 벽시계 영향, CLAUDE.md 제품 나침반 3문.
3. **판정** — 승인 / 보완 후 승인 / 반려. 보완은 번호로.
4. 승인 시 A 절차로 구현을 따로 발주한다 — RFC 승인과 구현 발주는 별개다.

## 반려 기준 (하나라도 걸리면)
allowlist 위반 · 하드리밋 위반 · 독립 재현 실패 · 실패 경로가 새 오류를 만듦 ·
계약 테스트 없이 동작 변경 · 다른 담당 파일 수정.
