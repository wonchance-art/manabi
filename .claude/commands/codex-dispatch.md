# /codex-dispatch — Codex 세션 발주 게시

## 역할
`#150`(AI-HANDOFF 이슈)에 Codex 세션이 **즉시 집을 수 있는 형식**으로 발주를 게시한다.
형식이 어긋나면 세션이 착수하지 못한다 — 2026-08-17 `[CLAUDE_REVIEW]` 토큰으로 올렸다가
Codex-3가 규약 불일치로 대기했고 재게시가 필요했다.

## 요청
$ARGUMENTS
(예: "Codex-4에 판별 캐시 구현 발주 — RFC 5xxxx 승인분")

## 필수 형식

첫 줄은 반드시:

```
[AI-HANDOFF][CLAUDE] <제목> → Codex-N
```

- `[CLAUDE]` 토큰과 **`→ Codex-N` 라우팅**이 둘 다 있어야 한다(`[CLAUDE_REVIEW]`는 검수 회신 전용).
- 둘째 줄에 `assignment=<코멘트id>` / `target=<브랜치명>` / 근거 RFC id.

## 본문 체크리스트

1. **배경** — 무엇을 왜(실측·오너 지시 인용).
2. **범위** — 번호로 열거. 애매어 금지("적절히", "필요 시" 금지).
3. **비범위** — 다른 세션·Claude가 맡는 부분을 명시(경계 분쟁 예방).
4. **exact allowlist** — 수정 허용 경로를 **wildcard 없이** 전부 나열. 신규 파일도 포함.
   테스트 파일과 `docs/ai-tasks.md`(자기 열만)를 빠뜨리지 말 것.
5. **게이트** — draft PR → 전체 vitest green → Claude 검수·squash merge(단일 창구).
   구현이면 계약 테스트 요구, RFC-first면 **"코드 변경 0, 구현 착수 금지"**를 굵게.
6. **하드리밋 재확인** — DB 스키마·시크릿·타 언어 경로·`user_verified`·IP 규약.
7. **allowlist 확장 절차** — 기존 계약 테스트가 깨지면 임의 수정 금지, 이슈에 exact 경로 요청 → 승인 후 수정.

## 공통 제약(전 세션 공통 — 매 발주에 포함)
자기 네임스페이스 브랜치만 · DB 스키마 변경 금지 · 시크릿 열람 금지 ·
콘텐츠 카피 신설 금지(필요 시 Claude에 요청) · 보드는 자기 열만 · merge·force-push 금지 ·
무응답 3회 시 회수 선례.
