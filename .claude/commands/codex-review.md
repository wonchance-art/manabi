# /codex-review — Codex 회신 검수 게이트

## 역할
Codex 세션의 CODEX_DONE(구현 PR) 또는 RFC를 검수한다. Claude는 **단일 머지 창구**이므로
이 절차가 main 품질의 마지막 방벽이다.

## 요청
$ARGUMENTS
(예: "#1049 C3 구현 검수" / "C4 판별 캐시 RFC 검수")

## A. 구현 PR 검수

1. **자기 보고 대조** — CODEX_DONE의 head/base/allowlist 주장을 실제와 맞춘다:
   `git fetch origin <branch> main && git diff origin/main...origin/<branch> --stat`
   → 변경 경로가 발주 allowlist와 **1:1**인지(초과·누락 모두 위반).
   `git merge-base`로 base 정합 확인.
2. **보완 지시 반영** — 승인 때 붙인 보완 항목이 코드에 실재하는지 `grep`으로 하나씩 확인.
   테스트로 고정하라 한 계약은 테스트 파일에서 확인한다.
3. **신뢰 경계** — 외부 모델 응답을 쓰는 코드면 검증(길이·화이트리스트·후보 소속)과
   **실패 시 현행 동작 수렴**을 확인. 실패가 사용자에게 새 오류로 새면 반려.
4. **하드리밋** — DB 스키마·시크릿·`user_verified` 보호·타 언어 경로·IP 규약 무변경.
5. **독립 재현** — 브랜치를 체크아웃해 **병합 트리에서** 전체 vitest를 직접 돌린다.
   (base가 최신 main이면 브랜치 트리 = 병합 트리. 아니면 `git merge origin/main` 후 실행.)
   자기 보고 수치를 믿지 않는다 — 재현이 검수의 본체다.
6. **CI 확인** → ready → **squash merge** → 브랜치 재동기화 → 리뷰 브랜치 삭제.
7. **검수 회신** — `[AI-HANDOFF][CLAUDE] §<발주> 검수 완료 — PR #N squash merge (sha) → Codex-N`
   형식으로 게시. 통과 근거를 항목별로 적고, 반려면 **정확히 무엇을 고칠지**를 적는다.
   잘한 설계는 명시적으로 인정한다(다음 발주 품질에 직결).
8. **보드** — 해당 세션 열 done + Claude 열 발주 항목에 결과 기록(같은 PR에 동봉).

## B. RFC 검수

1. **주장 실측 대조** — RFC의 "현행은 이렇다" 표를 코드로 직접 확인한다. 여기서 틀리면 설계 전체가 틀린다.
2. **설계 평가** — 스키마 무변경 하드리밋 준수, 기존 선례(null-marker·위치 무관 스캔·
   graceful fallback) 재사용 여부, 호출 수·벽시계 영향.
3. **판정** — 승인 / 보완 후 승인 / 반려. 보완은 번호로 명확히.
4. 승인 시 **`/codex-dispatch`로 구현 발주**(exact allowlist 포함) — RFC 승인과 구현 발주는 별개 게시다.

## 반려 기준 (하나라도 걸리면)
allowlist 위반 · 하드리밋 위반 · 독립 재현 실패 · 실패 경로가 새 오류를 만듦 ·
계약 테스트 없이 동작 변경 · 다른 세션 파일 수정.
