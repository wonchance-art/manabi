# N4 웹 교재 제작·인수

사용자 직접 발주: “N4 교재 제작. N5 제작 방식 그대로 전수 받아서 진행. 에이전트 풀가동.”
기준 main: `519045bebe16a05cb8f9aafdc7f31b5a346b23a0`. N4 원고와 도구는 별도 작업 브랜치에서 제작한다.

## N5에서 인수한 것

- 실물 기준: N5 `8a8c1c1fd452773810abaf8c`의 `bundle.manuscript`와 세 보존 판본.
- 학습 흐름: 작은 표현 → 단어 → 문형 설명·예문 → 같은 대화 → 바꾸어 말하기 → 읽기·확인 → 내 문장.
- N5 lesson JSON 필드 구조, 설명과 예문의 한자리 배치, 역할·사건·시점이 이어지는 원고, 정답·해설과 원문 색인.
- canonical JSON의 SHA-256, 앞 24자리 판본 ID, 출력 자산의 해시·바이트 원장, 기존 판본과 답안 분리.
- 대표1과 내용·화면 검수 후 전권 집필, 작성자와 다른 담당자의 문항·독해·용법 감수.
- N5 연락문 발신 방향·목적지/실제 본문·판본별 답안·기존 폰트의 새 글자 누락 반례를 N4 검수에 적용.

N5 원 `tooling/rebuild.py`, `package_app.py`, 최근 개정용 `build-n5-copy-review.py`는 현재 작업공간과 저장소에서 확보하지 못했다. **아래 도구는 이 계약을 잇는 새 N4 재구현이며, 원 제작 도구를 그대로 복구했다고 주장하지 않는다.** N5 산출 HTML을 N4 원고라고 바꾸어 부르지 않는다.

로컬 N5 `index.current=7f...`와 운영 DB의 공개 포인터는 별개다. 이 작업은 운영 공개판을 조회·전환하지 않는다.

## 원고 정본과 작성 범위

`src/content/textbookManuscripts/japanese-n4/`

- `book.json`: 책 정보·사용 안내·N5 회수 진단·연결 복습6세트·제작 범위·출처.
- `syllabus.json`: 42과의 목표·선수·핵심 문형·회수 계획·내부 출처.
- `lessons/u01.json`부터 `u42.json`: 개별 집필 원고. 42과는 새 문형 없이 누적 수행하며 `reviewPatterns`로 이미 배운 표현을 회수한다.

N4 본문은 새로 쓴 원고다. 기존 N5 판본, 원고, 음원, PDF, 공개 포인터와 기존 N4 레퍼런스 자료를 변경하지 않는다. 사용자의 이번 직접 집필 요청을 N4 새 경로의 콘텐츠 제작 근거로 삼으며 다른 제품 문구·콘텐츠 전체의 소유권을 바꾸지 않는다.

각 과는 소개·회수 어휘, 문형 설명과 예문, 역할 대화, 말하기2개, 독해와 근거 해설, 확인3개, 쓰기 예시와 체크를 연결한다. 신규 어휘 수를 채우기 위한 불필요한 단어 추가는 하지 않는다. +1/+3/+7은 회수 **계획**이며, `recall`은 실제 원고의 인용·위치로 확인한 회수와 구분한다.

내부 N4 문형156항목에 대한 목차 배정은 신규 핵심 문형156개 또는 공식 JLPT 완전 범위라는 뜻이 아니다. 학습시간은 편집 예상이며 학습자 실측이 아니다.

## 재생성

Node24, Python3, fontTools, Noto CJK의 원본 컬렉션과 OFL 라이선스가 필요하다. Python 도구는 fontTools의 WOFF 출력과 표준 zlib를 사용하므로 Brotli 설치 없이 동작한다. 폰트 원본 경로·가족·원본 해시와 실제 필요한 글자는 출력 `font-audit.json`에 기록된다.

```sh
npm ci
node scripts/textbooks/build-n4-web.mjs --out /tmp/manabi-n4-build-a
node scripts/textbooks/validate-n4-web.mjs --out /tmp/manabi-n4-build-a
node scripts/textbooks/build-n4-web.mjs --out /tmp/manabi-n4-build-b
diff -qr /tmp/manabi-n4-build-a /tmp/manabi-n4-build-b
```

출력 경로는 새 빈 폴더여야 한다. 기존 출력물을 덮어쓰거나 N5 판본을 수정하지 않는다. 다른 원고 경로는 `--source PATH`로 지정한다. 대표1과 출력은 별도 원고 디렉터리와 `--expected-lessons 1`로 검증하며 전권 검증은 기본42과다.

출력은 `index.html`, `style.css`, `app.js`, `bundle.json`, N4 글자에 맞춘 Noto 웹 폰트·OFL 라이선스, 폰트 감사다. N5의 시각 표현과 동일 가족의 서체를 계승하되 N5용 축약 폰트를 그대로 재사용하지 않는다.

빌더·런타임·스타일·폰트 도구·기준 N5 스타일의 해시를 원고의 `templates` provenance에 포함해 출력 변경도 판본 ID에 반영한다. canonical 알고리즘은 N5와 같고 이 provenance 필드는 N4 재구현에서 추가한 것이다.

## 읽기·답안·색인

로컬 HTTP 서버로 출력 폴더를 열면 목차·구간 주소·뒤로/앞으로·뜻/읽기/대화 해석·정답 펼치기·단어/문형 찾기를 사용할 수 있다. 각 답안의 저장 키는 N4 책 ID와 실제 판본 ID에 묶인다. 브라우저 저장 실패는 성공으로 표시하지 않는다.

답안은 이 브라우저의 로컬 저장이며 계정·개인 단어·복습 일정과 연결되지 않는다. 대화는 **음성 미제작 대본 확인**이다. 원고의 `listen_*`는 N5 스키마 호환 필드이며 실제 청해 완료를 뜻하지 않는다. 원고의 읽기 지도는 검토자가 문맥과 복합어를 대조하며, 글리프가 있다는 사실로 발음 정확성을 대신하지 않는다.

## 앱 통합과 발행

현행 앱의 책 ID·일부 경로와 DB CHECK는 N5 전용이다. 이 작업은 N4 원고와 독립 웹 교재 검토본을 제작하며 기존 앱을 임의 일반화하거나 DB를 바꾸지 않는다. N4 앱 등록에는 책 레지스트리·불변 판본 제공·초안/발행 권한·공개 포인터·단어 저장/복습/정확한 원문 복귀를 기존 N5 보존 하에 따로 통합·검수해야 한다.

N4 원고 제작, 웹 후보 생성, 독립 내용 검수, 계정 통합, 운영 발행을 서로 다른 결과로 기록한다. 새 음성·PDF 발행·운영 배포는 이 원고 생성 명령에 포함되지 않는다.
