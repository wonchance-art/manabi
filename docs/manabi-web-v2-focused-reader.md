# manabi 웹 v2 — 연속 탐색과 집중 읽기

2026-09-07 KST · 오너 「다음 ㄱㄱ」 후속 구현. Base는 자료 가져오기·읽기 왕복 PR #1285. 승인한 웹 v2의 ‘탐색은 개성 있게, 읽기는 집중하기 편하게’를 실제 텍스트 뷰어에 적용한다.

## 적용

- 로그인 직후 홈 로딩 중 검색을 누르면 주소는 서재인데 본문은 홈인 상태가 남는 문제를 수리했다. 개인화 홈의 자동 prefetch를 메뉴와 로고에서 끈다. 검색도 기존 개인 서재·복습과 같은 명시적 탐색 방식을 사용한다.
- `/viewer/:id`에서 상단을 작은 manabi 로고·메뉴·검색·프로필로 정리했다. ‘메뉴’ 안에 다섯 목적지와 관리자 진입을 유지한다. 서재·교재·PDF 등 다른 화면의 내비게이션은 유지한다.
- 긴 글에서 복귀·듣기·읽기 설정 막대를 상단에 고정한다. 페이지 전체가 스크롤되어 기존 읽기 위치 기록·복귀 동작과 일치한다. 빈 해설·표현 패널은 숨기되 너비는 유지해 단어 선택 시 본문이 밀리지 않게 한다.
- 모바일의 도구 시트는 실제 선택이나 해설이 있을 때 나타난다. 단어·문장·해설 컴포넌트와 저장 동작을 재사용한다.
- 글 제목·언어·레벨·공개 여부를 정돈하고 기존 본문 판면·발음·예문·배경 설정을 유지한다. 텍스트 뷰어의 최소 빈 높이는 줄인다.
- 읽기 설정은 native modal dialog로 바꾸어 배경 키보드 접근을 차단한다. Escape·바깥 클릭·닫기 버튼으로 닫고 설정 버튼으로 초점을 돌려준다. 창 안의 숫자 키가 뒤쪽 표현을 채점하지 않는다.
- 글자 크기·서체·행간·자간·발음 표시·읽기 프리셋을 바꾸면 도구막대 아래에 보이던 실제 토큰의 화면 위치를 유지한다. 새 읽기 진도나 퍼센트를 만들어 저장하지 않는다.

## 원인 검증

이전 배포 `manabi-k6jsmo785`에서 실제 페이지 코드와 격리한 인증 HTTP fixture로 재현했다. 로그인 후 URL이 `/home`이 되는 즉시 검색을 눌렀으며 홈 제목 표시를 기다리지 않았다.

| 비교 | 결과 |
|---|---|
| 기존 동작 | 주소는 `/materials?view=owned#library-search`, 본문은 홈으로 남음 |
| 모든 prefetch 차단 | 정상 |
| `/materials` prefetch만 차단 | 동일 실패 |
| `/home` prefetch만 차단 | 정상 |

history 호출 추적에서 실패 구간은 프레임워크 탐색이었고 서재 필터의 URL 교체가 실행되지 않았다. 따라서 필터 저장 코드·인증·라우터 패키지를 추측으로 재작성하지 않았다. 최종 배포 검증에서는 prefetch를 가로막지 않고 실제 코드의 설정으로 같은 빠른 이동을 검사한다.

## 검수

- 새 helper 계약 8개: 텍스트 뷰어 경계, 개인화 목적지 prefetch, 첫 가시 토큰 선택, 양방향 재배치, 빈/제거된 토큰 처리.
- 기존 `performanceRepairs.test.js`의 홈 메뉴 기대값 한 개를 `prefetch: false`로 갱신했다. 기존 ‘홈 prefetch 유지’와 이번에 재현해 수정한 동작이 직접 충돌하므로, 승인된 웹 개편의 탐색 오류 수정에 필요한 계약 변경으로 한정한다. 다른 기존 테스트는 수정하지 않았다. 새 배포 브라우저 검사로 실제 연속 탐색 결과를 함께 검증한다.
- 브라우저 하니스 `e2e/focused-reader.e2e.mjs`: 빠른 로그인→검색, 메뉴 키보드 조작, 단일 main, 빈 도구 숨김, 선택 시 본문 폭 고정, 고정 도구막대, 설정 초점·숫자키 격리·읽기 위치 보존, 출처를 유지한 표현 저장, 320/390/768/1180/1440px 넘침, 모바일 시트, 서재 복귀를 검사한다.
- 브라우저는 실제 앱을 실행하되 인증·REST·AI 응답은 명시적 상태 있는 fixture다. 개인 자료나 운영 DB에 쓰지 않는다. 운영 계정의 저장 권한을 새로 검증했다는 의미는 아니다.
- 데스크톱·모바일·설정 화면을 직접 렌더 확인했다. 본문 토큰 렌더러와 예문 박스는 기존 것을 재사용한다.
- 전체 단위 검사: `npm test -- --maxWorkers=2`, 348파일 / 3,778개 모두 통과(207.64초). 변경 파일 ESLint 오류 0, 기존 ViewerPage hook 경고 1. `git diff --check` 통과.
- 최종 실행 코드 `7d31cd666eeeed6efd0cbaa4a84d9550d82fae72`: Vercel Next 15.5.21 빌드 완료, 474페이지 생성, 콘텐츠/커리큘럼 오류 0(기존 경고 11). 이후 커밋은 테스트·검수 문서·보드다.
- 새 배포의 집중 읽기 브라우저 14조건 통과 / pageerror 0. 자동 prefetch를 차단하는 임시 우회 없이 빠른 로그인→검색 검사를 통과했다. 실제 배포 글꼴을 포함해 데스크톱·모바일 화면을 확인했다.
- 기존 읽기 왕복 20조건은 로컬과 최종 배포에서 전부 통과했다(pageerror 0). 배포 첫 실행은 분석 성공 후 스크린샷 캡처가 30초 제한으로 중단됐고, 동일한 하니스를 변경 없이 재실행하여 20조건을 완료했다.

## 선례 선택

| 선택 | 근거와 적용 |
|---|---|
| Next.js `Link prefetch={false}` 부분 채택 | 인증 경계를 통과하는 개인화 홈에만 적용하는 작은 변경. [Next.js 탐색 문서](https://nextjs.org/docs/app/getting-started/linking-and-navigating). 버전 변경 없음. |
| HTML modal dialog 채택 | 브라우저의 배경 비활성화·Escape·초점 범위 활용. React 조건부 제거 뒤 초점 복귀는 보완한다. 별도 모달 패키지 없음. |
| 기존 ViewerBottomSheet·설정·FSRS 재사용 | 내용과 저장 의미를 바꾸지 않고 노출과 조작만 정리한다. |
| 화면 토큰 기준 재배치 | 기존 토큰 ID와 실제 좌표를 사용한다. 가상 스크롤·진도 저장 모델 신설 불필요. |

- 기존 원고·판본·표현 출처·복습 일정·개인 자료 권한 보존. 새 DB 테이블·마이그레이션·환경 변경 없음.

- PDF 교재 조판·음성 제작·통합 검색·기기 간 교재 진도 동기화·월드 제외.
- 빌드 플랫폼이 Node 20의 2026-10-01 신규 배포 지원 종료를 안내했다. 현재 빌드는 성공했다. 배포 런타임 갱신은 별도 인프라 범위이며 이 변경에서 `engines`나 환경을 수정하지 않았다.
- 원본 iCloud 작업 공간의 미커밋 변경은 보존했다. 격리된 `codex/web-v2-focused-reader-20260907`에서 작업하며 merge·force-push·운영 승격하지 않는다.
