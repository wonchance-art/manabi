# 일본어 N5 한 권: 편집·발행·복습 연결

작성일: 2026-09-06. 최초 구현 기준 커밋은 동봉 `app-integration/manifest.json`에 기록한다. 이 문서는 최초 설계와 검증 범위를 보존한다. 이후 운영 적용·웹 발행은 [웹 우선 발행 기록](textbook-n5-web-release.md), 최신 출시 후보 상태는 [웹 v2 출시 문서](manabi-web-v2-release.md)를 따른다.

## 독자와 관리자 흐름

- `/lessons?lang=Japanese`에서 발행된 N5 한 권으로 이동한다. 기존 lessons와 개인 학습 데이터는 유지한다.
- `/books/japanese-n5`는 현재 공개 판본을, `?edition=<24자리 ID>#u03-study1`은 그 판본의 원문을 연다. 새 판본을 발행해도 옛 복습 출처의 판본과 위치는 바뀌지 않는다.
- 본문의 문장을 선택하고 기억할 표현·뜻을 입력하면 기존 `SaveContextButton`과 학습 문맥 RPC를 사용한다. 기존 단어 카드의 복습 일정과 FSRS 상태를 재설정하지 않는다.
- 과마다 기존 `MaterialChapterLinks`를 이용해 본인 자료를 연결한다. 자료 선택과 출처 검증은 서버에서 기존 소유권 검사를 통과해야 한다.
- `/admin/books/japanese-n5`에서 42과, 문자 준비, 문화 글, 어휘·문형·한자 노트의 내용과 번역을 편집한다. 초안 저장은 관리자만 가능하다. 다른 탭에서 먼저 저장했다면 409 충돌로 알리고 입력을 유지한다.
- 초안은 공개 교재와 분리되어 있다. 미리보기는 마지막 검수 출력본이다. 웹에서 입력할 때마다 PDF를 즉시 생성하는 기능은 이번 구현에 포함하지 않았다.

## 개정에서 발행까지

1. 관리자에서 초안을 저장하고 `원고 내려받기`로 JSON을 내보낸다. 과·문항 ID와 배열 구조는 편집기에서 잠근다. 구조를 변경하는 개정은 별도 이관 작업이다.
2. 동봉한 `tooling/rebuild.py`로 같은 원고의 웹과 PDF를 다시 생성한다. 새 글자가 있으면 `--refresh-fonts`도 사용한다. 실행 방법과 폰트 요건은 `tooling/README.md`에 있다.
3. PDF의 모든 쪽을 렌더링하고, 내용·폰트·쪽 나눔·예문 박스·문제와 정답을 검수한다. 웹 반응형·풀이 저장·내부 링크를 검사하고 새 판본에 해당하는 검수 결과를 기록한다. 기존 검수 JSON을 새 판본에 복사해서 통과로 삼지 않는다.
4. `tooling/package_app.py --root <검수 폴더> --out <앱>/src/content/textbookEditions --site-url <운영 HTTPS 주소>`로 비공개 출력물을 패키징한다. 운영 주소는 실제 사이트 주소여야 한다. PDF의 웹 복귀 링크만 운영 주소로 바꾸며 페이지 본문 스트림은 동일함을 검사한다.
5. 새 판본 폴더와 `index.json`을 앱 배포에 포함한다. **이미 발행한 판본 폴더를 삭제하거나 덮어쓰지 않는다.** 이전 판본 출처와 복원은 당시 파일이 존재해야 작동한다. 같은 원고라도 출력 디자인·링크를 바꾸는 후속 발행은 원고의 `version`을 올려 새 판본을 만든다.
6. 배포된 후보가 현재 저장 초안과 일치할 때 관리자 `검수한 판본 발행`이 활성화된다. 저장 초안이 달라졌거나 다른 관리자가 먼저 발행하면 서버/RPC가 거절한다. 이전 발행 기록에서는 공개 포인터만 복원한다.

CLI는 생성과 패키징만 수행하며 DB 저장·공개 전환을 자동으로 실행하지 않는다. 이 과정에 담당자의 재출력·검수가 필요하다는 점을 관리자 화면에도 표시한다.

## 데이터와 권한

적용된 마이그레이션: `supabase/migrations/20260906024758_textbook_book_editions.sql`. 최초 검토 파일 번호는 `20260906000912`였고, 원격 적용 도구가 기록한 버전은 `20260906024758`이다. 같은 SQL의 파일명만 원격 이력에 정합화했다. 이미 적용된 SQL을 다시 실행하지 않는다.

| 저장소 | 역할 | 읽기/변경 |
|---|---|---|
| textbook_book_drafts | 수정 중인 원고와 저장 버전 | 관리자 전용 |
| textbook_book_editions | 발행한 원고·출력물 해시 | 공개 읽기, 관리자 추가, UPDATE/DELETE 권한 없음 |
| textbook_book_releases | 현재 공개 판본 포인터 | 공개 읽기, 관리자 발행·복원 |

기존 `public.is_admin()`, `auth.uid()`, `auth.users`를 사용한다. 별도 서비스 역할 키는 추가하지 않는다. 두 RPC는 `security invoker`, RLS, 트랜잭션 잠금과 버전 비교를 사용한다. 발행 판본의 원고/해시는 변경할 수 없다.

출력물은 `public/` 밖에 두고 asset API가 발행 상태 또는 관리자 권한과 SHA-256을 확인한 뒤 반환한다. 모든 응답은 private/no-store이다. 원고 bundle과 임의 파일 경로는 asset API에서 제공하지 않는다. Next 파일 추적 설정에 비공개 파일 경로를 명시했다.

복습 저장 시 서버가 발행 판본의 실제 텍스트에 선택 문장과 표현이 있는지 확인하고 과를 결정한다. 클라이언트가 과·페이지·인용문을 임의로 조합하면 거절한다. 후리가나 rt 텍스트는 문장 선택에서 제거한다.

## 적용과 확인

이 교재 migration과 최초 N5 공개 판본은 이미 운영에 반영됐다. 이전 파일 번호를 미적용 migration으로 취급해 SQL을 다시 실행하거나 원격 이력을 repair/reset하지 않는다. 정합화 담당자는 SQL 본문을 바꾸지 않고 파일명과 문서 참조를 원격 이력에 맞춘다.

연결된 프로젝트를 확인한 뒤 최신 migration 목록과 `supabase db push --dry-run --linked`로 적용 예정 목록을 검토한다. 이번 파일명 정합화 자체는 새 SQL 적용을 만들지 않아야 한다. 다른 미적용 migration이 보이면 해당 담당자와 별도로 확인하며 `--include-all`, seed, roles를 묶어 실행하지 않는다.

실제 계정 검수와 운영 전환의 담당·완료 범위는 [웹 v2 출시 문서](manabi-web-v2-release.md)를 따른다. 앞으로 새 판본을 발행할 때는 실제 관리자/일반 사용자/비로그인 검수로 초안 비공개, 동시 저장 충돌, 발행/복원, 표현 출처 복귀와 자료 소유권을 확인한다. 파일명 정합화를 이유로 현재 판본을 다시 발행하지 않는다.

## 검증의 실제 범위

앱 단위 테스트 전체, 로컬 Postgres(PGlite)의 RLS/RPC 계약, 로컬 Next + 가짜 Supabase HTTP로 관리자·독자 UI 연결을 확인했다. PGlite는 auth 함수를 테스트용으로 구성했고 브라우저 통합 검사는 테스트 사용자와 모의 응답을 사용했다. **이 최초 검증 시점에는 실제 Supabase 인증·운영 데이터 통합 시험과 실제 공개 발행을 수행하지 않았다.** 이후 실제 발행과 계정 검수는 위 연결 문서에 별도로 기록한다. 세부 수치·빌드 결과·파일 해시는 납품본 `qa/`와 최종 검수 보고서에 있다.

독립 검토 웹의 답안은 그 브라우저에 저장된다. 앱의 복습 카드는 로그인 계정의 기존 학습 저장 경로를 사용한다. 이 두 저장을 동일한 인증 검증으로 간주하지 않는다.

새 음성 제작은 제외했다. 기존 147개 음원은 보존했고 변경된 원고와 맞지 않는 재생 연결은 숨겼다. N5 청해 실전 검증 완료를 의미하지 않는다.
