보고서는 `.qa/live/<실행>/`에 남고 `.qa/runs`의 합성 증거 업로드에 포함되지 않는다.

## 로그인은 한 번의 검수 묶음으로

1. 후보 exact 실행 SHA·고정 주소 일치·OAuth 복귀 허용 설정을 먼저 확인한다.
   코드 없는 callback 검사는 허용 목록 검증을 대신하지 않는다. OAuth 허용 목록은 관리자
   화면에서 확인하고, 변경이 필요할 때 해당 설정만 별도 승인을 받는다.
2. 교사·학생은 서로 다른 정상 계정과 격리된 브라우저 문맥을 사용한다. 같은 origin을
   두 탭에 열기만 하면 같은 세션을 공유할 수 있으므로 권한 분리 증거가 되지 않는다.
3. 사용자가 정상 로그인한 문맥을 같은 고정 origin에서 계속 재사용한다. 다른 주소의 cookie를
   복사하거나 임시 JWT/service-role로 사용자를 가장하지 않는다. 제품에 검수 우회 계정을 만들지 않는다.
4. 교사는 검수 전용 팀·교재·설명판에서 입력→저장→닫기→재접속→지난 판 가져오기를 한 묶음으로 확인한다.
   학생은 별도 문맥에서 팀 입장→원본 열람→뜻/독음→직접 단어 저장→복습→출처 귀환을 확인한다.
   동시에 교사 전용 쓰기·다른 사용자의 비공개 자료 접근 거부를 확인한다.
5. 로그인·권한·저장·재접속은 각 항목별 실제 결과로 기록한다. 실패 시 그 단계만 재개하며,
   배포/권한/자료 계약이 달라졌다면 관련 이전 증거를 재검토한다. 만료·로그아웃 때만 재로그인한다.

지속 인증 문맥/인증 상태는 저장소 밖의 접근 제한된 로컬 폴더에 보관하고 역할별로 분리한다.
CI·PR·스크린샷·trace에 인증 상태 파일을 넣지 않는다. 지금 PR은 인증 상태를 가져오거나
계정을 생성/변경하지 않는다. 저장소의 기존 `QA_LOGIN`은 합성 응답 테스트이며 실제 검수 계정이 아니다.
외출 중인 오너에게 즉시 재로그인을 요청하지 않았다.

## 완료 조건과 후속 범위

공개 사전 검사가 PASS라도 실사용 완료는 아니다. 최종 출시 판정에는 다음을 따로 붙인다.

| 증거 | 이번 결과 | 남은 작업 |
|---|---|---|
| 공개 배포·callback | 후보 PASS, 고정 주소 불일치 감지 | alias 연결 승인·연결 후 같은 검사 |
| OAuth 허용 목록 | 미확인 | 관리자 설정 읽기 확인, 필요 시 좁은 변경 승인 |
| 실제 교사·학생 인증/권한/저장 | 미실행 | 위 한 묶음으로 정상 계정 검수 |
| 물리 iPad/Pencil | 미실행 | 손바닥·회전·소프트 키보드·교실 네트워크 |
| 합성 수업/노트/SQL | 기존 QA 프로필 | 수정 head의 CI 결과 유지 |

이후 승인 화면 기준 비교/접근성, 실제 AI 의미 평가, 한 언어·한 레벨 교재 커버리지 순으로 확장한다.
새 병렬 세션은 실제 배정 시 작업 공간·네임스페이스·담당 파일을 정하며 이번에는 만들지 않았다.

## 재사용 판단

| 기존 구현·공식 문서 | 선택 | 이유 |
|---|---|---|
| `releaseVerificationErrors`·`/api/version` | 재사용 | 버전·판본 판정을 중복 작성하지 않음 |
| 기존 `check-web-release`·`auth-return.e2e` | 유지하고 보완 | 전자는 단일 주소, 후자는 합성 공급자 응답. 새 도구는 공개 두 주소 비교·코드 없는 복귀에 한정 |
| Playwright 인증 문맥, Apache-2.0 | 정상 인증 분리 설계에 채택 | 기존 의존성, 문맥별 세션 분리·재사용 가능. 실제 계정과 synthetic 결과를 혼합하지 않음 |
| 신규 SaaS·서비스 역할 로그인 우회 | 채택하지 않음 | 현재 문제는 주소/검수 순서이며 권한 우회가 필요하지 않음 |
