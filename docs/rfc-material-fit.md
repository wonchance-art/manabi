# RFC — 서재 i+1: 자료 맞춤도(커버리지) 산정과 수준 맞춤 추천 v1

- 상태: **R1(엔진) 진행 · R2(UI) 목업 승인 대기** — 오너 위임(2026-08-23 "다른 거 할 일
  큰 목표 설정해서 진행")으로 목표를 자율 설정, UI 규약대로 화면 반영은 목업 합의 선행.
- 기준: `origin/main` `b985b4e` (+#1106 만남 출처 문맥 R3 대기 중)
- 근거: evaluation-and-strategy.md Phase 3 **P0 "AI 난이도 적응형 추천 — i+1 원칙"**,
  현황 표 ❌("레벨 필터만 있고 i+1 기반 개인화 없음") — 전략 문서가 스스로 꼽은
  최대 공백이며 학습 웹 위주 방향(오너 2026-08-22)과 정합.
- 원칙: **LLM 없음 — 결정적 계산**(전략 문서의 'AI'는 목적 기술이지 수단 지정이 아니다).
  보상·랭킹 없음. 만남 모델(§4.2~§4.8)의 3상태가 입력.

## 1. 결론

서재의 각 자료에 대해 **"내가 아는 말이 몇 %인가"(커버리지)** 를 결정적으로 계산해,
i+1 스윗스팟(대부분 알고 조금 새로운 자료)을 학습자가 고를 수 있게 한다. 자료 읽기
순환의 입구(자료 선택)가 학습자 상태와 연결되는 마지막 미연결 지점이다.

## 2. 실측 — 이미 있는 재료 (2026-08-23 조사)

- **서재 목록(MaterialsPage)은 이미 `processed_json` 통짜를 목록 쿼리로 받는다** —
  각 자료의 전체 토큰(sequence + dictionary{text, base_form, pos})이 목록 시점에
  클라이언트에 있다. 커버리지 계산에 새 왕복·새 스키마가 필요 없다.
- 뷰어에 선례 2개: 자료 내 복습 가능 단어 계수(sequence 순회 + `findSavedVocab`),
  저장 단어 매칭(surfaces/bases Set — `fetchUserVocabWords`).
- 사용자 상태: 담김(user_vocabulary)·익힘(repetitions≥2)·만남(서버 정본 §4.5) 전부
  조회 부품 기존재.

## 3. 설계

### 3.1 커버리지 정의 (R1 — materialFit.js)

- **고유 내용어(types) 기준**: dictionary의 고유 `base_form`(없으면 text) 집합.
  개행·기호·수사·조사·어기조사 pos는 분모 제외 — 문법 기능어 지식은 문법 진도의
  소관이고, 인스턴스가 아닌 타입 기준이라 조사 반복이 커버리지를 왜곡하지 않는다.
- **아는 말 = 담김**(user_vocabulary surfaces ∪ bases — 뷰어 isSaved 관용구와 동일
  대조). 익힘은 담김의 부분집합이라 별도 축 불요. **만남은 보조 신호**(met 수를
  같이 세되 커버리지에는 불산입 — 만났다 ≠ 안다).
- **밴드**: coverage ≥0.95 `comfort`(술술) · 0.90~0.95 `fit`(**i+1 스윗스팟**) ·
  0.75~0.90 `stretch`(도전) · <0.75 `hard`(아직). 표본(내용어 types) 20 미만이면
  밴드 없음(짧은 자료 왜곡 방지 — EWMA 최소 표본 원칙과 같은 결).
- 임계값은 저작 상수(핀) — 확장 독서 연구의 95~98% 관례를 타입 기준에 맞춰 보수
  조정한 시작값이며, 실사용 후 조정은 상수 1곳.

### 3.2 UI (R2 — 목업 승인 후 착수)

서재 자료 카드에 조용한 한 줄 + 정렬 칩 하나. 숫자 과시 없음(0 무표기 결).

**목업 A. 자료 카드 맞춤도 줄** (로그인 + 계산 가능 자료만):

```
  ┌──────────────────────────────┐
  │ 星の王子さま 1장             │
  │ 아는 말 92% · 새 단어 14     │  ← fit 밴드면 「지금 읽기 좋아요」 꼬리표
  │ 아는 말 97% · 새 단어 3      │  ← comfort — 꼬리표 없음
  │ 아는 말 61% · 새 단어 120    │  ← hard — 꼬리표 없음(경고·잠금 없음)
  └──────────────────────────────┘
```

**목업 B. 정렬 칩** — 기존 탭/필터 줄에 [내 수준 맞춤] 칩 하나. 탭하면 fit→stretch→
comfort→hard 순 정렬(재탭 시 기본 최신순 복귀). 게스트·미계산 자료는 기존 순서 유지.

### 3.3 게스트·미분석 자료

게스트는 담김이 없어 줄 자체를 그리지 않는다(0 무표기). status가 analyzing/실패인
자료도 생략. 계산은 목록 렌더 시 메모이즈(자료당 1회, 토큰은 이미 로드됨).

## 4. 선례 조사 (규약)

| 대상 | 판정 | 근거 |
|---|---|---|
| Lute v3 book stats(unknown %) | 채택(이식) | 텍스트별 미지어 비율이 곧 이 기능 — term 대신 우리 담김 단어장으로 치환(MIT·이번 세션 심층 검토 완료) |
| LWT 계열 coverage | 참고 | Lute와 동계 — 타입 기준 산정 관례 확인 |
| Krashen i+1 / 확장 독서 95~98% | 채택(임계 근거) | 인스턴스 기준 연구치를 타입 기준으로 보수 조정, 저작 상수로 |
| LLM 난이도 추정 | 배제 | 결정적 계산으로 충분·재현 불가 비용(전략 문서의 'AI'는 수단 지정이 아님) |
| 레벨 메타(JLPT 급수) 기반 추천 | 배제 | 이미 있는 레벨 필터의 중복 — 개인 상태 반영이 이 RFC의 목적 |

## 5. 비목표

- LLM 실시간 난이도 추정·자동 추천 문구 생성
- 강제 재정렬·자료 잠금·경고(hard여도 자유롭게 읽는다 — 표시는 정보일 뿐)
- 보상·랭킹·"추천 정확도" 게임화
- 문법 난이도 축(어휘 커버리지만 — 문법은 진도 시스템 소관)
- 서버 사전 계산·스키마 확장(목록에 토큰이 이미 있어 불요 — 목록 쿼리가 가벼워지는
  날 재설계)
