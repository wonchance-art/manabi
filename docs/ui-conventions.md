# UI 규약 (v2-K R1 — 오너 착수 승인 2026-08-30 "K ㄱㄱ")

이 문서는 **이미 확립된 것을 적어 둔 것**이지 새 체계를 세운 것이 아니다.
값은 실측(2026-08-30) 기준이며, 어긋나면 `uiConventions.test.js`가 CI에서 잡는다.

## 1. 색은 토큰으로만

- 정본은 `src/index.css`의 CSS 변수(고유 57종). 의미 기반으로 이름 짓는다
  (`--bg-card`·`--accent-text`·`--warning`·`--gnb-height`).
- **인라인 `style`에 색 리터럴(`#hex`·`rgb()`)을 쓰지 않는다.** 투명도가 필요하면
  `color-mix(in srgb, var(--토큰) N%, transparent)`.
- `var(--토큰, 폴백)`의 폴백에도 색 리터럴을 넣지 않는다. 토큰이 있으면 폴백은
  죽은 코드이고, 토큰이 없으면 그 폴백이 **실제로 렌더되는 우회**다
  (R1에서 `--success`·`--bg-subtle`·`--surface-2`·`--brand`·`--accent2`·
  `--warning-bg/text/border`·`--border-color`가 실제로 그랬다). 이런 폴백을 실재
  토큰으로 옮길 때는 **같은 계열의 근사 대체**라 미세한 색 이동이 생긴다 — 값
  병합과 같은 성격이므로 눈에 띄는 건은 실기 확인 후 조정한다(R3).
- 글자색과 배경색은 토큰이 갈린다: `--accent`는 배경용, `--accent-text`는 글자용
  (대비 AA를 각각 맞춘 값이라 서로 바꿔 쓰면 대비가 깨진다).

- **투명 검정(스크림)은 `--scrim` 토큰**을 쓴다. 모달 뒤를 덮는 검정이 값으로 흩어져
  있었다 — 인라인 3벌(v2-K 잔여가 흡수)과 오버레이 클래스 **9종**(0.3·0.45·0.5×3·0.55·
  0.6·0.65·0.75). 2026-09-01 라운드가 아홉을 전부 토큰으로 모았다. `viewerChrome.test.js`
  ⑧이 「스크림을 칠하는 규칙은 토큰만 쓴다」를 CSS 전수로 지킨다.
  · **투명이 의도인 것은 스크림이 아니다** — `.rsheet-backdrop`·`.reanalyze-panel-overlay`·
    `.pdf-detail-overlay`는 클릭 받이라 배경을 아예 안 쓴다(바텀시트 「backdrop은 무광」 합의).
  · **흐림(`backdrop-filter`)은 별개 축이다.** 값 통합에 묻어가지 않는다 — 우리가 의도적으로
    정한 적이 없어서 그것대로 판단이 필요하다(오너 ⓐ「그대로」 2026-09-01). 쓰는 오버레이
    목록을 계약이 고정한다.
  · 목업이 「구분되지 않는다」고 판정한 범위는 **0.45~0.65**다. 그 밖 값(0.3·0.75)을 쓰는
    오버레이는 죽은 CSS였고, 되살리면 통합이 겉모습 변경이 된다 — 계약이 거기서 멈춘다.
- **삼항 안의 색도 계약 대상이다.** `background: cond ? 'rgba(...)' : ...` 꼴은 한 줄
  계약도 여러 줄 라쳇도 못 잡는다 — 상태색은 **클래스로 분해**한다(`.quiz-opt--right`).
- **레터박스·게임 팔레트처럼 토큰이 아닌 색은 예외 등재가 아니라 CSS로 옮긴다.**
  규약이 금하는 것은 *인라인* 색 리터럴이고, CSS 본문은 값이 사는 자리다
  (`.fr-media__frame`의 `#000`, `.worldmap-viewport`의 `#0b0d08`).

- **일본어 요미(후리가나) 조판은 JLReq / JIS X 4051을 따른다.** 우리가 정할 문제가 아니다.
  ⑴ 요미 크기 = 본체의 **절반**(0.5em) ⑵ 요미가 길면 삐침(はみ出し)은 한쪽 **요미 1글자**
  까지만, **줄머리·줄끝으로는 금지** ⑶ 그보다 길면 **본체 글자를 벌린다**(分散配置).
  카드 표제어가 ⑵⑶을 어기고 있었다(실측 `志望者`: 왼쪽 47px·줄 위 17.8px) — 2026-09-01
  分散配置로 수리. 폭은 `--yomi-n`(요미 글자수) × 0.5em을 CSS가 계산한다(`--fit-n` 패턴).
  ※ 0.5em/자는 **가나 전제**다. 라틴 읽기(혼종 중국어 토큰의 병음)에는 넘기지 않는다 —
  실측상 없는 폭 256px를 예약해 루비가 카드보다 넓어진다.

## 2. 브레이크포인트 (v2-K R2 — 동결)

### 정본 티어

| 티어 | 경계 | 뜻 |
|---|---|---|
| **480** | `max-width: 480px` | 작은 폰 |
| **600** | `max-width: 600px` | 폰 일반 |
| **768** | `max-width: 768px` | 태블릿 세로 |
| **1180** | `max-width: 1179px` / `min-width: 1180px` | 데스크톱 3열 ↔ 시트 전환 |

### 동결 목록 (신규 값 금지)

현재 뷰포트 값은 9종뿐이고 **이 목록이 동결선이다.** (R3에서 767·880 제거)

```
max-width : 400 · 420 · 480 · 560 · 600 · 768 · 1179
min-width : 760 · 900
```

목록 밖의 값을 새로 쓰면 `uiConventions.test.js`가 잡는다. 총 쿼리 개수에도 상한이
있어(**현재 28** — 계약의 `VIEWPORT_QUERY_CAP`과 같은 값이다) **뷰포트 쿼리를 새로
추가하는 것 자체가 막혀 있다.** 분포(R3 2차 실측):

```
max-400×1 · max-420×1 · max-480×2 · max-560×7 · max-600×7 · max-768×3 · max-1179×3
min-760×2 · min-900×2
```

### 새 접힘은 `@container`

기존 쿼리 대부분은 "이 컴포넌트가 좁아지면 접힌다"인데 **화면 폭으로 대신 재고**
있다(`400 stats-grid 1열` · `420 hanja-bridge 여백`). 그래서 사이드바 유무·시트
열림 같은 상황에서 어긋난다.

R3에서 `myplan` 격자를 실제로 옮겨 그 차이를 실측했다 — 260px 사이드바 옆에서
화면 1000px일 때 격자의 실폭은 712px인데, 뷰포트 쿼리는 "1000 > 880"이라 2열을
답했다. 컨테이너 쿼리는 1열로 옳게 답한다.

새 컴포넌트의 접힘은 컨테이너 쿼리로 쓴다. 리포에 이미 검증된 선례가 있다:

```css
.word-fit-wrap { container-type: inline-size; }
@container (max-width: 320px) { … }
```

지원 범위는 모던 브라우저 전부와 iOS 16+이며, 리포에서 이미 쓰고 있어 검증됐다.

### 기존 값의 병합은 R3

`560→600`은 40px 구간에 스타일이 새로 적용되는 **실제 시각 변화**라 한 번에 못
바꾼다. **한 건씩, 해당 화면 실기 확인 후** 이관한다. 컴포넌트 단위인 것은 이관 대신
`@container` 전환.

### R3 1차 결과 (2026-08-31 · 실측 근거 포함)

| 후보 | 판정 | 실측 근거 |
|---|---|---|
| `767 → 768` (뷰어 풀블리드) | **이관** | `768`은 모바일 크롬(`--gnb-height`·하단 네비)이 쓰는 경계다. 767이던 탓에 폭이 정확히 768px일 때 **크롬은 모바일인데 뷰어만 데스크톱**이었다 |
| `880 → @container` (myplan 격자) | **이관** | 사이드바 옆 실폭 712px에서 뷰포트 쿼리가 2열을 답했다(위 §) |
| `400 → 480` (stats 격자) | **기각** | `400` 규칙을 빼면 400px 미만이 **136px 2열**로 쪼그라든다(로드베어링). `480`으로 옮기면 401~480의 2열(196px — 충분)이 1열로 바뀌어 흔한 폰 폭이 나빠진다 |
| `420 → 480` (한자 다리) | **기각** | 421~480에서 표가 **이미 스크롤 없이** 들어간다. 옮기면 좁은 여백·작은 글자(16.8→16px)를 필요 없는 구간에 확대 적용하게 된다 |
| `560 → 600` (7곳) | 2차로 이월 | 서로 다른 7개 컴포넌트라 각각 실기가 필요하다 — 한 라운드에 묶지 않는다 |
| `min-900` · `min-760` | 2차로 이월 | `admin-edit__pencil`은 본문 컬럼 밖 여백을 재는 것이라 **뷰포트가 맞는 축**이다. 나머지는 컨테이너 전환 후보(← 이 추측은 2차 실측에서 기각됐다) |

### R3 2차 결과 — 잔여 11건 전수 실측 (2026-08-31)

1차의 「미착수」 두 줄은 **추측이었다**. 2차는 재고 시작했다: 실물 Chromium에 실제 DOM과
실제 `index.css`를 물려 뷰포트 17폭(360~1920)에서 각 요소의 **실폭**을 재고, 그 폭이
뷰포트를 1:1로 따라가는지 갈라지는지 대조했다. 결과가 추측과 달랐다.

#### 먼저 잰 구조 사실 — 이게 판정을 갈랐다

| 페이지 | 컨테이너 | 본문 실폭 상한 |
|---|---|---|
| 챕터·어휘 (`fr-*`·`bk-*`·`gojuon-*`) | `page-container` `maxWidth: 760` | **712px** — 뷰포트 760에서 도달하고 그 위로는 불변 |
| 지도 (`jpmap-*`) | `page-container` `maxWidth: 880` | 832px |
| 단어장·교재 목록 (`review-dash`·`vocab-row`) | `page-container` 기본 | 1152px |

`--sidebar-width: 240px`는 **정의만 되고 아무 데서도 쓰이지 않는다** — 학습 웹에 상주
사이드바는 없다. 1차가 말한 260px 사이드바는 `myplan` 화면 안의 것이다.

#### 판정

| 대상 | 쿼리 | 판정 | 실측 근거 |
|---|---|---|---|
| 요음 획순 패널 | `min-760` | **수리** | 뷰포트 759→760에서 요음 표가 683→**322px**(−53%). 패널이 글리프 2개라 306px를 먹는데 본문 상한이 712px다 |

#### 수리한 하나

요음 패널의 획순 줄을 감싸 글리프를 세로로 쌓아, 패널 폭을 기본 세트와 같은 **한
글리프**로 맞췄다. 그러면 요음의 낙폭이 기본과 같아진다.

| 뷰포트 | 700 | 759 | **760** | 800 | 1200 | 1920 |
|---|---|---|---|---|---|---|
| 기본 표 (전후 동일) | 624 | 683 | 478 | 462 | 462 | 462 |
| 요음 표 — 전 | 624 | 683 | **322** | 306 | 306 | 306 |
| 요음 표 — 후 | 624 | 683 | **478** | 462 | 462 | 462 |

글리프 한 변은 `--kana-glyph` 하나로 모았다(≤560의 120px도 그 변수로 옮겼다) — 패널
폭 계산이 그 값에 걸려 있어 두 곳에 두면 조용히 갈린다.
**뷰포트 쿼리 신설 0** — 기존 `min-760` 블록 안에 규칙을 더했을 뿐이라 동결 목록 불변.

#### 왜 나머지 10건은 안 옮겼나

전부 뷰포트를 1:1로 따라간다(상수 오프셋). 컨테이너 쿼리로 옮기면 **같은 답을 다른
숫자로 쓰는 churn**이고, 옮기는 과정에서 40px 구간의 시각 변화만 새로 생긴다.
컨테이너 전환은 폭이 **실제로 갈라질 때** 하는 것이다(myplan 선례 — 사이드바 옆 실폭
712px에 2열을 답한 그 경우). 역전 2건(`gojuon-cell`·`fr-pager`)은 실재하지만 넘침이
없어, 고치는 쪽이 얻는 것보다 잃는 것이 크다 — 다음 세션이 다시 재보지 않도록 수치를 남긴다.

## 3. 접근성 (회귀 방지 하한)

| 항목 | 현재 | 규칙 |
|---|---|---|
| 터치 타깃 `44px` | 29곳 | WCAG 2.5.8 — 단독 아이콘 버튼은 44×44 |
| `:focus-visible` | 12곳 | 키보드 포커스는 반드시 보이게 |
| `prefers-reduced-motion` | 10곳 | 애니메이션에는 축소 분기를 함께 둔다 |

숫자는 하한이다. 줄어들면 계약이 잡는다.

## 4. 테마

- `data-theme` 속성 + `[data-theme="light"]` 재정의가 정본.
- **저장값이 있으면 그것, 없을 때만 OS 설정**(`prefers-color-scheme`)을 따른다.
  저장은 사용자가 토글할 때만 한다 — 자동 저장하면 '저장값 없음'(OS 추종) 상태가
  첫 렌더에 사라진다.

## 5. 계약과 e2e의 경계

계약 테스트는 전부 **소스 문자열 검사**다. "코드가 이렇게 쓰여 있다"는 지키지만
**"동작이 옳다"는 보장하지 않는다.** 픽셀·좌표·투명도는 실렌더 e2e
(`e2e/typography.e2e.mjs`)가 본다.

> **계약 = 배선 보증, e2e = 동작 보증.**

새 계약을 심을 때는 **일부러 깨뜨려 FAIL을 1회 확인**하고 커밋한다(v2-L에서
공허 통과가 실측된 뒤 굳은 절차). 앵커 슬라이스는 `helpers/sliceBetween`만 쓴다.
