# L3 型紙(가타가미) — NOTES (2026-10-15 KST)

## 구성 규칙(한 줄)
굵기 1u 단선 획을 칼로 오려 낸 형지다. **떨어질 종이(닫힌 속공간)와 획이 꿰뚫는 교차에만, '/' 45° 방향에 폭이 같은 つり(다리) 하나를 남긴다.**

| 항목 | 값 |
|---|---|
| 획 굵기 W | 1u(둥근 획은 ×1.08 광학 보정) |
| 글자 높이 H | 라틴 5u / 가나 칸 5.6u(5u에서 작도한 뒤 좌표만 ×1.12, 획 굵기는 그대로) |
| 획 끝 | 획 방향에 직각으로 자름(칼 끝). 곡선은 원호만 씀(거북이 작도: 직선 + 원호) |
| つり 방향 | 45°('/') 한 가지 |
| つり 폭 b | 큰 판 0.24u · 작은 판(-s, 24px 헤더용) 0.50u |
| 놓는 자리 | ① 닫힌 속공간 하나에 하나 ② 교차는 중심을 '/'로 갈라 ㄱ·ㄴ 두 조각으로 나눔. 교차가 속공간을 닫으면 그 つり 하나로 둘 다 처리 |
| 둥근 획 | '/'가 반지름과 겹치는 북동·남서에만 둔다. 그래서 획에 직각으로 잘린다 |
| 주홍 #d4462a | 'な' 음절의 つり 하나를 주홍으로 채운다(TONARI의 A 꼭지, な·ナ의 교차). 두 조각을 묶는 붉은 실이라는 뜻 |
| 검증 | つり를 오려 낸 뒤 잉크에 구멍(떨어지는 종이 섬)이 0개여야 한다. 빌드가 assert로 확인 |

つり 지도:
- TONARI: O 북동, A 꼭지(주홍), R 북동. 모두 3개
- となり: な의 가로×사선 교차(주홍), な의 꼬리×기둥 교차(고리 겸함). 모두 2개
- トナリ: ナ 교차(주홍). 1개

と·り·ト·リ·T·N·I에는 떨어질 종이가 없어서 つり가 없다. 장식으로 넣은 다리는 하나도 없다.

## 서명 디테일
1. **'/' 한 방향 つり의 리듬**: TONARI에서는 O·A·R 세 글자의 오른쪽 위에만 같은 각도로 틈이 나 있다. 그래서 단어 전체가 칼이 한 방향으로 지나간 형태로 기억된다.
2. **'な'의 붉은 실**: 세 마크 모두 'な' 음절(A / な / ナ)의 つり만 주홍이다. 교차를 둘로 가른 두 조각을 붉은 실이 묶는 모양으로, 「이웃」을 뜻한다.

## 회차(iterations/)
- `it1.png`: 첫 작도. な가 뭉개졌다. 고리 반지름이 0.82u라서 속공간이 W보다 작았고, 고리가 왼 사선에 붙었다. 주홍 つり와 つり 폭 0.20u는 큰 크기에서 가늘었다.
- `it2.png`: 가나 칸을 5.6u로 키워(좌표 ×1.12, 획 그대로) な 고리 반지름을 1.05u로 했다. 꼬리×기둥 교차가 고리를 닫는다는 점을 보고, 고리 남서의 つり를 지우고 교차 つり 하나로 고리까지 처리하게 바꿨다(규칙 ②가 ①을 겸함). つり 폭은 0.24u로 했다.
- `it3-plate.png`: **버린 시도.** 형지 판 사각 테두리와 小紋 점 한 줄을 넣어 봤다. 상자형 라벨이나 티켓 절취선처럼 읽히고, 24px에서는 글자가 30%가량 작아진다. 장식이 글자 밖에 붙는 셈이라 뺐다. `L3_PLATE=1`이면 다시 생성된다.
- `it4.png`: 여백 0.6→0.4u로 24px 글자를 키웠다. 작은 판 つり 폭은 0.50u(24px에서 약 2px), 자간은 N–A 0.3, A–R 0.25u로 조였다. 섬 0개 assert를 추가했다.
- `card.png`: 최종(카드 배치 정리, つり 지도 추가).

## 버린 시도
- 형지 판 테두리 + 小紋 점(it3): 위 참고.
- 모든 이음(T자 접합·꺾임)에 つり 두기: 그려 보기 전 설계 검토에서 버렸다. つり가 10개를 넘어 소음이 되고, '꼭 필요한 자리만'이라는 형지의 논리가 사라진다.
- O에 つり 두 개(북동+남서): 설계 검토에서 버렸다(그려 보지 않음). 한 사선이 O를 관통해 ⊘(금지 기호)처럼 읽힐 위험이 있어 하나로 줄였다.
- な 고리 남서 つり(it1): 교차 つり가 고리를 겸하면서 필요 없어졌다.

## 읽힘 점검
- ナ와 テ: ナ의 세로획이 가로획을 꿰뚫고 왼쪽 아래로 휘어서 テ(가로 두 줄)와 갈린다. 주홍 つり는 교차 위의 사선이라 가로 두 번째 줄로 읽히지 않는다.
- り와 リ: り는 왼 획이 오른쪽 위로 꺾여 올라가고(はね) 오른 획이 어깨 원호로 시작한다. リ는 왼 획이 곧은 짧은 기둥이고 오른 획이 수직에서 바로 휜다.
- TONARI: O의 틈은 0.24u 사선 하나뿐이라 C로 읽히지 않는다(24px 작은 판 포함).

## 선례 비교
가장 가까운 장르 선례는 TRANSIT 제호다(스텐실 끊김이 있는 장체). 차이는 세 가지다. 우리는 ① 끊김이 모두 '/' 45° 한 방향이고 ② 원·직선의 넓은 기하 비례이며 ③ 떨어질 종이와 교차에만 끊김을 둔다. 실루엣이 겹치지 않는 것은 확인했지만 장르가 같다는 점은 약점으로 남는다. 가문 문장(家紋)이나 특정 형지 무늬는 재현하지 않았다.

## 파일
- `build-l3.py`: 작도와 SVG 생성. Python 3 + shapely 2.x(불리언 연산)를 쓰고 서체 파일은 쓰지 않는다. 좌표는 0.01로 반올림한다. 두 번 빌드해 `SHA256SUMS.txt`가 같은 것을 확인했다.
- `svg/L3-{TONARI|tonari-hira|tonari-kata}[-s]-{light|dark}.svg`: 아웃라인 path. light는 밤 글자, dark는 눈 글자이고 주홍 path는 따로 있다. `-s`는 24px용 작은 판이다.
- `card.html` / `card.png`: 큰 크기(명/암), 웹 헤더 24px(큰 판 축소와 작은 판 비교), 표지 제호 크기.
- 재생성(리포 루트):
  ```
  python3 -I docs/japanology/magazine/brand/marks/lettering/L3-katagami/build-l3.py
  export PATH=/opt/node24/bin:$PATH; node <scratchpad>/shotfull.cjs card.html card.png 1500   # 이 폴더에서
  ```

## 스스로 본 약점
- 규칙대로라면 トナリ에는 つり가 하나뿐이다. 스텐실이라는 정체성이 세 마크 중 가장 약하다.
- 24px에서 주홍 つり는 1–2px짜리 붉은 점으로 줄어 '실'로 읽히지 않는다. 그 크기에서는 O·R의 흰 틈이 서명 역할을 한다.
- 획 자체는 기하 산세리프에 가까워서, つり를 빼면 개성이 많이 줄어든다. 서명이 つり 배치에 전부 걸려 있다.
