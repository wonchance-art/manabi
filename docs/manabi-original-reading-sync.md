# 원본 읽던 위치 동기화

2026-09-08. 오너의 ‘다음 작업 개시!’에 따라 직전 권장 후속인 기기 간 원본 읽기 위치 동기화를 구현한다. 부모 #1291, exact head 98415d70649be5980dd27f11a1c6e5b471399da2. 격리 worktree codex/original-reading-sync-20260908.

## 제품 계약

- 통합 서재에 내가 보관한 원본의 작성 본문·PDF·EPUB를 대상으로 한다. PDF는 쪽, 본문은 텍스트 위치, EPUB는 파일의 장과 장 안의 텍스트 위치를 보관한다. 픽셀 스크롤을 다른 화면에 그대로 적용하지 않는다.
- 로그인 계정 + 원본 자료 + 파일 hash/본문 revision별 위치다. 마지막으로 읽은 첨부도 다른 기기에서 이어 연다. 기존 자료 URL, 명시적 첨부 주소, 학습 구간 출처 링크를 보존하고 명시적 출처 이동을 일반 이어 읽기보다 우선한다.
- 처음 열 때 저장된 위치를 복원한다. 읽는 동안 다른 기기에서 위치가 바뀌면 안내와 ‘그곳에서 이어 읽기’를 제공하며 화면을 강제로 이동하지 않는다.
- 현재 기기의 위치를 유지할 수도 있다. 서버 버전을 비교하는 저장으로 오래된 요청/오프라인 기록이 최신 위치를 덮어쓰지 않도록 한다. 충돌은 최신 위치로 이동하거나 현재 위치를 명시적으로 저장하여 해결한다.
- 네트워크 실패 시 계정별 로컬 기록을 보관하고 재시도한다. 성공하지 않은 동기화를 ‘저장됨’으로 표시하지 않는다. 날짜는 서버가 기록하고 기기 시계로 우선순위를 정하지 않는다.
- 읽기 위치는 학습 완료율·표현 저장·FSRS 채점/일정과 별도다. 자료 내용/판본/첨부 파일을 수정하지 않는다. 출처 확인만으로 학습 진도나 복습을 채점하지 않는다.
- 새 사용자·위치 없음·로컬 저장 차단·연결 실패·오프라인·동시 탭·계정 전환·삭제/교체된 원본을 처리한다. 첨부가 바뀌면 새 파일 hash에 과거 위치를 옮기지 않는다.

## 데이터/동작

별도 private original_reading_positions 테이블과 RLS, SECURITY INVOKER RPC를 사용한다. owner/material/source key로 유일하며 실제 원본 소유·현재 또는 보관 첨부·본문 revision·입력 상한을 검증한다. RPC의 version 비교와 write_id로 충돌 및 저장 후 응답 유실을 처리한다. 본문 위치는 Unicode code point 단위다. 기존 localStorage 페이지 키는 초기 호환 읽기를 유지한다.

서버 조회 실패가 원본 열람을 무한히 막지 않도록 제한 시간을 둔다. 재연결·탭 복귀 시 위치를 재확인하고 사용자에게 이동 여부를 맡긴다. Realtime 구독이나 별도 외부 동기화 서비스는 추가하지 않는다.

## 허용 범위

- 신규 originalReadingPosition 모델/동기화 훅/안내 컴포넌트 및 관련 테스트.
- OriginalMaterialReader, 원본 읽기 CSS, libraryActivity/관련 최근 이어 읽기 연결.
- 필요한 경우 PdfJsViewer의 원본 위치 콜백(기존 API 호환), 합성 e2e fixture/검수 스크립트.
- migration 1개, 본 문서, 자기 보드만 별도 커밋.

제외: 다른 교재 진도 체계 통합, 레거시 PDF 전체 이관, 학습 구간 내용/표현/FSRS 변경, 파일 정리·URL 본문 가져오기·OCR·음성·PDF 교재 조판·월드·환경 파일. merge/force-push/운영 웹 승격 없음.

## 검증

- 실제 SQL: 소유자/비소유자/anon, 접근 철회, 원본 확인, source 변경, 범위/형식 제한, 동시 version 충돌, 응답 유실 재시도, 별도 파일 위치 및 원문·진도 불변.
- 모델: 저장 직렬화, 오프라인 큐와 복구, 중간 실패, 늦은 응답, 새로고침, 계정별 분리, 로컬 저장 불가.
- 두 독립 브라우저 저장소로 본문/PDF/EPUB 위치 왕복, 늦은 원격 업데이트가 화면을 움직이지 않는지, 명시적 출처 링크 우선, 파일 교체/보관 첨부.
- 320/390/768/1280px와 키보드/200% 글자 확대, 기존 선택 구간·서재·편집 흐름 회귀, 전체 Vitest와 빌드.
- 실제 로그인 계정은 기존 전용 검수 원본만 사용하고 원문·표현·복습 날짜를 바꾸지 않는다. 두 브라우저 저장소 테스트와 실제 물리 기기/Safari 검수는 구분하여 보고한다.
