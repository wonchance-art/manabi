# 교재·복습·내 자료 연결 설계

상태: 관리자 편집(1차), 공개 원고 통일·교재 복습 출처 연결(2차), 내 자료·여러 문맥 연결(3차) 운영 배포 완료. SQL 적용·권한 검증과 실제 운영 화면 검증을 완료했으며, 발행·PDF·TTS(4차)는 설계안. 2026-09-05. 최신 결과는 [배포 기록](textbook-release-verification.md)을 따른다.

교재는 학습 순서를 제시하고, 내 자료는 실제 문맥을 제공하며, 복습은 기억이 약해질 때 다시 꺼내게 한다. 세 화면이 같은 학습 항목과 출처를 공유하는 방향으로 연결한다.

## 확정된 교재 기준

- 한 언어의 한 레벨을 한 권으로 본다. 현재 Course의 언어×레벨 모델과 맞는다.
- 일본어 모브 `#80576A`, 중국어 세이지 `#466C5D`, 프랑스어 잉크블루 `#4D5D85`. 영어는 세 색과 구별되면서 차분한 앰버 `#85602F`를 제안·적용한다.
- 웹과 PDF의 학습 내용은 같은 원고와 판본에서 만든다. 화면 기능과 인쇄 배치는 매체에 맞게 바꾼다.
- 일본어 초반 본문은 기존 가나 우선 원칙을 지키고, 한자를 배우는 시점에 읽는 법을 붙인다. 중국어는 병음을 병기한다. 영어·프랑스어 학습자 화면에는 발음 표기를 붙이지 않는 기존 요청을 따른다.
- 문화는 회화 장면에서 짧게 접하고, 자료 탭의 읽기 글로 확장한다.
- 초급의 가벼운 진행 방식과 시험 범위의 충실함은 함께 유지한다. 복습에서 덜 보여 주는 항목도 교재 범위에서 삭제하지 않는다.

## 사용자가 경험할 흐름

1. 교재에서 한 단원을 학습한다. 단어·표현을 선택하면 뜻과 음성을 확인할 수 있고, ‘복습에 담기’로 필요한 항목을 저장한다.
2. 단원의 자료 탭에서 공식 읽기 글 또는 내가 연결한 기사·대본·PDF를 연다. 같은 뷰어 도구로 문장 설명, 단어 저장, 메모를 쓴다.
3. 뷰어에서 이미 배운 표현을 만나면 관련 교재 단원으로 갈 수 있다. 모르는 표현을 저장하면 출처 문장이 함께 남는다.
4. 오늘의 복습에서는 교재와 내 자료에서 저장한 항목이 함께 나온다. 같은 단어를 두 곳에서 저장해도 복습 항목을 중복 생성하지 않는다.
5. 틀린 항목은 ‘교재 설명 다시 보기’ 또는 ‘이 표현을 만난 자료’로 돌아간다. 문맥을 본 다음 짧은 재확인 문제로 마무리한다.

예: 주문 표현을 배운 뒤 카페 대본에서 `ください`를 다시 만난다. 이미 복습 중인 표현이면 새 카드 대신 대본 문맥을 추가한다. 다음 복습에서 ‘푸딩 하나 부탁하기’를 말하거나 빈칸을 채운다. 틀리면 단원의 표현 설명과 대본의 해당 문장으로 바로 돌아간다.

## 세 화면의 역할

| 화면 | 중심 역할 | 연결 기능 |
| --- | --- | --- |
| 교재 | 한 권의 순서대로 배우기 | 본문, 연습, 자료, 내 메모. 표현 저장과 복습 진입 |
| 내 자료 뷰어 | 실제 글·대본·PDF를 읽기 | 뜻·TTS·문장 설명·메모, 교재 연결, 출처와 함께 저장 |
| 오늘의 복습 | 답을 떠올려 기억 확인 | 약한 표현 우선, 문맥 교체, 교재/자료 원위치로 이동 |

교재의 본문 화면은 읽기 중심으로 유지한다. 기본 상태에서 뷰어의 분석 패널을 전부 펼치지 않는다. 사용자가 단어나 문장을 선택했을 때 관련 도구를 연다. 모바일은 하단 패널, 넓은 화면은 옆 패널을 쓰되, 같은 도구와 상태를 공유한다.

교재의 ‘자료’에는 공식 보충 글과 사용자의 개인 자료 연결을 구분해 표시한다. 공식 글은 교재 편집자가 관리하고, 개인 자료는 소유자에게만 보인다. 개인 자료를 교재와 연결했다고 공개 자료로 전환하지 않는다.

## 기존 기능에서 재사용할 것

- `grammarSrs.js`: 챕터 복습 대기열과 FSRS 갱신.
- `RefPatternCheck`: 단원 문제 결과와 복습 등록.
- `user_vocabulary` 및 `useInlineReview`: 저장 단어와 뷰어 안의 간단한 복습 평가.
- `ViewerPage`: 단어 클릭, 문장 분석, 원문 문맥과 단어 저장, 읽기 진도.
- `grammar_notes` 및 `useGrammarNoteSave`: 자료에서 선택한 문장과 개인 설명.
- `PdfViewerPage`: 업로드 PDF 열람과 문장 분석. 현재 PDF 페이지 좌표와 원문 위치 연결은 추가 설계가 필요하다.
- `lessonModel.js`: 언어·레벨별 Course, Lesson, chapterRefs, Review 모델.

2차에서 `publishedChapter.js`를 도입했다. 교재 화면·메타데이터·이전/다음 제목·누적 복습, `/review/grammar`의 문항·예정 제목·백필 판정, 공부 모드의 교재 문제를 같은 공개 수정본으로 해석한다. 문제의 다른 챕터 보기 풀도 수정본을 사용한다. 진행 중인 세션은 처음 받은 내용을 유지하고 새 세션은 최신 원고를 읽는다. 발행 이력을 보관하는 불변 판본 저장소는 아직 없다.

## 같은 표현, 여러 문맥

‘학습 항목’과 ‘출처’를 분리한다.

- 학습 항목은 언어·표현의 정규화된 식별자와 의미를 가진다. 동형어의 다른 뜻까지 무조건 합치지 않는다.
- 복습 일정은 사용자와 학습 항목의 조합에 한 번만 존재한다.
- 출처는 한 항목에 여러 개 붙을 수 있다. 교재 예문, 기사 문장, PDF 문장 등을 각각 보존한다.
- 다시 저장할 때 기존 FSRS 일정과 숙련도는 초기화하지 않는다. 새 문맥만 추가한다.
- 개인 문맥의 추가·삭제는 다른 사용자의 교재나 복습 상태에 영향을 주지 않는다.

처음부터 기존 복습 테이블을 모두 새 테이블로 옮기지 않는다. 현재 단어/문법 복습을 묶어 보여 주는 어댑터를 먼저 만들고, 출처 연결과 중복 방지 계약을 추가한다. 이행 기간에도 동일 개념의 복습을 두 번 청구하지 않도록 기존 항목과 새 개념 ID를 매핑한다.

## 원래 위치로 돌아가기

출처 위치의 목표 계약은 다음과 같다. 2차에서는 교재 예문의 출처와 당시 발췌를 기존 `review_events.detail.sourceRef`에 저장하도록 연결했다. 3차에서는 읽기 글·PDF의 발췌를 개인 단어 카드의 추가 출처로 연결했다. 아래 표는 불변 판본·정밀 위치까지 포함하는 최종 목표이며, 3차의 실제 위치 계약은 진행 현황에 구분했다.

| 출처 | 위치 정보 |
| --- | --- |
| 교재 | bookId, chapterSlug, sectionId, blockId, editionId, 선택한 원문 |
| 읽기 글·대본 | materialId, paragraphId, token 범위, 자료 버전, 선택한 원문 |
| PDF | documentId, 파일 버전, 페이지 번호, 선택 텍스트, 가능하면 정규화된 사각형 좌표 |

화면상의 배열 순서나 PDF 쪽 번호 하나만 영구 식별자로 사용하지 않는다. 교재 편집으로 문장이 옮겨져도 blockId와 판본 정보를 통해 출처를 찾게 한다. 현재 교재는 section index를 사용하는 부분이 있으므로, 1차 편집기에서는 섹션·문항 배열의 추가·삭제·재배치를 제공하지 않았다. 안정적인 식별자 부여와 기존 학습 기록 매핑을 준비한 뒤 구조 편집을 연다.

2차의 이행용 맵은 파일 원고의 섹션·예문 내용을 기준으로 sectionId/blockId를 만들고 기존 위치도 함께 기록한다. 웹에서 제목·문장을 수정해도 ID는 유지한다. 원문 발췌·번역과 현재 내용 지문 `revision`을 함께 저장하며, 이 지문은 보관된 출판 판본 ID와 구분한다. 원고 파일을 직접 크게 개편하거나 중복 문장을 재배치할 때는 별도의 ID 이행이 필요하다. 구조 편집은 계속 제한하고, 위치를 찾을 수 없는 이전 링크에는 단원 확인 안내를 표시한다.

복습에서 답을 확인하면 ‘교재에서 이 예문 보기’가 나타난다. 새 탭에서 실제 예문 위치를 열어 진행 중인 답안을 보존한다. 현재 원고 지문이 복습 시작 당시와 다르면 수정 안내를 표시한다. 열람 자체로 복습 일정이나 정답 기록을 바꾸지 않는다.

원문이 바뀌었을 때는 기존 발췌를 보존하고 ‘원문이 수정됨’을 표시한다. 자료가 삭제·비공개 전환됐으면 다른 사람에게 원문을 노출하지 않고, 접근 가능한 출처만 제공한다.

## 복습으로 인정하는 행동

- 페이지를 열거나 TTS를 재생하는 것만으로 정답 처리하지 않는다.
- 뜻을 떠올린 뒤 답 보기, 빈칸 답하기, 문장 바꾸기, 말한 뒤 자기평가처럼 회상한 결과만 복습 기록에 쓴다.
- 자기평가와 실제 정답 채점은 구분한다. 현재 `qtype: flash`의 낮은 신뢰도 처리 원칙을 재사용한다.
- ‘읽음’, ‘단원 학습 완료’, ‘복습 통과’를 별도 상태로 유지한다.
- 같은 화면에서 반복 클릭하거나 저장을 재시도해도 복습·점수 이벤트가 중복 기록되지 않도록 요청 ID를 둔다.

오늘의 복습 기본 구성은 기한이 지난 항목 → 최근 자주 틀린 항목 → 여력이 있을 때 새로 저장한 항목이다. 처음에는 5~10분 정도의 짧은 세션으로 제안하되, 세션을 짧게 끝내는 것이 해당 레벨 전체 범위를 축소하는 의미가 되지 않게 한다.

## PDF와 웹의 판본 일치

공개 원고 판본을 하나 선택해 웹 본문, 연습 문제, 자료 링크, PDF, TTS 목록을 함께 만든다. PDF에는 책·판본·단원 정보와 해당 웹 단원으로 가는 링크/QR을 넣는다. 현재 읽고 있는 PDF가 구판이면 해당 판본의 원문으로 연결하고 최신판 안내를 별도로 제공한다.

본문이 고쳐졌을 때 문항 ID와 복습 일정은 유지한다. 정답이나 학습 목표가 실질적으로 바뀐 문제는 개정 표시와 재확인 대상으로 처리하고, 문구만 다듬은 수정은 이미 쌓인 학습 기록을 초기화하지 않는다.

문장별 TTS는 언어·정규화한 텍스트·음성 설정의 해시로 관리해 변경된 문장만 다시 만든다. 무료 고품질 음성 제공자는 아직 선정하지 않았다. 무료 범위, 상업 이용 조건, 한국 사용자에게 들리는 품질을 실제 샘플로 비교한 뒤 정한다.

## 관리자 편집과 공개

이번에 만든 1차 편집은 기존 공개 수정본 저장 방식을 사용한다. 저장하면 교재에 바로 반영된다. 미리보기는 저장 전 내용 확인이며 비공개 서버 초안 저장이나 PDF 출력은 아니다.

향후 본격 발행 단계에서는 다음처럼 분리한다.

1. 관리자 비공개 초안에서 편집.
2. 언어·레벨 규칙, 한자/읽기 병기, 필수 시험 범위, 문제 정답, 음원 상태 검증.
3. 웹·PDF 동일 판본 미리보기.
4. 검토 후 공개. 이전 공개 판본으로 되돌릴 수 있게 보존.

비공개 초안은 현재 공개 읽기 권한이 있는 `content_overrides`에 그대로 저장하면 안 된다. 관리자만 읽는 초안 저장소와 공개 판본 저장소를 분리하고 RLS를 적용한다. 그 단계의 마이그레이션은 별도로 설계·검토한다.

## 진행 순서

### 1차 — 관리자 편집, 이번 작업

- `/admin/textbooks`: 언어·레벨·챕터 선택, 제목·안내·본문·예문·대화·표·읽기·연습 내용의 폼 편집.
- 저장 전 내용 미리보기, 저장 상태, 실패 시 입력 유지, 저장하지 않은 변경을 버리기 전 확인.
- 서버 관리자 검사, 기존 RLS 사용, 문항 ID/출처 보존, 읽은 수정 버전과 다른 경우 저장 충돌 처리.
- 관리자 홈의 콘텐츠 탭, 교재 목록, 챕터 하단에서 편집기로 진입.
- 교재 강조색과 편집기의 언어별 색상 연결.

### 2차 — 같은 원고와 교재 출처 연결, 이번 구현

- 교재·문법 복습·공부 모드의 공개 원고 해석 경로 통일.
- 이행용 sectionId/blockId·기존 위치 매핑, 현재 내용 지문과 당시 발췌 기록.
- 복습 문항에서 원래 예문으로 이동, 원고 변경·위치 변경 안내.
- 사용자×언어×챕터 큐 키와 기존 FSRS 유지. 반복 통과는 중복 등록을 무시하고 백필 입력 중복도 제거.
- 클라이언트 완료 처리 중복 방지. 말하기 자기평가는 `assessment: self`, `qtype: flash`로 실제 정답 채점과 구분.
- 개인 단어와 교재 개념을 하나로 합치는 작업은 3차의 여러 출처 연결과 함께 진행한다.

검증: 관련 190개 테스트, 변경 운영 파일 린트, 실제 서버 교재 렌더와 복습 컴포넌트를 사용하는 격리 브라우저에서 답변→출처 이동→세션 유지→완료 흐름을 확인했다. 320/390/1024px의 밝은/어두운 테마에서 가로 넘침과 실행 오류가 없었다. 인증·저장·TTS는 모형으로 대체했으며 운영 데이터 쓰기·DB 스키마 변경·배포·전체 앱 빌드는 수행하지 않았다.

### 3차 — 내 자료 뷰어 연결, 운영 배포 완료

- 교재의 ‘자료와 함께 복습하기’에서 내 읽기 자료·PDF를 연결한다. 자료 뷰어에서도 교재 단원을 선택하고 해제할 수 있다. 연결 목록은 개인 소유이며 자료의 공개 범위를 변경하지 않는다. 목록 제목도 관리자 공개 수정본을 사용한다.
- 교재 일반 예문에서 단어·표현과 뜻을 입력해 저장한다. 레슨 어휘는 개별 또는 일괄 저장한다. 읽기 자료의 단어 선택·드래그, PDF 분석 단어 목록·팝업에서도 같은 출처 저장 API를 사용한다.
- 기존 `user_vocabulary` 카드를 유지하고 `vocabulary_contexts`에 교재·읽기·PDF 발췌를 추가한다. 문맥 추가는 기존 카드의 뜻·간격·숙련도·복습일을 수정하지 않는다. 공통 저장 RPC 안의 단어 등록과 문맥 저장은 하나의 DB 트랜잭션이며 재시도는 중복 출처를 만들지 않는다. 최신 뷰어의 기존 카드 저장 경로는 먼저 정본 조립기로 카드를 저장한 뒤 문맥을 추가하며, 문맥만 실패하면 별도 안내와 재시도를 제공해 기존 4등급 저장·취소를 유지한다.
- 이전 PDF 저장 방식의 활용형 카드도 `base_form`이 같은 단일 후보이면 재사용한다. 후보가 여러 개면 새 카드를 만들거나 임의로 합치지 않는다. 기존 고유 키가 `(user_id, word_text)`이므로 언어가 다른 동형어는 충돌 안내를 한다. 언어·의미별 여러 카드의 완전한 이행은 별도 작업이다.
- 뜻이 다르면 기존 뜻과 이번 뜻을 보여 주고 같은 의미인지 확인한다. 확인에는 카드 ID와 확인 당시 뜻을 함께 보내 오래된 확인으로 덮어쓰지 못하게 한다. 다른 뜻인 경우 취소하며, 새 의미별 카드 생성은 이번 범위에 포함하지 않았다.
- 복습 답을 연 뒤 여러 문맥을 볼 수 있고 원문을 새 탭으로 연다. 문맥만 지워도 단어·일정·자료 원본은 유지된다. 최초 저장 예문은 기존 카드에도 남는다.
- 읽기 자료: 토큰 ID와 표면형으로 위치를 찾는다. 재분석으로 위치가 달라졌으면 유일한 표면형 일치만 강조하고 중복·미일치는 안내한다. 드래그 선택은 원문 포함 여부를 서버에서 확인한다. 문단 버전·좌표를 영구 보관하는 기능은 아직 없다.
- PDF: 발췌는 사용자 선택 입력이다. PDF.js 모드의 현재 쪽수를 출처 입력에 반영하고 브라우저 기본 PDF 모드에서는 직접 쪽수를 입력한다. 저장한 페이지를 PDF 열기 주소로 전달한다. 선택 좌표의 정밀 복원은 제공하지 않는다.
- 로그인 사용자는 기존 서버 단어장 큐를 사용한다. 게스트의 기존 로컬 레슨 카드는 유지하며 자동 이관하지 않는다. 자가 체크 자체는 로그인 사용자의 단어 카드를 별도로 중복 생성하지 않는다.

운영 적용: 사용자 직접 승인에 따라 [3차 적용 안내](textbook-material-contexts.md)의 SQL을 Manabi에 적용하고 운영 권한·기존 데이터 보존을 검증했다. 이후 최신 운영 코드에 통합해 전체 빌드·배포를 완료했다. 기본 CI 전체 3,688테스트와 E2E가 통과했고 실제 운영 16개 화면 및 비로그인 접근 차단을 확인했다. 앞선 단계의 PostgreSQL 권한·원자성·기존 일정 보존 20개 검사와 격리 Chrome 흐름 검사도 통과했다. 실제 운영 사용자 원고·자료·카드 쓰기는 검증 목적으로 수행하지 않았다.

이번 범위 밖: 공식 문화 reading 신규 집필, 표현과 교재 개념의 자동 추천, 의미별 카드 마이그레이션, 불변 판본·PDF 정밀 좌표. 현재 자료 연결은 사용자가 명시적으로 선택한다.

### 4차 — 발행과 PDF·TTS

- 관리자 초안·공개 판본 분리, 개정 이력과 복원.
- 동일 원고의 웹/PDF 출력과 시험 범위 점검.
- 문장별 TTS 생성·재사용, 완성도 검수 후 레벨별 책 확장.

3차까지 운영 배포를 완료했다. 4차는 설계안이다. 다음 본격 제작 범위는 관리자 초안·공개 판본과 웹/PDF 동일 원고 출력이며, 발행 전에 검토 가능한 시안과 판본 계약을 먼저 준비한다.
