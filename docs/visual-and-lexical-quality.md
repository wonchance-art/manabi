# 뷰어·설명판 품질 기준

이 검사는 합성 자료로 실제 UI 부품과 읽기→뜻 확인→설명판→노트 정리를 검증한다.
실계정 권한, 실제 AI 번역 정확도, 배포 글꼴, 물리 iPad/Pencil 검수를 대체하지 않는다.

## 화면 기준

- `npm run qa:release`에 Chromium/WebKit 화면·접근성 검사가 포함된다.
- CI는 `npm run qa:release -- --collect-all`로 정리가 완료된 독립 검사들의 실패를 한 번에
  수집한다. 실패 하나라도 있으면 최종 결과는 실패다. 빌드·서버·정리·격리·입력 불변 조건이
  깨지면 즉시 중단한다. 기본 로컬 명령의 첫 실패 중단 동작은 유지한다.
- 대표 화면: 다중 표현+필기 설명판, 폰 표현 입력, 폰 뜻 창, 폰 Aa 설정,
  폰 집중 문장, 일본어 독음/훈음/오른쪽 뜻, 폰 개인 노트 정리.
- `e2e/visual-baselines/<OS>-<CPU>-<engine>-<version>`의 PNG 및 검토 해시와 비교한다.
  기준 부재, 해시 불일치, 크기 변경, 20픽셀 초과 차이, 불안정 캡처는 실패다.
  색 차이 threshold 0.12·앤티앨리어싱 경계 제외를 사용한다. 내용 마스킹은 없다.
- 테스트는 기준 이미지를 생성/갱신하지 않는다. 실패 실행의 `visual/*/*.png`를 직접
  확인하고 **이미 확인한 SHA-256**과 검토 사유를 지정해 별도 승인한다.
  `node scripts/qa-visual-approve.mjs <case.json> <inspected-sha256> '<review>'`
  CI에서는 이 승인 명령이 거부된다. 새 OS/브라우저도 검토 없이 통과하지 않는다.
- 기준 파일은 PR에 포함하고 UI 변경과 함께 diff를 검토한다. 실패 보고서에는 실제 이미지와
  차이 이미지, 브라우저/OS/뷰포트, 접근성 위반과 판정 불가 항목이 남는다.
- Next 합성 빌드는 기존 오프라인 폰트 대역을 사용한다. 기준은 **하니스 렌더링의 회귀 기준**이며
  운영 Noto 글꼴 자체의 최종 타이포그래피 승인으로 부르지 않는다.
  Linux CI에는 `fonts-noto-cjk`를 설치해 한글·한자가 빈 글리프로 검수되는 것을 막는다.
- 이미지 비교와 접근성 검출기가 작동하는지도 검증한다. 이름 없는 버튼과 2px 배치 변형을
  실제 브라우저에 넣으면 실패해야 한다. 단위 검사는 1px 이동과 잘림을 별도로 거부한다.
  집중 모드는 실제 뷰포트를 캡처해 긴 본문 요소의 자동 스크롤이 상단 도구를 겹쳐 찍는 것을
  피한다. 설명판은 계정 저장 완료, 투명도·글자 크기는 실제 전환 완료를 확인한 뒤 검사한다.

## 접근성 범위

axe-core WCAG 2 A/AA, 2.1 AA, 2.2 AA를 실제 열린 패널에 적용한다.
보드에서는 Manabi 메뉴를 검사하며 Excalidraw의 픽셀 필기 자체를 DOM 접근성 통과로 세지 않는다.
집중 모드는 사용자가 의도적으로 흐린 주변 글과 선택한 선명한 문장을 분리하고 선택 문장을 검사한다.
주변 opacity ≤0.3/선택 opacity 1을 기하 계약으로 고정한다.
Aa 탭의 End 이동·대화상자 Tab 순환·Escape, 기존 복귀 초점·폰/태블릿/가로 넘침 검사를 함께 실행한다.
WebKit의 네이티브 dialog에서 Tab이 브라우저 크롬으로 잠깐 이동할 때는 문서의 초점 상실을
확인하고 다음 Tab이 dialog 안으로 복귀해야 한다. 뒤쪽 페이지의 활성 요소로 빠지면 실패다.
글자를 200%로 키웠을 때도 뜻 창을 열 수 있고 문서에 가로 넘침이 없어야 한다.
axe의 `incomplete`는 무시된 오류나 통과가 아닌 수동 검토 대상이다. 특히 SVG 글자 대비와
캔버스 필기 읽기는 별도 확인이 필요하다. 자동 도구는 WCAG 전체 준수를 보증하지 않는다.

## 검수에서 발견한 제품 수정

폰의 오른쪽 뜻 영역에서 `입장에서`가 `입 / 장에서`로 끊어졌다. 뜻 조판은 들어갈 수 있는
단어를 통째로 다음 줄에 보내며, 한 단어 자체가 열보다 길 때만 글자 단위로 나눈다.
독음·훈음의 글자 정렬, 기존 저장된 설명판 요소의 크기, 원문의 공백과 개행은 보존한다.

## 의미 기준 40건

`e2e/fixtures/lexical-gold.json`은 기존 `lexical-senses.json`을 참조해 중복 정본을 피한다.
32건은 직접 작성한 문맥·선택 의미·독음·품사·금지 혼동을 갖고, 8건은 문맥 없는 입력의
자동 확정 금지 사례다. 사용자 문장이나 개인 노트는 사용하지 않는다.

- 출처: 교육부 국어사전, 小学館 사전의 Kotobank 제공 항목, 漢字ペディア, 文化庁 常用漢字表.
- 한글 뜻, 예문, 앱 품사 정규화, 일본어 대응은 편집안이다. 사전 본문을 복제하지 않는다.
- 중국어 독음은 출처에 명시된 **대만 사전 기준**이다. `研究 yán jiù` 같은 지역 차이를
  HSK 오답으로 판정하지 않는다. 대륙 표준을 확정하기 전 HSK 독음 평가에 사용하지 않는다.
- 일본어 대응 후보는 독립 이중언어 검토 전이다. 정확히 일치해도 이 부분을 자동 합격시키지 않는다.
- `node scripts/qa-lexical.mjs`는 자료의 완결성만 검사한다. 공급자 호출·모델 성적은 없다.
- `assessLexical`은 알려진 오역을 구분하고, 허용 목록에 없는 바른 의역도 `needs-review`로
  남긴다. 응답 없음은 `not-run`, 문맥 없이 단정하면 `unsafe-certainty`다.
- 실제 모델 평가는 공급자/프롬프트/모델 버전·표본·비용 한도를 정하고 원응답을 확보한 다음 한다.
  준비된 정답을 그대로 평가 함수에 넣은 단위 테스트를 AI 정확도로 보고하지 않는다.

## 오픈소스 판단

| 도구 | 채택 | 이유 / 한계 |
|---|---|---|
| 기존 Playwright Core (Apache-2.0) | 재사용 | 기존 실제 컴포넌트/브라우저 시나리오 유지, 새 테스트 프레임워크 중복 없음 |
| axe-core (MPL-2.0) | 테스트 의존성 | 브라우저 WCAG 규칙 실행, 판정 불가/수동 검수는 남음 |
| pixelmatch (ISC), pngjs (MIT) | 테스트 의존성 | 작은 이미지 비교/PNG 입출력, 제품 번들에 포함하지 않음 |
| 현재 이미지를 매번 정답으로 자동 갱신 | 배제 | 회귀를 정상 상태로 덮어쓰므로 사람이 검토한 해시만 승인 |
| CI에서 실제 AI 호출 | 배제 | 합성 기능 검사와 의미 품질·비용·개인정보 경계를 섞지 않음 |

근거: [Playwright 화면 비교](https://playwright.dev/docs/test-snapshots),
[axe-core](https://github.com/dequelabs/axe-core), [pixelmatch](https://github.com/mapbox/pixelmatch).
각 어휘의 정확한 출처는 기준 JSON과 기존 lexical-senses에 연결되어 있다.
