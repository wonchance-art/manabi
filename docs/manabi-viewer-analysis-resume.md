# 뷰어 분석 복구 A — 구현과 검수

2026-09-09 KST. 오너의 설계 승인 후 ‘작업 진행’ 요청으로 착수했다. #1296의 Claude 후속 요청 중 분석 resume 항목을 별도 PR #1297로 구현한다. 부모 `19f5c5d5b7307ddc62383b018e077bebbc0d4560`의 이력을 유지한다.

## 결과

- 원문 줄과 분석 토큰을 비교해 누락·실패·불완전 줄을 합친다. 실패 토큰이나 개행 토큰이 있다는 이유만으로 완료로 세지 않는다.
- ‘이어서 분석’이 실제 복구 인덱스를 분석기에 전달한다. 완료 상태만 남았으면 AI 호출 없이 기존 비교 저장 RPC로 마무리한다.
- 분석 요청은 기존 문단 단위를 유지할 수 있지만 정상 줄의 결과·ID·독음·뜻·개행은 기존 것으로 병합한다. 동일 문단의 정상 줄 응답이 실패해도 그 줄의 기존 결과를 잃지 않는다.
- 직접 수정한 뜻·독음과 위치가 확실한 토큰 ID를 보존한다. 사전 구멍 등으로 글자 위치를 증명할 수 없는 경우 임의로 다른 토큰에 교정을 붙이지 않는다.
- 모든 줄·ID·내용을 검증한 뒤 한 번에 조건부 교체한다. 중지, 응답 누락, 교정 이력 조회 실패, 동시 수정에서 기존 자료를 유지한다.
- 완료로 표시됐지만 내용이 빠진 자료도 복구 안내를 제공한다. 중단된 자료의 관리 메뉴는 사용할 수 있어 구조 오류 시 전체 재분석으로 전환할 수 있다.
- 복구 안내·진도·중지 버튼을 기존 배너에 표시한다. 작은 화면에서 줄바꿈하며 버튼 높이 44px를 보장한다. 중국어 버튼은 뷰어의 세이지 색상을 따르고, 실패 표시가 본문 위로 떠 있던 위치를 해당 토큰 옆으로 옮겼다.

## 보존 범위

기존 `viewer_replace_analysis`를 사용한다. DB 스키마·권한·원문·학습 일정의 일괄 변경은 없다. 새 단어 저장/취소와 출처 문맥 UUID는 변경하지 않는다. 구간 지문 분석은 기존 별도 흐름을 유지한다. 새 외부 서비스나 일본어 대조의 선택 문장 전송은 추가하지 않는다.

이번 실행의 중간 결과는 메모리에만 둔다. 창을 닫으면 이미 저장돼 있던 분석에서 다시 복구한다. 같은 문단의 정상 줄도 기존 분석 요청에 포함될 수 있으므로 ‘실패 줄만 외부로 전송한다’고 안내하지 않는다.
