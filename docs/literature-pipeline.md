## 1. 순환 속 자리

학습 순환 ① 「자료 읽기」의 **입구**다. 정본 책이 늘면 함께 읽는 글 → 뷰어 → 단어 저장 → FSRS 복습으로 이어지는 자료가 늘어난다.

## 3. 이번에 구현한 것

1. **후보 선정** `scripts/literature/candidates.mjs` — 색인 CSV(`list_person_all_extended_utf8.zip`)를 작품별로 묶고, 2020–22년
   접속 순위(XHTML 열람 상위 500, 2023년 이후는 게시되지 않음)로 정렬. 이미 수록한 작품은 뺀다.
2. **작품 추가** `scripts/literature/add-work.mjs` — 받기·해시·변환·파싱·진단·entry 초안. 다시 돌려도 사람이 채운 칸(레벨·표기·권리)은 지키고
   원문·해시·색인 칸만 새로 쓴다.
3. **결정적 변환** — Node 내장 Shift_JIS 디코더(WHATWG = Windows 대응)에 JIS X 0208 표준 대응 여섯 칸을 되돌린다(`〜 ‖ − ¢ £ ¬`).
   기존 5편의 `source.txt`가 예전 iconv 절차와 바이트까지 같게 재현된다(실측 — 鼻·文鳥의 0x8160).
4. **외자** — `src/lib/aozoraJisx0213.json`(JIS X 0213:2004 추가 4,354자, Python 표준 코덱 `euc_jis_2004`에서 생성,
   `scripts/literature/gen-jisx0213.py`). 「第3水準1-85-56」·비한자 「1-6-84」를 푼다. 쪽-줄 표기(「168-12」)·설명만 있는 외자는 미해결(fail-closed).
   외자에 걸린 루비(「※［＃「目＋匡」、第3水準1-88-81］《まぶた》」)는 외자 글자를 기준으로 저자 루비 잠금이 된다.
5. **권리 선 보정** — 예전 식 「1931년 이전 출판 **또는** 1945년 이전 사망」은 출판만 이르면 사망 연도를 보지 않았다. 그래서
   1968년 이후 사망 작가의 1931년 이전 작품(川端康成 1972 사망 · 伊豆の踊子 1926 — 일본에서 2042년 말까지 보호)이 식을 통과할 수
   있었다(색인의 저작권 존속 표시가 막아 주긴 한다). `aozoraJurisdictionVerdict`로 관할별 판정을 하고 「1945년 이전 사망, 또는
   1931년 이전 출판 + 1968년 이전 사망」으로 고쳤다. 한국은 저작권법 제3조 제4항(보호기간 상호주의) — 본국에서 만료된 외국
   저작물은 한국에서도 보호하지 않으므로 일본 판정을 따른다(江戸川乱歩·谷崎潤一郎의 1931년 이전 작품은 세 관할 모두 만료 → 후보).
6. **D5 개정(오너 2026-10-15 KST 「일본에서만 끝나면 그만」)** — 공개 조건을 **일본 보호기간 만료(작가 1968년 이전 사망)** 하나로
   줄였다. 미국(URAA 회복 — 1931년 이후 출판·1945년 이후 사망 작가는 출판 후 95년)은 참고 판정으로만 남긴다. 검토 관할 기록은
   JP·KR. 太宰治(1948)·坂口安吾(1955) 등이 열렸다(走れメロス는 青空文庫 열람 1위). 雪国(川端康成 1972)은 일본에서 2042년 말까지
   보호라 여전히 青空文庫에 없다.
   처음 안은 한국 자체 기간(사후 70년)으로 1963년 선을 그었으나, 오너 질의(「우린 원문 다루는데 왜 강화?」)로 다시 보고 바로잡았다.
6. **긴 見出し 장** — 4,000자를 넘는 見出し 장만 그 장 안에서 고르게 나눈다(坊っちゃん 「一」 7,539자 → 「一 (1/3)」 2,551 · 2,342 · 2,644).
   예전에는 6,000자를 넘을 때만 앞에서부터 잘라 「(2/2)」 758자 같은 꼬리가 생겼다.
7. **5차 보완(2026-10-15 KST, 오너 「빼기엔 너무 중요한 작품들 — 상징적이니 추가」)** — 상징작이 막혀 있던 네 원인을 고쳤다.
   - **장보다 긴 문단 → 문장 끝 분할**(`aozoraMaterial` `sentencePieces`): 吾輩は猫である 한 문단 1만 1천 자 · 駈込み訴え 전체 두 문단.
     문단 경계만으로 장 상한 안에 못 들면, 목표 2/3보다 긴 문단을 문장 끝(。！？ + 닫는 괄호, 인용 뒤 「と·って·、」 앞은 제외)에서 조각내
     다시 나누고, 장 안에서는 한 문단으로 도로 잇는다(빈 줄을 새로 만들지 않는다). **문단 경계로 다 들어가는 작품에는 쓰지 않으므로
     기존 26편의 장 경계는 한 글자도 바뀌지 않는다**(`--check` 실측). 見出し 없는 원작이 문단이 커서 고르게 못 나뉠 때(陰翳礼讃
     1,972자 첫 장)도 더 고른 쪽을 고른다. 진단 `sentenceSplitCount`(있을 때만 기록).
   - **꼬리 장 고르기**: 見出し 없는 긴 원작의 끝 장이 목표 2/3 미만이면 끝 두 장을 반씩 다시 나눈다(ドグラ・マグラ 1,739 → 2,467·2,321).
   - **여러 줄 中見出し**(`aozoraParser`): 「ここから中見出し」…「ここで中見出し終わり」 사이 줄을 전각 공백으로 이은 표제 하나(学問のすすめ 九編).
     窓·同行 블록형은 여전히 경고.
   - **기호 외자·기호 루비**: Unicode에 한 글자가 없는 「感嘆符三つ」는 ！！！, 물음표·느낌표 한 글자에 붙은 루비(「？《インタロゲーションマーク》」)는
     그 한 글자를 기준으로(ドグラ・マグラ). 괄호 같은 다른 기호는 여전히 경고.
   - **루비 기준 안의 외자**(기존 결함): 「｜御※［＃…］《ごぜん》」의 외자가 풀리지 않고 주석 글자째 본문에 남았다(吾輩は猫である) — 기준 안에서도 푼다.

## 4. 게시 자동화 설계 — 제안 (오너 결정 필요)

지금 게시는 작품마다 「게시」(확인) → 브라우저에서 장마다 분석(화면을 닫으면 멈춤) → **장마다** 「검수 완료」 → 「공개」(확인)다.
13편·67장이면 클릭이 120번 가까이(게시·공개 확인 52 + 장별 검수 67)이고, 분석하는 동안 관리자 화면을 열어 두어야 한다. 세 단계로 줄인다.

### 4.1 일괄 게시·분석 (코드만 — 인프라 변경 없음) · 구현(오너 「권장대로」 2026-10-14 KST, AOZORA-P1-2)

```
📚 정본 문학책                                       [준비 안 된 8편 모두 게시·분석]
진행 중: 坊っちゃん 분석 12/34 · 남은 작품 3편 · [멈춤]
┌ 羅生門   芥川龍之介 · N2 상급 · 2장   검수 대기 2장       [검수 열기]
├ 坊っちゃん 夏目漱石 · N2 상급 · 34장  분석 중 12/34
└ 山月記   中島敦 · N1 심화 · 2장      준비 안 됨(대기열 3번째)
```

- 한 번 누르면 준비 안 된 작품을 차례로 준비·분석한다(지금의 「게시」+「이어서 분석」을 대기열로). 멈췄다가 다시 누르면 남은 장부터.
- 확인 창은 대기열 시작 때 한 번(작품 목록과 권리 근거를 한 화면에).

### 4.2 검수 묶음 처리 (사람 확인은 그대로) · 구현(오너 「ㄱㄱ」 2026-10-15 KST, AOZORA-P1-10)

```
坊っちゃん — 검수 34장 중
  확인할 낱말이 없는 장 29장   [29장 검수 완료]
  확인할 낱말이 있는 장 5장     一 (2/3) 3개 · 四 (1/3) 1개 …  [열기]
```

- 분석 뒤 「뜻 확인 필요」가 0개인 장은 한 번에 검수 완료할 수 있게 묶는다. 판단이 필요한 장만 하나씩 연다.
- 버튼은 사람이 누른다 — 자동 검수 완료는 하지 않는다(검수 = 사람 확인 지점이라는 기존 계약 유지).
- 구현: 「뜻 확인 필요」 0 **그리고 쪼개진 저자 루비 낱말 0**인 검수 전 장만 묶는다(확인 창 한 번). 서버 `reviewMany`가 장마다 같은
  판정을 다시 해 그사이 바뀐 장은 이유와 함께 넘긴다(부분 성공). 같은 때 **분석 이어하기**도 넣었다 — 관리자 화면을 다시 열면
  모든 장을 준비해 둔 작품의 멈춘 분석을 한 번 자동으로 잇는다(4.3 없이 「화면을 닫으면 멈춤」의 손일을 줄인다, 쓰기(prepare)는 하지 않음).

### 4.2a 고유명사·낱말 경계 (오너 「고유명사 같은 게 … 형태소로 나눠버리는 상황 빈번함」 2026-10-15 KST, AOZORA-P1-10)

### 4.2b 분석 실패 건너뛰기·배포 뒤 점검 (오너 「권장대로」 2026-10-16 KST, AOZORA-P1-13)

- **실패 건너뛰기**: 한 장이 실패해도 다음 장을 잇고 끝에 건너뛴 장을 한 번 알린다(실패한 장은 분석 전으로 남아 다음 이어하기에서
  다시 시도). 연달아 3장 실패하면 할당량·네트워크 같은 공통 원인으로 보고 멈춘다. 멈춤(Abort)은 그대로 멈춘다.
- **배포 뒤 점검(Claude 절차 — 조회만)**: 게시 흐름을 바꾸는 PR을 병합하면 Claude가 ① Vercel 운영 배포가 그 커밋 SHA로 READY인지
  ② 최근 24시간 런타임 오류(특히 `/api/admin/literature`·`/api/admin/art-books`) ③ 운영 DB 정본 행 상태를 실측해 보고한다.
  운영 DB는 아래 조회만 쓴다(쓰기는 오너 승인 범위 안에서 따로). 첫 실측(2026-10-16)이 P0-3 이전 공개 15장(AOZORA-P1-11)과
  준비 뒤 빠진 경계 기록 40장(AOZORA-P1-12)을 잡았다.

-- 정본 책 단계 실측(작품별 장 · 분석 · 검수 기록 · 공개 · 경계 기록 실린 장)

### 4.2c 「공개」의 뜻 — 목록은 누구나, 본문은 로그인 뒤 (오너 「권장대로 진행」 2026-10-16 KST, BOOK-GUEST-GATE-1)

- 책 장은 관리자 소유 행 하나를 모든 독자가 같이 읽는다(사본 아님 — 분석은 책당 한 번, 교정·재분석은 모두에게 반영).
  독자 각자의 것은 저장 단어·FSRS·읽은 기록·책갈피뿐이다.
- 비로그인(anon)은 **책 목록만** 본다. 책 = `processed_json.metadata.book.key`가 있는 자료 전부(정본 문학·그림책·사용자가
  공개한 책). 낱개 공개 글은 그대로 열린다.
- 막는 자리는 DB다 — anon SELECT 제한 정책 `anon_book_chapters_hidden` + 메타만 주는 `public_book_catalog(p_id)`
  (`supabase/migrations/20261016150000_anon_book_catalog.sql`, 실제 PostgreSQL 검증 `supabase/tests/anon-book-catalog.mjs`).
  화면만 막으면 목록 조회가 내려받는 분석 전체로 본문이 보인다.
- 화면: 「함께 읽는 글」 책 카드에 「로그인하고 읽기」(로그인 후 첫 장), 뷰어에서 책 장을 열면 「로그인이 필요해요」(로그인 후 같은 장).

- 팀 화면(수업 암호가 열쇠 — 로그인 없이 열린다)은 그대로 쓰되 **정본 책(青空文庫 · Standard Ebooks · 위키문헌 · 전자책 사이트 · 그림 큐레이션)은 내주지
  않는다**(오너 「팀 화면 접근은 가능해도 정본 책 접근은 못하도록」 2026-10-16 KST): 팀 목차 · 장 열기 · 출처 · 사본 만들기가 같은
  판정 `isProtectedBookMetadata`(`src/lib/server/classIndex.js`)를 쓴다. 사용자가 만든 책으로 여는 수업은 무변경.

### 9.2 카탈로그 규칙 (`scripts/lib/literature-catalog.mjs`)

  고른다(주제 · 시대 아님). 큰 갈래(`CATALOG_GROUPS`) 셋 › 작은 갈래(`CATALOG_CATEGORIES`) 아홉, 줄에는 작은 갈래 key 하나(큰 갈래는 거기서 나온다 —

2. `node scripts/literature/import.mjs <id>` — 권리 · 표지 검사 → 받기(판 고정 · 해시) → entry.json → 빌드 → 장 점검. 멈추면 그 줄이 무엇을 고칠지 말한다.
3. `node scripts/literature/inspect.mjs <key>`(장 목록 · 분량) · `--chapter N`(장 전체)로 눈으로 한 번 → `npm test` → PR.
4. 병합 뒤 관리자 화면 「준비 안 된 N편 모두 게시·분석」 → 묶음 검수 → 공개(§4).
