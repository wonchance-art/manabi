# N3 교재 제작·앱 연결

사용자 직접 발주: “N3도 만들어 ㄱㄱ 풀가동”. 직전 N4의 집필·독립 검수·웹 교재·앱 연결·발행 방식을 이어간다. 기준 main은 `12b69920f3ae8d6cfb529296da5ddfac6bbb88ac`, 작업 브랜치는 `codex/n3-textbook-production-20261021`이다.

## 사용자 결과와 범위

N4를 이수한 한국어 사용자에게 문장 간 인과·조건·근거·태도·시간 관계를 구별하고 긴 글의 정보를 이용해 말하거나 쓰는 N3 교재를 제공한다. 48과, 주요 신규 문형 최대 2개/과, 마지막 과 신규 문형 0, 8과마다 3문항의 누적 복습 6세트를 설계 기준으로 삼는다. 내부 문형 목록과 교육과정 배정은 공식 JLPT 전체 출제 범위 인증이 아니다. 내부 N3 bunkei의 설명상 195개와 실제 배열 165개의 차이는 기존 자료를 수정하지 않고 출처 원장에 기록한다.

N4의 작은 장면 → 어휘 → 문형 설명·예문 → 대화 → 말하기 → 독해·확인 → 내 문장 흐름과 시각 규격을 계승한다. N3의 어휘·문형·대화·독해는 새로 집필한다. 원고의 원문과 읽기 보조, 실제 음성과 대본 확인, 회수 계획과 실제 회수 근거를 구분한다. 새 PDF·음성은 범위에 포함하지 않는다.

## 파일과 분담

- 교육과정 담당: `src/content/textbookManuscripts/japanese-n3/book.json`, `syllabus.json`; 선수·연결·범위 원장과 대표 과 의미 감수.
- 집필 A/B/C: 같은 경로의 `lessons/u01.json`–`u16.json`, `u17.json`–`u32.json`, `u33.json`–`u48.json`. 작성자와 다른 담당자가 교차 감수한다.
- 제작 도구 담당: `scripts/textbooks/`의 N3 빌더·검증기·패키저·런타임·스타일·폰트 도구와 신규 계약 검사. 기존 N4 제작 도구는 변경하지 않는다.
- 앱 담당: 책 레지스트리·서버/출처/복습 계약·서가/읽기/관리 화면, N3 sibling 페이지/API, 폰트/스타일 스코프와 서버 파일 추적, 신규 N3 계약 검사.
- M00: 대표 과 수락, 범위/용법 검토와 전체 통합, 필요한 N3 판본 등록·검수 근거, 보존 검증, CI/PR·발행·배포와 실제 결과 기록. N3 지원 요구와 직접 충돌하는 기존 검사의 N3 미지원 기대만 사실에 맞게 갱신한다. 미지원 교재 거절 검사는 N2로 옮겨 유지하고 기존 N5/N4 회귀나 권한 검사를 약화하지 않는다.

전체 검사에서 새 N3 관리자 페이지가 계정 전환 시 서버 렌더를 비우는 보호 목록에 누락된 사실을 확인했다. `accountRouterRefresh.test.jsx`의 명시적 경로 목록에 N3 관리자 경로와 보호 이유 한 줄을 추가했다. 자동 발견과 목록의 정확한 일치, 계정 변경 시 캐시 폐기 검사는 그대로 유지한다.

배포와 DB 쓰기는 M00만 수행한다. N3의 비파괴 책 ID 호환 확장이 필요하면 정확한 기존 제약·함수와 권한을 먼저 확인하고 격리 PostgreSQL의 거절·보존 시나리오를 검증한다. N5/N4 원고·판본·공개 포인터·학습 기록·소유권은 보존한다. 시크릿/환경 파일은 읽거나 출력하지 않는다. 월드와 다른 담당 작업은 변경하지 않는다.

## 수락 순서

1. 48과 교육과정과 JSON 작성 계약을 고정한다. 대표 u01의 설명·용법·역할·시점·문항 정답/대안·읽기를 작성자와 다른 담당자가 검토하고 실제 생성 화면을 확인한 뒤 전권 집필을 진행한다.
2. 전48과와 18개 누적 문항을 교차 감수한다. 근거 인용·오답 제약·허용 대안을 남기고 같은 문형의 새 사례를 검토한다. 자동 구조 검사나 일부 표본을 전체 언어 품질 인증으로 확대하지 않는다.
3. 정확한 원고·도구·폰트·출력 자산을 해시로 묶고 두 번 생성의 동일성을 확인한다. 생성만 한 후보의 QA를 통과 처리하지 않으며 검수 영수증을 후보 판본에 결합한다.
4. 전 과/구간·좁은 폭·후리가나·기본 글리프·답안/검색/재로드/판본 분리를 실제 Chromium에서 확인한다. 앱에서는 책장 → 읽기 → 표현 저장 → 복습 → 같은 책/판본/원문 복귀와 교재 간 오인·위조·비로그인/타 소유자 거절을 검증한다.
5. 전체 lint·필수 Vitest·원격 CI, 프로덕션 빌드와 서버 파일 추적을 확인한다. 검증한 정확한 head만 PR/병합 대상으로 삼는다. 이미 같은 입력으로 통과한 근거는 재사용하고 변경·실패 범위만 다시 확인한다.
6. 관리 DB 초기 등록은 실제 계정 로그인 검수와 구분한다. 정상 계정 인증이 없으면 미검증으로 명시하고 세션/JWT를 조작하지 않는다. 발행과 운영 배포 식별자·원문/폰트 해시·공개 포인터·N5/N4 보존·복원 기준을 실제로 확인한다.

이 문서는 착수 설계이며 완료 보고가 아니다. 실행 근거와 미확인 항목은 판본별 검수 자료 및 최종 결과에 기록한다.

## 재생성

최종 판본의 도구·Noto CJK 원본 글꼴·라이선스·fontTools 버전은 `manuscript.templates`에 해시로 기록한다. 검수 환경은 Node 24와 fontTools 4.61.1, `/usr/share/fonts/opentype/noto`의 원본 TTC 세 개를 사용했다. 다른 경로의 체크아웃에서는 빈 출력 디렉터리를 명시한다.

```bash
node scripts/textbooks/build-n3-web.mjs --source src/content/textbookManuscripts/japanese-n3 --out "$PWD/tmp/n3-web"
node scripts/textbooks/validate-n3-web.mjs --out "$PWD/tmp/n3-web"
```

생성 후보의 QA는 false다. 실제 독립 언어·브라우저 검수를 수행하고 정확한 후보의 세 해시와 증거 파일 SHA를 영수증에 결속한 뒤에만 `package-n3-release.mjs`를 사용한다. 기존 판본 디렉터리는 덮어쓰지 않는다. 기록된 원본 글꼴이나 도구 버전이 달라지면 같은 판본이 재생성된 것으로 취급하지 않는다.
