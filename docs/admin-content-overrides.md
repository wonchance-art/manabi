# 관리자 웹 교재 편집

교재 원본은 `src/content/**`에 두고, 관리자 수정본만 기존 Supabase `content_overrides`에 저장한다. 현재 저장은 **공개 교재에 즉시 반영**된다. 비공개 초안·출판 이력 기능은 별도 설계 단계다.

## 편집 진입

- `/admin` → 콘텐츠 → **교재 편집 열기**.
- `/lessons` → 관리자 계정에서 **관리자 교재 편집**.
- 챕터 하단 → **챕터 전체 편집**.
- 직접 주소: `/admin/textbooks?lang=Japanese&slug=<chapter-slug>`.

언어, 레벨, 챕터를 선택하고 제목·학습 안내·본문·예문·대화·표·읽기·연습 내용을 폼으로 고친다. 내용 미리보기 후 변경 저장을 누른다. 미리보기는 내용을 확인하는 화면이며, 실제 교재의 배치는 교재 페이지에서 확인한다.

이번 편집기는 기존 구조의 내용 수정에 집중한다. 배열 추가·삭제·재배치와 출처/문항 ID 편집은 제공하지 않는다. 정답이 보기 인덱스인 문항은 선택 상자로 변경한다. 다른 숫자·형식 메타데이터는 보존한다. 신규 미디어 업로드나 링크 교체는 별도 관리 기능이다.

기존 문장 옆 연필 편집도 유지한다. 예문의 출처 객체를 문자열 입력으로 바꾸지 않도록 텍스트 필드만 폼에 노출한다.

## 저장·충돌 처리

- GET `/api/admin/chapter?lang=&slug=` → `{ base, override, merged, updatedAt }`.
- GET은 `private, no-store`. DB 조회 실패를 수정본 없음으로 취급하지 않고 503을 반환한다.
- POST `{ lang, slug, data, expectedUpdatedAt }`.
- 최초 저장은 `expectedUpdatedAt: null`로 INSERT. 같은 챕터가 먼저 저장됐으면 PK 충돌로 409.
- 수정은 조회 시 받은 `updatedAt` 그대로 UPDATE 조건에 사용한다. 다른 탭에서 먼저 수정했거나 복원해 행이 없어졌으면 409. 새 서버 버전을 성공 응답으로 돌려준다.
- 버전 없는 구형 저장 요청은 428로 편집 화면 재열기를 요구한다.
- 전체 편집기는 충돌/실패 시 입력을 유지한다. 최신 내용을 불러올 때는 미저장 변경을 버릴지 확인한다.
- 인라인 편집은 저장 직전 최신 원고를 다시 읽고, 편집 중인 값이 바뀌었으면 저장을 멈춘다. 다른 필드 변경은 최신 원고 위에 패치하며 최종 쓰기에도 버전 조건을 사용한다.
- DELETE `{ lang, slug }`는 기존 복원 동작이다. 관리자 화면의 확인을 거쳐 수정본을 삭제한다. 이력 버전 복원과는 다르다.

## 인증과 병합

서버 페이지와 API 모두 `requireAdmin()`으로 서버에서 확인한 사용자 및 `profiles.role = admin`을 검사한다. 쓰기는 사용자 세션 클라이언트를 사용하며 RLS가 최종 권한을 검사한다. 서비스 역할 키는 사용하지 않는다.

원고는 얕게 병합한다. `slug`, `level`, `order`는 원본 값으로 고정한다. 저장 구조 검증과 기존 story 문항 ID 보존 검사를 거친다. 챕터 제목은 비울 수 없다.

저장 후 해당 챕터 경로, `/lessons`, `/review/grammar`를 재검증하고 편집 화면의 클라이언트 라우터 캐시도 갱신한다. 공개 교재 렌더는 기존 실패 안전 동작으로 DB를 읽지 못하면 정적 원본을 표시한다. 관리자 편집 GET의 실패 처리는 이 공개 읽기 동작과 구분한다.

교재 본문·메타데이터·이전/다음 제목, 패턴 체크의 다른 챕터 보기 풀, 누적 복습, 문법 복습과 공부 모드는 `publishedChapter.js`의 공통 조회를 사용한다. 요청 안에서 같은 언어의 수정본 맵을 재사용한다. 이미 진행 중인 복습은 시작 때 받은 문항을 유지하며, 새로 시작하는 세션에서 최신 수정본을 읽는다.

## 검증과 현재 경계

2026-09-05 연결된 Manabi 프로젝트에서 테이블 컬럼과 RLS를 읽기 전용으로 확인했다. SELECT는 공개, INSERT/UPDATE/DELETE는 `is_admin()` 조건이다. 운영 데이터의 쓰기·스키마 변경은 수행하지 않았다.

로컬 검증: API 권한·저장 충돌·수정본 구조·출처 보존 관련 72개 테스트와 변경한 JS/JSX 10개 파일의 린트가 통과했다. 실제 편집 컴포넌트를 격리한 브라우저에서 밝음/어두움 × 5개 화면 폭(320~1024px), 미리보기, 저장 후 새로고침, 실패·충돌 시 입력 유지, 언어 전환, 비관리자 접근을 확인했다. 브라우저 인증·저장 응답은 메모리 모형이며 운영 저장 검증은 아니다. 저장소의 iCloud 미다운로드 의존성 때문에 전체 앱 빌드는 완료하지 못했고, 임시 디렉터리에 격리한 Node 22 도구로 검증했다. 배포는 수행하지 않았다.

웹 저장은 전체 콘텐츠 린터를 실행하지 않는다. 표기·레벨·한자 예외·시험 범위 검토는 편집자가 계속 확인해야 한다. 파일 정본화 시 `scripts/check-content.mjs` 등 기존 검증을 거친다. 비공개 초안·발행 검증은 [통합 설계](./rfc-textbook-review-materials.md)의 후속 단계다.

2차에서 `/review/grammar`와 공부 모드의 교재 문제까지 수정본 조회를 연결했다. 관련 190개 테스트와 실제 컴포넌트를 사용하는 격리 브라우저 검증이 통과했다. 운영 인증·저장·음성 재생은 모형으로 대체했고 전체 앱 빌드·배포는 수행하지 않았다.

PDF 자동 생성과 TTS 제작은 후속 구현 범위다. 개인 자료와의 출처 연결은 3차 구현에 포함했다. 저장된 교재 수정본이 이 기능들까지 이미 전파된다고 가정하지 않는다.

최신 운영 코드와의 통합 및 배포 검증은 [배포 기록](textbook-release-verification.md)을 따른다. 위 단계별 검증은 당시 결과이며 최신 전체 검증과 구분한다.
