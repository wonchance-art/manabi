# 단어 페이지 오프라인 채점 (OFFLINE-GRADE-001) — 보류 메모

- 상태: **보류** — 오너 2026-10-31 KST 「일단 내용 저장만 해둬」. 착수 전 오너 확인.
- 배경: 단어 페이지 FSRS 채점은 카드당 요청 1회(GRADE-ONE-REQUEST-001, #1615)다. 운영 실측(10-31, 15회):
  서버 처리(묻기 → 채점 반영) 중앙 0.16 s · 상위 10% 0.19 s, 사용자 생각 시간 중앙 7 s — 낙관 갱신이라 대기가 없다.
  빈틈은 연결이 끊긴 때뿐이다: `answer`는 보낼함에 넣지 않아 실패로 끝나고 기기에도 남지 않는다.
- 묶음 · 로컬 우선(Anki식) 전환은 배제: 서버가 일정 정본 · 여러 기기 · 하루 새 단어 몫을 서버가 센다 — 묶음은 탭 닫힘 유실 · 기기 간
  어긋남 · 되돌리기 · 몫 처리 비용이 크고, 대기 0이라 얻는 것이 없다.

## 1단계 — DB 변경 없음(권장안)
- 연결 실패한 채점을 이 기기(IndexedDB 보낼함)에 보관 → 연결되면 누른 순서대로 전송. 탭 ID(operationId)로 멱등(두 번 반영 없음).
- 화면: 실패 토스트 대신 한 줄 「오프라인 — 연결되면 보내요 (N개 대기)」, 다음 카드는 그대로.
- 한계: 서버는 **받은 시각**으로 채점한다 — 몇 시간 늦음은 영향 미미, 며칠 쌓이면 다음 간격이 조금 길어진다.
  오프라인 중에는 새 단어 몫을 확인할 수 없어 **새 단어는 내지 않고** 이미 차례인 복습만 이어 간다.
- 재사용: `fsrsOperationOutbox`(보낼함) · `createFsrsLearningClient().answer` · `levelFsrsGrade` 직렬 줄.

## 2단계 — 정확한 시각(DB 변경 · 별도 승인)
- 서버가 기기의 누른 시각을 받아 그 시각으로 일정을 계산 — 경계 조건(예: 72시간 안 · 미래 금지 · 순서 일치).
- 「시각은 서버가 정한다」 원칙을 바꾸는 일이라 운영 DB 함수 수정이 필요하다. 1단계 사용 뒤 오프라인 학습이 잦으면 오너에게 다시 묻는다.
