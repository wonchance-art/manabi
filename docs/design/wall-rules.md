# 화면 벽 판정 규칙 (정본)

화면 벽은 앱의 모든 화면을 장면 단위로 찍어 펼쳐 두고, AI가 1차로 판정한 뒤 오너는 의도와 취향만 판단하는 판이다.
이 문서는 그 판정 규칙의 **정본**이다. Claude(화면 벽 루틴 · 검수)와 ChatGPT/Codex(구현 · PR 리뷰)가 같은 규칙을 따른다.

- 승인: 오너 2026-10-12 KST — 화면 벽 설계 D-W1~16, D-W14(AI 자동 승인 범위) · D-W15(PR 코멘트 수정 요청) 상시 승인,
  D-X1(이 폴더) · D-X2(교차 모델 판정).
- 설계 문서: 화면 벽 설계 2판(아티팩트), 인계 #1337 WALL-001 · WALL-002 · WALL-003, 기록 #1077.
- 바꾸는 법: 설계 세션이 이 파일을 PR로 고치고 오너가 승인한다. 다른 세션은 #1337 · #1077에 제안만 한다.
- 시각은 모두 KST로 적는다.

## 1. 장면과 기준

- **장면** = 경로 × 사람(합성 학습자) × 상태 × 조작 순서. 화면 크기는 휴대폰 390 · 데스크톱 1280 두 가지다.
- **비교 기준(승인본)** = 오너 또는 AI가 승인한 마지막 캡처다. 직전 빌드와 비교하지 않는다 — 한 번 뜬 변화가 다음
  갱신에서 기준이 되어 묻히기 때문이다(D-W1).
- 승인 전까지 그 장면은 검수 줄에 남는다. PR 단계에서 승인된 장면은 병합되면 그대로 기준이 된다.
  승인 없이 main에 생긴 변화는 「예상 밖 변화」로 남는다.
- **신호 세 겹:** 그림(픽셀 차이, 안티에일리어싱 잡음은 문턱으로 거름) · 문구(본문 글자 해시와 자체 LCS 차이) ·
  배치(주요 요소 상자 해시). 한 갱신에서 장면의 40%를 넘게 같은 종류의 변화가 덮으면 「전역 변화」 묶음 하나로 판정한다
  (대표 3장).
- 원본 글꼴이 로드되지 않은 장면 · 캡처에 실패한 장면 · 합성 데이터가 없어 오류 화면이 찍힌 장면은 **판정하지 않는다**(§4).

## 2. 두 질문을 나눈다

| 질문 | 대조 대상 | 보는 때 |
|---|---|---|
| ① 의도대로 만들어졌나 | [설계 등록부](registry.json)의 목업 프레임 · 인계문 수용 기준 · 인계문 문구 | PR |
| ② 의도치 않게 바뀌었나 | 승인본 | PR · main |

판정마다 근거(규칙 · 목업 프레임 · 인계 링크 · 증거 이미지)를 남긴다.

이미 병합된 설계(등록부 단계 「병합됨 · 목업 대비 확인 대기」)는 PR을 다시 열지 않는다. 다음 main 캡처에서 ①을 한 번
판정하고, 다르면 #1337에 보고한다.

## 3. 객관 검사 (규약 위반)

아래는 취향과 무관한 위반이다. 하나라도 걸리면 **수정 요청**이다. 기준값은 [`../ui-conventions.md`](../ui-conventions.md)가 정본이고,
여기 값은 그 사본이다. 어긋나면 ui-conventions를 따른다.

| 검사 | 위반 조건 | 측정 |
|---|---|---|
| 가로 넘침 | 문서 `scrollWidth` > 창 너비 | 화면 크기마다 |
| 대비 AA | 일반 글자 4.5:1 미만, 큰 글자(24px 이상 또는 18.66px 이상 굵게) 3:1 미만 | axe `color-contrast` |
| 터치 타깃 | 화면에 **실제로 보이는** 글자 없는 버튼 · 링크가 44×44px 미만 | 보이는 요소만 센다(접힌 메뉴 속 버튼 제외) |
| 대체 글꼴 | 원본 글꼴(Noto Sans KR 등 next/font 변수 전체)이 로드되지 않음 | `document.fonts` |
| 오류 원문 노출 | 서버 · 런타임 오류의 영어 원문이 사용자에게 보임 | 정규식(Server Components render · Application error · TypeError 등) |
| 값 누락 노출 | `undefined` · `null` · `NaN` · `[object Object]` · 치환되지 않은 `{{…}}` · `%s`가 화면 글자에 보임 | 화면 글자 정규식(낱말 경계). 저장소에 번역 키 체계가 없어 「키 노출」 대신 이것을 잰다 |
| 이름 없는 조작 | 이름 없는 버튼 · 링크 | axe `button-name` · `link-name` |
| 깨진 이미지 | 로드 실패 이미지 · 대체 글 없음 | `naturalWidth` 0 · axe `image-alt` |

1판 캡처(2026-10-12)는 값 누락 노출과 이미지 로드 실패(`naturalWidth`)를 아직 재지 않았고, 터치 타깃은 보이지 않는 버튼까지 셌다.
2판 캡처(#1337 WALL-002 · WALL-003)에서 이 표대로 맞춘다.

## 4. 판정 표

| 상황 | AI 판정 | 다음 동작 |
|---|---|---|
| 설계 등록부에 「바뀔 화면」으로 올라 있고, 목업 · 수용 기준과 맞고, §3 위반이 0이며, §5 교차 모델 조건을 만족 | **자동 승인** | 기록만. 주 1회 표본으로 오너에게 보인다(§8) |
| §3 위반 | **수정 요청** | 그 PR에 리뷰 코멘트(§7 형식). main이면 #1337 보고 |
| 목업과 다름: 배치 · 위계 · 빠진 요소 · 문구가 인계문과 다름 | **수정 요청** | PR 코멘트(목업 프레임과 나란히). 해석이 갈리면 오너에게 |
| 설계에 없는 화면이 바뀜(예상 밖 변화) | **질문** | PR에 「이 화면이 바뀐 이유」를 묻는 코멘트. 의도된 변화라고 답하면 오너에게 |
| 공용 부품 변화로 여러 화면에 같은 변화 | 부품 판에서 한 번 판정 | 설계된 토큰 · 부품 변경이면 자동 승인(§5 조건 적용), 아니면 오너에게(대표 3장) |
| 설계 없는 새 화면 · 설계 없는 디자인 변화 | **오너에게** | 판단 필요 알림 |
| §6 자동 승인 금지 목록 | **오너에게** | 자동 승인하지 않는다 |
| 「목업과 일치」로 보이지만 §5 교차 판정을 할 수 없음 | **오너에게** | 판단 필요로 올린다(표본으로 미루지 않는다) |
| 데이터 필요 · 캡처 실패 · 글꼴 실패 | **판정 안 함** | 개발 세션에 보완 요청(같은 사유는 한 번만) |

AI 판정은 그림 · 문구 · 규약 기준이다. 사용성 · 취향 · 브랜드 감각은 오너 판단으로 남긴다.

## 5. 자동 승인 조건 — 교차 모델 (D-X2)

「목업과 일치」로 자동 승인하려면 **구현한 모델과 판정하는 모델이 달라야 한다.**
AGENTS.md 공통 품질 실행 원칙의 「같은 모델의 자기 승인만으로 완료하지 않는다」를 화면 벽에 적용한 것이다.

| 구현 | 판정 | 자동 승인 |
|---|---|---|
| Codex/ChatGPT PR (`codex*/*`) | Claude(화면 벽 루틴) | 가능 |
| Claude PR (`claude/*`) | ChatGPT/Codex(PR 리뷰) | 가능 |
| 교차 판정자가 없음(같은 모델만 판정 가능) | — | **불가.** §3 객관 검사는 자동으로 처리하고, 「목업과 일치」는 **오너에게**(§4) 올린다 |

- 구현 모델은 PR 브랜치 네임스페이스로 정한다. 한 PR에 두 모델의 커밋이 섞이면 어느 쪽도 교차 판정자가 될 수 없다(자동 승인 불가).
- 같은 모델의 다른 세션은 교차 판정자가 아니다(AGENTS.md 문구가 「같은 모델」이다).
- **교차 판정 경로(2026-10-12 KST 연결, D-X4):** ChatGPT Codex 코드 리뷰가 이 저장소에 연결돼 있다. **자동 리뷰는 끄고**
  필요한 PR에만 `@codex review`로 부른다(모든 PR을 리뷰하면 리뷰 한도가 문서 PR에 쓰인다).
  - 화면 벽 루틴은 화면이 바뀌는 `claude/*` PR에만 `@codex review`를 단다. 요청 문구에 「`docs/design/wall-rules.md` §4 · §7과
    `docs/design/registry.json`의 목업 경로로 판정」을 붙인다.
  - Codex 리뷰는 **코드 diff를 읽는 리뷰**다(캡처를 보지 않는다). 그래서 Codex가 맡는 것은 「바뀐 코드 · 문구가 인계문 · 목업 원본과
    맞나」이고, 그림 대조는 화면 벽 루틴(Claude)이 맡는다. 두 결과가 모두 「일치」일 때만 자동 승인한다.
  - 리뷰 한도가 바닥나거나 Codex가 응답하지 않으면(24시간) 「목업과 일치」는 **오너에게** 간다. 크레딧은 사지 않는다(실화폐 금지).
  - **보안 리뷰는 쓰지 않는다:** 저장소가 공개라 `@codex security review` 결과가 수정 전에 공개된다. 보안 점검은 비공개
    절차를 따른다(#1337 SEC-PRIVATE-001).
- 판정 코멘트에는 판정한 쪽을 적는다(§7 `판정` 줄).
- §3 객관 검사의 수정 요청은 어느 모델이 판정해도 된다 — 측정값이 근거라 자기 승인 문제가 없다.

## 6. 자동 승인 금지 목록

아래는 어떤 조건에서도 자동 승인하지 않고 오너에게 올린다. 판정은 저장소 코드가 아니라 루틴이 하므로, 루틴은 판정 기록에서
이 유형에 「자동 승인」 값을 쓰지 못하게 스스로 검사한다. 주 1회 표본에 이 유형이 섞여 있으면 그 자체가 결함이다.

1. 설계 등록부에 없는 새 화면
2. 설계 없는 디자인 변화(색 · 글꼴 · 간격 · 배치가 등록된 설계 밖에서 바뀜)
3. 인계문과 글자까지 같지 않은 문구
4. 한국어가 아닌 **화면 안내 문구**(简体 · 繁體 화면 등) — 원어민 검수 여부를 함께 표시한다. 학습 본문 · 예문 · 표제어 같은
   학습 내용의 외국어는 여기에 들지 않는다
5. 브랜드 · IP 관련 — 로고 · 엠블럼 · 국기 같은 이미지 자산, 실존 브랜드 서술([`../policy-brand-content.md`](../policy-brand-content.md))

## 7. PR 코멘트 형식

코멘트는 **그것만 읽고 고칠 수 있게** 쓴다. Codex는 claude.ai 아티팩트를 열 수 없으므로 아티팩트 링크에 기대지 않는다.
캡처는 GitHub CI가 아니라 **Claude 화면 벽 루틴**이 찍는다(Actions 사용 시간 0). 그래서 증거는 이미지 파일이 아니라
**글로 된 근거**(선택자 · 측정값 · 기대 문구 · 목업과 다른 점)와 **재현 명령**으로 준다. 개발 세션은 저장소의 장면 목록 ·
캡처 스크립트로 같은 장면을 직접 찍어 확인한다(같은 빌드 · 같은 조건). 목업은 이 폴더의 경로로 가리킨다.

```markdown
### 화면 벽 판정 — <sha 앞 8자> (YYYY-MM-DD HH:MM KST)
판정: <Claude 화면 벽 루틴 | ChatGPT/Codex 리뷰> · 구현: <claude/* | codex*/*>

| 장면 | 화면 | 판정 | 규칙 | 증거 |
|---|---|---|---|---|
| study.e0 | 390 | 수정 요청 | §3 오류 원문 노출 | 본문에 「An error occurred in the Server Components render」 |
| home.p2 | 1280 | 수정 요청 | §4 목업과 다름 — 「오늘 복습」 칸이 빠짐 | `main .bento` 칸 3개(기대 4) ↔ docs/design/mocks/ak/ak.home.d.jpg |

**고칠 것**
1. <파일:행> — <무엇을 어떻게>. 측정값: <예: #796d70/#f8f2f2 4.48:1, 기준 4.5:1>
2. …

재현: `npm run e2e:build && npm run wall:capture -- --scenes <장면 id,…>` (출력 `wall-out/`)

자동 승인 <n> · 수정 요청 <n> · 질문 <n> · 오너에게 <n> · 판정 안 함 <n>
규칙: docs/design/wall-rules.md
```

- 새 커밋을 찍을 때 **판정이 바뀐 경우에만** 새 코멘트를 단다(코멘트 수정은 구독 세션을 깨우지 않는다). 바뀐 것이 없으면
  아무것도 달지 않는다. 고쳐진 줄은 다음 코멘트에 「해결」로 적는다.
- 오너에게 올린 장면은 PR 코멘트에 「오너 판단 대기」로만 적고, 판단 요청은 오너 알림으로 보낸다.

## 8. 보정 · 알림

- **주 1회 표본:** 지난주 자동 승인 중 무작위 **정확히 5건**을 오너에게 보인다.
- 오너가 번복하면 그 유형은 앞으로 「오너에게」로 옮긴다. **번복률이 10%를 넘으면** 자동 승인을 멈추고 전부 오너에게 올린 뒤
  이 규칙을 다시 짠다.
- 오너 알림은 판단 필요가 있을 때만 보낸다. 판단 필요가 0이면 알림이 없다(D-W16).
- 화면 벽 상단에 판단 필요 건수 · 자동 승인 번복률 · 수정 요청 반영까지 걸린 시간을 늘 보인다.
- 화면 벽이 48시간 넘게 갱신되지 않으면 화면 벽 페이지가 스스로 경고 띠를 띄운다(마지막 갱신 시각으로 페이지에서 계산).
  멈춘 루틴은 자기 정지를 보고하지 못하므로, #1337 보고는 루틴과 별개인 점검(하루 1회)이 한다.

## 9. 보존

- 캡처 이미지: 화면 벽 루틴이 찍어 화면 벽 저장소(아티팩트 자산)에 둔다. 승인본은 장면마다 마지막 1장, 판정 대기 캡처는
  판정이 끝나면 지운다. 보관 공간이 한도(1GiB)의 절반을 넘거나 30일 넘는 이력이 필요해지면 외부 보관소(예: Google Drive)를
  다시 검토한다(2026-10-12 오너 결정: 보류).
- 저장소에 기준 이미지를 커밋하지 않는다 — 저장소가 커지고, 기준이 오너 승인 없이 개발자 커밋으로 바뀐다.
  예외는 이 폴더의 목업 프레임이다(설계 확정본이지 캡처 기준이 아니다).
- 검수 이력(누가 · 언제 · 어느 SHA를 승인 · 문제 · 보류했는지)은 화면 벽 db에 남긴다.
