# 화면 문구 표준 (정본)

앱 화면에 나오는 안내 · 오류 · 토스트 · 확인창 · 빈 상태 · 로딩 · 메일 문구의 표준이다.
학습 본문 · 예문 · 표제어 · 뜻 같은 **학습 내용**과 학습 언어 텍스트는 이 표준의 대상이 아니다.

- 승인: 오너 2026-10-13 KST 「권장대로 승인, 넘겨」.
- 근거: 화면 벽 상태 · 알림 재고 [`states-inventory.json`](states-inventory.json)의 문구 묶음 — 같은 상황에 문구가
  여러 가지로 갈려 있었다(실패 끝맺음 5가지, 다시 시도 버튼 5가지, 「복습할 것 없음」 4가지 이상, 합니다/해요 혼재).
- 정한 값은 **가장 많이 쓰이던 형태**를 우선했다(예: 「…지 못했어요」 96곳, 「다시 시도」 59곳, 「잠시 후」 38곳).
  갈린 정도가 비슷하면 표준 표기를 따랐다(예: 말줄임표 「…」 25곳 대 「...」 28곳 → 「…」).
- 이 표준은 `.claude/commands/korean-copy.md`의 「~합니다/~세요 체」 안내를 대체한다.
- 화면에 오류 문구를 만드는 곳은 하나다: `src/lib/errorMessage.js`(`friendlyError` · `friendlyToastMessage`).
  새 오류 문구는 여기에 더하고, 화면마다 따로 짓지 않는다.
- 바꾸는 법: 설계 세션이 이 파일을 PR로 고친다. 다른 세션은 #1337 · #1077에 제안만 한다.

## 1. 말투

| 규칙 | 맞음 | 틀림 |
|---|---|---|
| 해요체로 쓴다 | 저장했어요 · 불러오지 못했어요 · 휴지통으로 옮길까요? | 저장되었습니다 · 실패했습니다 · 삭제하시겠습니까? |
| 부탁은 「…해 주세요」(띄어 쓴다) | 다시 시도해 주세요 · 다시 로그인해 주세요 | 다시 시도해주세요 · 로그인하세요 |
| 말줄임표는 「…」 한 글자 | 불러오는 중… | 불러오는 중... |
| 화면 문구에 영어 원문 · 코드 · HTTP 번호를 쓰지 않는다(오류 ID는 예외) | 문제가 발생했어요 · 오류 ID: 3023217680 | Failed to fetch · 500 · JSON parse error |

## 2. 상황별 문구

| 상황 | 표준 | 쓰지 않는 형태 |
|---|---|---|
| 불러오기 · 저장 · 분석 등 **실패** | 「〔무엇〕을 〔동작〕하지 못했어요.」 뒤에 필요하면 다음 행동 한 문장 — 예: 「목차를 불러오지 못했어요.」 「저장하지 못했어요. 입력은 이 기기에 보관돼 있어요.」 | 「저장 실패 — …」 「…에 실패했어요/했습니다」 「불러올 수 없어요/없습니다」 「못 받았어요」 |
| 규칙상 **할 수 없는 일** | 「…ㄹ 수 없어요」 — 예: 「줄을 넘어서는 묶을 수 없어요」 | (실패를 이 형태로 쓰지 않는다) |
| 원인을 모르는 오류(화면 전체) | 「문제가 발생했어요」 + 「잠시 후 다시 시도해 주세요.」 + 오류 ID | 오류 원문 · 「알 수 없는 오류」 |
| 다시 시도 버튼 | 「다시 시도」 — 같은 동작을 다시 할 때는 모두 이것 | 「다시 불러오기」 「다시 확인」 「다시 열기」 「다시 연결」 |
| 다른 동작으로 보내는 버튼 | 그 동작의 이름 — 「다시 로그인」 「홈으로」 「전체 보기」 | 「다시 시도」로 뭉뚱그리기 |
| 성공 토스트 | 「〔무엇〕을 〔동작〕했어요」 — 예: 「단어를 저장했어요」 「복습 3개를 저장했어요」 | 「저장!」 「저장됨」(토스트로) 「단어장에 저장」 |
| 되돌리기 버튼 | 「되돌리기」 | 「실행 취소」 「저장 취소」 |
| 상태 표시(버튼 · 칩 안) | 짧은 상태어 — 「저장됨」 「저장 중…」 | 문장 |
| 로딩 | 「〔무엇〕 불러오는 중…」 — 예: 「목차 불러오는 중…」 · 오래 걸리는 작업은 「〔동작〕하고 있어요…」 — 예: 「분석하고 있어요…」 | 「로딩 중...」(무엇인지 없음) · 스피너만 |
| 빈 상태 | 「아직 〔무엇〕이 없어요」 + 다음 행동 버튼 | 「데이터가 없습니다」 |
| 복습할 것 없음 | 「지금 복습할 〔단어 · 표현 · 문법〕이 없어요」 + 필요하면 다음 복습 안내 한 문장 | 「복습할 게 없어요 — 내일 다시 와요」 등 변형 |
| 연결 끊김 | 「인터넷 연결을 확인해 주세요」 + 보관 여부 한 문장 — 예: 「연결되면 자동으로 보내요.」 | 「네트워크 연결을 확인해주세요」 「인터넷 연결이 끊겼습니다」 |
| 로그인 필요 | 「로그인이 필요해요」 + 「로그인」 버튼 | 「로그인이 필요합니다」 「로그인하세요」 |
| 확인창 제목 | 질문 — 「〔무엇〕을 휴지통으로 옮길까요?」 | 「정말 삭제하시겠습니까?」 · 제목 없음 |
| 확인창 버튼 | 실제 동작 이름 + 「취소」 — 「휴지통으로」 · 「삭제」(영구 삭제일 때만) · 「취소」 | 휴지통 이동에 「삭제」 · 「확인」/「예」 |

## 3. 길이 · 구조

- 한 메시지는 **두 문장까지**. 첫 문장은 무슨 일이 있었는지, 둘째 문장은 사용자가 할 일이나 보존 여부.
- 보존 여부가 중요한 실패(입력 · 기록)는 반드시 적는다 — 「입력은 그대로 있어요」 「복습 기록은 남아 있어요」.
- 같은 화면에서 같은 상황은 같은 문구를 쓴다(화면 벽 「문구 묶음」이 다른 문구를 잡는다).

## 4. 지키는 방법

- **계약 테스트(문구 린트):** 화면 코드(`src/app` · `src/components` · `src/views`, 학습 내용 `src/content` 제외)의
  문자열에서 아래가 나오면 실패한다 — 「해주세요」(붙여 씀) · 「하시겠습니까」 · 「실패했습니다」 · 「로딩 중...」 ·
  「...」(세 점) · 「저장!」. 예외가 필요하면 파일과 사유를 테스트 안 허용 목록에 둔다.
- **화면 벽:** 상태 · 알림 재고와 「문구 묶음」 탭으로 갈린 문구를 찾는다. 이 표준과 다른 문구는 「수정 요청」으로 낸다
  (`wall-rules.md` §4 「목업과 다름: 문구」와 같은 취급).
