2. 설계 원칙

  1. 표현 하나(방향 · 문형별)에 기억 상태 하나. 범위는 「보기」일 뿐이다.어느 범위에서 풀든 같은 카드의 같은 일정이 갱신된다. R3에서 생기는 표현(산출) 상태 · 문형 상태도 「방향 하나 · 문형 하나에 상태 하나」로 같은 원칙을 따른다. 범위마다 점수를 따로 두지 않는다(Bunpro 덱 선례 채택, Pleco 별도 점수판 배제).
  2. 언어가 첫 번째 축이다. 언어 안에서는 섞는다.배움 화면 국기 칩으로 고른 언어가 곧 복습 언어다. 한 언어 안에서는 한 줄로 내야 간격이 넓어진다(Kornell 2009 — 큰 한 묶음이 작은 네 묶음보다 90% 학습자에게 유리했던 간격 연구). 다만 뜻이 비슷한 새 단어를 붙여 내면 서로 간섭한다(Tinkham 1993 · Waring 1997). 그래서 같은 과의 새 표현 · 헷갈리기 쉬운 쌍(たい/ほしい)은 줄 안에서 띄운다. 좁은 범위는 선택 사항이다.
  3. 범위 하나가 개수·시작·줄을 함께 정한다.화면마다 따로 세지 않는다. 같은 함수 하나(countReviewScope)가 배움 칸 · 국기 칩 · 복습방의 숫자를 낸다. 계약 테스트로 고정.
  4. 일정에 반영되는 「복습」과 반영 안 되는 「집중 연습」을 나눈다.시험 전 「5–10과 몽땅」처럼 기한 전 카드를 돌릴 때 일정이 망가지면 안 된다(Anki 미리보기 · Bunpro Cram · WaniKani Extra Study가 모두 같은 결론).
  5. 명시한 범위는 실패하면 닫힌다. 저장된 설정은 덮지 않는다.범위를 못 읽으면 「전체」로 새지 않고 빈 줄을 낸다. 지금 교재 범위 계약(bookReviewNavigation.test.js, n5 e2e)을 모든 범위로 넓힌다.
  6. 모든 복습에는 원문으로 돌아갈 길이 있다.카드·끝 화면·오늘 문단에서 출처 문장으로 돌아간다(LingQ · Readlang 선례).
  7. 결과는 그 결과가 증명하는 기억에만 기록한다.이해 · 산출 · 읽기 · 문형 · 연습은 서로 다른 것을 증명한다. 한 일정에 섞으면 일정이 무엇을 재는지 흐려진다. 아래 증거 모델이 정본이고 계약 테스트로 심는다.

3-2. 종류 축과 한 가지 카드 규격 — 단어 · 문장 · 문형

지금: 단어·예문은 user_vocabulary(뜻 떠올리기), 문형은 grammar_review(문법 과정의 과 단위, 과 끝 문제 정답률로 자동 채점)로 따로 돈다. N5 교재의 문형 표는 문형 복습과 연결이 없고, 「예문 담기」로 담은 문장은 단어와 똑같은 카드로 나온다.

바꾼다: 세 종류 모두 뒷면 규격이 같다(뜻 + 읽기 + 소리). 스스로 채점하는 카드는 모두 같은 버튼 넷(다시 / 어려움 / 알맞음 / 쉬움, 키 1–4), 자동 채점 문항(문형 빈칸 · 어순, R2)만 정답률로 등급을 매긴다. 다른 건 무엇을 묻느냐다. 한 복습방에서 섞여 나오고, 카드 위에 종류가 붙는다. 화면 이름은 단어 · 문장 · 문형.

3-3. 발음 — 답의 일부, 하나라도 못 하면 「다시」 (오너 결정 2026-10-10)

  • 뒷면 = 뜻 + 읽기 + 소리. 일본어는 한자 위 후리가나(ruby), 중국어는 성조 부호 병음, 영어 · 프랑스어는 소리 중심(IPA는 선택 표시). 가나만 있는 표현은 읽기 줄 없이 소리만.
  • 앞면에는 읽기를 내지 않는다. 한자어 · 중국어는 읽기를 떠올리는 것 자체가 학습이다.
  • 판정: 뜻 · 발음 중 하나라도 못 떠올리면 「다시」. 「어려움 · 알맞음 · 쉬움」은 둘 다 떠올렸을 때, 얼마나 쉽게 떠올렸는지로 고른다. 버튼 아래 고정 문구: 「뜻이나 발음 중 하나라도 막혔다면 다시」. 선이 분명해 자기 채점이 흔들리지 않는다(WaniKani: 뜻과 읽기를 둘 다 맞혀야 통과).
  • 발음 판정 대상. 읽기가 따로 있는 표현만 — 일본어 한자어(후리가나), 중국어(병음 · 성조 포함). 가나만 있는 단어 · 영어 · 프랑스어는 뜻으로만 판정한다(철자와 소리가 거의 같아 따로 떠올릴 것이 없다. 일본어 억양 데이터는 없음).
  • 버튼 넷이 전부(Anki와 같음). 「무엇을 놓쳤나」 같은 추가 질문은 두지 않는다. 틀린 직후 한 번 더 누르게 하면 대부분 건너뛰어 데이터도 듬성해진다. 발음 약점은 발음을 직접 묻는 활동 — 집중 연습의 리스닝(소리 → 뜻) · 오늘 문단의 쓰기 — 결과로 숙련 사다리에 자동으로 쌓인다(Anki에서 듣기 카드를 따로 두는 것과 같은 역할).
  • 대가. 읽기만 틀려도 간격이 처음부터 다시 시작돼 복습량이 늘 수 있다(특히 중국어 성조). 실사용에서 표현별 · 언어별 「다시」 비율을 보고 다시 판단한다.
  • 소리 규격. 세션 시작 버튼을 누를 때 오디오를 한 번 열어 두고(iOS 자동 재생 제한), 다음 카드 소리를 미리 받는다. 머리줄에 🔈/🔇 전환(기기별 기억, 대중교통 대비). 화면 읽기 프로그램 사용 중엔 자동 재생하지 않고 「뜻 · 읽기」를 글로 알린다. 음성을 쓸 수 없으면 ▷ 버튼을 숨기고 읽기 글만.
  • 「말해 보기」는 따라 말하기 연습이다. 자기 발음 오류는 스스로 못 듣기 때문에 채점 근거로 쓰지 않는다.
  • 읽기가 비어 있는 표현(R1): 뜻으로만 판정하고 발음 문구를 숨긴다. 자동 채우기는 R2.
  • 읽기 빈칸 채우기 · FSRS 화면 소리는 1판 그대로(kuromojin · pinyin-pro로 「자동」 표시와 함께 채우기, FsrsReviewSession.jsx에 듣기 추가).

③ 줄 만들기 — 두 엔진을 한 줄로

  • 합치기: 범위 안 FSRS 카드와 예전 일정 카드를 한 줄로 만든다. 「FSRS 카드가 하나라도 있으면 세션을 FSRS로 전환」(VocabPage.jsx:794)은 없앤다. 채점은 카드마다 원래 엔진으로 저장(기존 저장 경로 재사용).
  • 순서: 기한 지난 카드는 지금 기억 확률이 낮은 순(두 엔진 모두 스냅샷 기억 모델로 계산 — forecast.js와 같은 방식). 새 표현 · 학습 카드는 복습 3장마다 1장 끼운다. 같은 출처 단위(교재 과 = chapter_slug, 자료 = material_id, 덱 = source_ref)의 새 표현끼리는 최소 4장 띄운다.
  • 학습 카드 · 단계: 새 표현의 첫 등장은 채점 없는 「처음 보는 표현」 카드. FSRS 카드는 학습 단계(1분 · 10분)를 따른다. 예전 일정 카드는 분 단위 단계가 없으므로 같은 세션 안에서 3장 뒤 한 번 다시 묻는 세션 내 재질문(줄 메타데이터만, 일정 저장 없음 — FSRS의 nextQuestionAt과 같은 개념)으로 처리하고, 그 첫 채점부터 일정에 반영한다.
  • 세션 길이: 「5분 ≈ 20 · 50 · 전부」 = 서로 다른 카드 수(학습 단계 · 세션 내 재질문은 세지 않음, 새 표현 포함). 줄 앞에서부터 자른다.
  • 이어 하기: 세션 저장소에 {scopeKey, cardIds, index, startedAt}. 다시 열 때 다른 곳에서 이미 채점된 카드(마지막 채점 > startedAt)는 건너뛰고, 24시간이 지나면 버린다. 지금 메모리 안 이어 하기(VocabPage.jsx:1065)를 대체 · 재사용.
  • 밀린 복습 규칙: 기준 = 그 언어의 지난 14일 하루 평균 완료 복습 수(14일 기록이 없으면 20). 오늘 기한 지난 복습이 기준의 2배를 넘으면 그 언어 범위의 새 표현을 0으로(계정 한도는 차감하지 않음).
