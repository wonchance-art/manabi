# 설명판·개인 학습 후속 설계

2026-09-17 KST · 오너가 승인한 A → B → C 구현 기준. 검수 결과는 `verification/classroom-refinements-20260917.md`에 별도 기록한다.

기준: PR #1319 `bcce8f12f973df95906c3d963ee736d1c8746b92`. 앞선 개인 노트·계정 저장·전체/부분 복사 구현을 재사용한다. 사용자는 외출 중이므로 실계정 로그인과 실물 기기 검수는 귀가 후로 분리한다.

**결정 요약**

| 순서 | 목표 | 첫 결과물 |
|---|---|---|
| A | 예전 설명을 현재 수업에 빠르게 다시 사용 | 기간 탐색·100개 이후 조회·현재 수업을 유지하는 가져오기 |
| B | 내용이 많아져도 수업을 끊지 않음 | 재현 가능한 부하 검수·측정된 병목 수정·태블릿 동선 보완 |
| C | 학습자가 믿고 읽을 수 있는 언어 표시 | 검증 예제·독음/훈음/뜻/일본어 대조의 일관된 규칙 |

각 단계는 별도 검토 가능한 변경으로 완성한다. 실행 중인 판의 원본·좌표·학생 기록·개인 복습 일정을 보존한다. 완료된 기능을 다시 만드는 대신 조회·성능·표시의 빈틈을 메운다.

## 1. 확인된 현재 상태

- 지난 설명판 API는 날짜 내림차순으로 최대 100개를 가져온다. 검색창은 내려받은 100개만 부분 문자열로 검사한다. 오래된 날짜가 실제로 있어도 ‘없음’처럼 보일 수 있다.
- 정확히 100개인 경우에도 현재 응답의 `truncated`가 참이다. 추가 결과의 존재를 별도로 확인하지 않는다.
- 목록의 큰 날짜 버튼은 과거 수업 날짜로 이동하고, 옆의 작은 ‘가져오기’가 현재 수업에 복사하는 기능이다. 재사용 중 의도치 않게 수업 날짜를 바꿀 여지가 있다.
- 페이지/부분 복사, 출처 보존, 중복 안내, 한 번 undo/redo, 서버 저장·복구는 이미 구현돼 있다.
- 과거 판을 선택하면 `readCloudBoard`가 해당 판의 페이지들을 순서대로 전부 내려받는다. 썸네일 그리기는 이미 IntersectionObserver로 지연한다. 새 지연 로딩 기능이 전혀 없는 상태로 취급하지 않는다.
- 판 한도는 20페이지, 페이지당 5,000요소, 문서 6MiB다. 표현 1개도 본문·독음·훈음·뜻 등 여러 요소를 쓰므로 표현 수와 요소 수를 따로 측정해야 한다.
- 카메라 변화도 기기 저장 흐름에 들어간다. 저장 내용 비교는 문서 정규화·직렬화를 수행한다. 이는 측정할 후보이며 아직 실측된 성능 결함이라고 단정하지 않는다.
- DOM 미리보기와 캔버스 표현은 같은 `teachingWordLayout`을 사용한다. 표시 토글 때 필기 위치를 보존하는 검사도 이미 있다.
- 뷰어의 일본어 대조는 글자 변환과 뜻 대응을 이미 구분한다. 이 규칙을 없애거나 단순한 한자 치환으로 대체하지 않는다.

## 2. A — 지난 설명판 탐색

**학습 동선**

현재 수업 → 지난 설명판 → 날짜/기간 선택 → 페이지 살펴보기 → 전체 또는 일부 선택 → 현재 판에 놓기 → 설명 계속하기.

별도 과거 수업 편집은 ‘그날 수업 열기’를 명시적으로 선택할 때만 수행한다. 날짜 목록에서 행을 누르는 기본 동작은 미리보기다. 학생에게 남기는 것은 기존 ‘수업에 남기기’를 계속 사용한다.

**목록 텍스트 목업**

```text
지난 설명판                         [닫기]
현재 수업 · 2026.09.17

[전체 기간 ▾]                      [새로고침]

2026년 9월
  9.16 수요일                 3쪽      ›
  9.10 목요일                 5쪽      ›

2026년 8월
  8.28 금요일                 2쪽      ›

              [이전 수업 더 보기]
```

목업 날짜·쪽수는 예시다. 본문에는 날짜와 페이지 수만 먼저 보여준다. 실제 저장되지 않은 교재명이나 내용 요약을 추측해서 붙이지 않는다.

기간 메뉴: 전체 기간(기본) / 이번 달 / 지난달 / 기간 지정. 기간 지정에서만 시작일·종료일과 적용 버튼을 보여준다. 입력 중에는 목록을 바꾸지 않고 적용 후 조회한다. 잘못된 날짜·역전 범위는 입력 옆에서 안내한다. 수업일은 저장된 날짜 그대로 쓰고, ‘이번 달’ 계산은 서비스 기준 KST를 따른다.

**날짜를 누른 뒤**

```text
[← 날짜 목록]                 2026.09.10
9월 17일 수업에 가져올 설명을 골라 주세요.

[1쪽 미리보기]     [2쪽 미리보기]
[전체 선택 □]     [전체 선택 □]
[부분 고르기]     [부분 고르기]

                    [선택한 페이지 가져오기]
그날 수업 열기 ↗
```

기존 미리보기·부분 선택 UI를 재사용한다. 부분 고르기에서는 현재 판/새 페이지 선택과 한 번 실행 취소를 유지한다. 가져오기 완료 후 현재 수업의 삽입된 요소를 선택해 즉시 옮길 수 있게 한다. 복사로 source day나 viewer URL을 변경하지 않는다.

같은 수업 날짜는 ‘현재 수업’으로 표시하고 재사용 진입을 비활성화한다. ‘그날 수업 열기’는 별도 버튼으로 구분하며 기존 `prepareLeave` 저장 보호를 거친다. 평범한 탐색마다 확인창을 늘리지 않는다. 저장 문제 때문에 이동이 막힐 때만 필요한 복구 선택을 안내한다.

**태블릿·폰**

- 넓은 화면에서는 설명판 안의 기존 패널 공간을 활용해 현재 필기를 옆에서 볼 수 있게 한다. 화면 전체를 새 관리 페이지로 전환하지 않는다.
- 좁은 화면은 한 장의 패널이 목록→미리보기→부분 선택으로 바뀐다. 작은 모달을 겹쳐 띄우지 않는다.
- 제목/닫기와 하단 확정 버튼은 남고 가운데 목록만 스크롤한다. 44px 조작 영역, Tab/Enter/Escape, 원래 버튼으로 초점 복귀를 유지한다.
- 목록으로 돌아오면 기간·불러온 범위·스크롤 위치·선택했던 날짜를 복원한다. 패널을 닫고 다시 열 때도 같은 로그인/팀 안에서는 유지한다. 계정·팀 변경 때는 지운다.
- 기간을 바꾼 뒤 예전 응답이 도착해도 현재 목록에 끼어들지 않는다. 가져오는 중 중복 클릭도 한 요청만 처리한다.

**조회 설계**

- 최초 30개, ‘더 보기’로 30개씩. 무한 자동 스크롤은 첫 차수에 넣지 않는다. 필기 중 의도하지 않은 요청과 위치 이동을 줄이고 끝을 명확히 보여주기 위해서다.
- `GET /api/classroom/boards`의 단건 `day` 조회는 유지한다. 목록에 `from/to/cursor`를 추가한다.
- 서버는 동일 사용자·팀·기간으로 날짜 내림차순 조회한다. 마지막 날짜보다 이전인 행을 31개 읽고, 30개와 `nextCursor`를 반환한다. 날짜는 소유자+팀 안에서 이미 유일하므로 날짜 커서를 사용할 수 있다. 정확히 30개인 마지막 목록도 잘못 ‘더 있음’으로 표시하지 않는다.
- cursor는 버전·팀·기간·마지막 날짜를 검증한다. 커서는 위치 정보이며 권한 증명이 아니다. 모든 요청에서 기존 교사 소유권과 RLS를 적용한다. raw query 조립을 피하고 기존 SDK 필터를 사용한다.
- 새 자료가 위에 추가돼도 이어 읽는 이전 목록에 중복을 만들지 않는다. 새 항목은 명시적 새로고침 또는 다시 처음 조회할 때 반영한다. 날짜가 수정 불가능한 기존 모델을 전제로 한다.
- 목록은 날짜·페이지 수·갱신 시각 등 최소 정보만 응답한다. 전체 필기 JSON은 목록 요청에서 내려받지 않는다.
- 설치된 TanStack Query를 재사용하고 캐시 키를 사용자/팀/기간으로 분리한다. 1차 조회 실패, 추가 조회 실패, 갱신 실패를 구분한다. 더 보기 실패는 이미 보던 목록을 유지하며 아래에 재시도를 둔다.
- 권한 상실/로그아웃에는 캐시와 열린 원본을 지운다. 닫힌/바뀐 요청은 취소 신호와 세대 검증으로 늦은 반영을 막는다.
- 최초 차수는 기존 유일 인덱스와 조회 모델을 활용해 DB 마이그레이션 없이 설계한다. 운영 데이터의 실행 계획은 실제 적용 전 확인하며, 추가 인덱스가 필요하면 별도 변경으로 제시한다.
- 기존 `truncated` 의존 UI/테스트를 함께 교체하고 부분 복사 fixture의 목록 계약도 업데이트한다. 오래 열린 구버전 탭에는 해당 필드를 잠시 유지하는 호환 전략을 검토한다.

**A 완료 기준**

0/1/29/30/31/99/100/101/365개, 윤일·월말·연말, 다른 팀/교사, 3개 이상 목록 페이지, 새 자료 추가, 기간 변경 중 응답 역전, 추가 조회 실패를 검수한다. 날짜 선택→부분 복사→목록 복귀 후 기간/스크롤/초점과 현재 수업 날짜가 유지되어야 한다. API 응답에 필기 본문이 없어야 하고 학생 계정은 조회가 거부되어야 한다.

## 3. B — 큰 판 성능과 조작성

**측정부터 시작한다.** 불필요한 전면 교체나 엔진 업그레이드를 먼저 하지 않는다. 기존 Excalidraw 0.18.1을 유지하고 앱의 조회·미리보기·저장 연결 부분을 우선 조사한다.

| 검수 집합 | 구성 | 확인 |
|---|---|---|
| 보통 수업 | 5페이지·혼합 표현 20개·자유 필기 | 입력·선택·토글·복사·저장 기준선 |
| 큰 수업 | 20페이지·여러 페이지에 표현/필기 분산 | 페이지 전환·복원·전체/부분 복사 |
| 경계 | 한 페이지 5,000요소 또는 6MiB 근접(유효 범위 안) | 멈춤/누락·한도 안내·백업·복구 |
| 반복 | 목록/원본/부분 선택 열기·닫기 20회 | 썸네일·이벤트·캐시의 지속 누적 여부 |
| 장애 | 지연·오프라인·저장 응답 유실·동시 수정 | 최신 필기 보존·상태 안내·재시도 |

합성 자료를 사용하고 사용자 필기/학습 기록을 외부 성능 수집 서비스에 보내지 않는다. 브라우저·CPU·뷰포트·네트워크 조건을 기록해 비교한다.

**우선 측정할 곳**

1. 카메라 이동만으로 문서 전체 의미 비교/직렬화가 반복되는 비용. 카메라는 기기 기록으로 유지하고 의미 변경과 분리하되, 실제 변경 판정과 계정 저장 검증은 약화하지 않는다.
2. 매번 호출되는 선택 요소 탐색·읽기 레이아웃·썸네일 생성. 내용이 바뀌지 않은 결과를 재사용할 수 있는지 확인한다.
3. 여러 페이지의 순차 다운로드. 필요하면 제한된 동시 읽기(초기 2개)를 적용한다. 페이지 ID/바이트/hash와 전체 manifest 검증을 계속 수행하고, 일부만 읽은 문서를 완전한 판으로 저장하지 않는다.
4. 닫힌 원본의 Blob URL/메모리 잔존. scope 변경과 패널 종료 시 해제하며 활성 복사 원본은 작업 완료 전 제거하지 않는다. 목록 메타데이터와 큰 필기 본문의 캐시를 분리한다.

**목표치 — 아직 측정 결과가 아님**

- 정해진 로컬 검수 조건의 보통 수업에서 주요 메뉴·선택·토글의 p95 응답 200ms 이내, 이미 읽은 페이지 재표시 500ms 이내를 초기 목표로 둔다.
- 네트워크 포함 다운로드는 별도 측정하고 지연을 필기 UI 멈춤과 구분한다. 긴 작업의 진행/실패/취소를 즉시 보여준다.
- 큰 수업에서 기존 대비 회귀가 없어야 한다. 500ms 이상 메인 스레드 정지가 보이면 원인을 기록하고 해결 여부를 판단한다. 실측 전 모든 iPad에서 같은 수치를 보장하지 않는다.
- 필기 좌표·독음/뜻·원본 hash·학생 기록 불변이 속도보다 우선한다. debounce를 늘려 미저장 창을 넓히는 방식은 채택하지 않는다.

개선은 측정된 병목만 좁게 적용한다. 썸네일은 이미 지연 생성하므로 먼저 기존 기능의 중복 실행·해제부터 확인한다. 가상 목록은 A의 페이지 처리만으로 충분한지 확인한 뒤 필요할 때 도입한다. 목록 가상화를 하더라도 선택 행과 키보드 초점을 화면 밖으로 갑자기 제거하지 않는다.

**조작성 완료 기준**

390px 폰, 768px 세로 태블릿, 1024px 가로 태블릿, 넓은 데스크톱과 200% 확대에서 닫기·확정·직접 입력 접근을 확인한다. 좁은 화면은 container 기준으로 접는다. 소프트 키보드 공간은 시뮬레이션으로 점검하되 실제 iPad 키보드/회전/손바닥/Pencil 검수를 대체했다고 표시하지 않는다. 커진 판에서 한 번 undo/redo, 학생 공개 전환 없는 복사, 저장 후 복원과 원문 복귀가 유지되어야 한다.

## 4. C — 일본어·중국어 표시 품질

**고정할 표시 위계**

```text
       독음/병음
       원래 표기          한국어 뜻
       글자별 훈음
```

설명판에서는 여러 단어와 필기를 함께 놓는 현재 목적을 유지한다. 글자만 표시를 기본으로, 카드 테두리와 독음/훈음/뜻 토글은 계속 제공한다. 선택한 표현에만 설정을 적용하고 다른 단어·주변 필기를 재배치하지 않는다. 새 표현 기본 설정과 기존 표현 편집을 구분한다.

| 항목 | 설계 규칙 |
|---|---|
| 일본어 독음 | 글자별 독음과 단어 전체 독음을 구분. 대응 관계가 불확실하면 억지로 한 글자씩 나누지 않음 |
| 중국어 병음 | 확인된 대응 관계만 글자 위에 정렬. 음절 수 불일치·라틴 혼합·숫자·구두점에 안전한 묶음 표시 |
| 한자 훈음 | 실제 한자에만 제공. 대표 훈음은 단어의 문맥상 뜻과 다를 수 있으므로 뜻 칸의 번역과 혼동하지 않게 함. 자료가 없으면 만들어 채우지 않음 |
| 일본식 자형 | 글자 모양을 옮긴 결과임을 표시. 그 자체를 실제 일본어 어휘/번역이라고 단정하지 않음 |
| 같은 뜻 일본어 | 선택한 뜻과 품사가 맞는 대응만 사용. 기존 사전·AI·직접 수정 출처를 구분하고 뜻 변경 시 이전 대응을 무효화 |
| 긴 표현 | 독음 묶음·본문·오른쪽 뜻의 읽을 크기를 지키며 줄바꿈. 모든 내용을 무조건 축소해 한 줄에 넣지 않음 |
| 영어·프랑스어 | 독음·한자 훈음 자동 추가 안 함 |

일본어 루비 처리의 근거는 [W3C JLReq](https://www.w3.org/TR/jlreq/)와 [Simple Ruby의 대응 관계 구분](https://www.w3.org/TR/simple-ruby/)이다. 초안 문서의 선택 가능한 세부 규칙을 모든 브라우저의 보장된 동작으로 취급하지 않고, 저장소의 기존 0.5em 일본어 독음 규칙과 실제 SVG/캔버스 결과를 함께 검증한다.

**뜻의 정확성과 데이터 보호**

- 조회 결과에서 선택한 뜻을 기준으로 일본어 대응을 연결한다. 단어 표기만으로 다의어를 합치지 않는다.
- 현재 뷰어의 ‘일본식 자형/같은 뜻’ 구분을 유지·검증한다. 설명판 모든 단어에 일본어 대조를 강제로 추가해 면적을 늘리지 않는다.
- 독음·뜻 직접 수정 후 늦게 도착한 사전/AI 응답은 덮어쓰지 않는다. 확신 없는 경우 원래 표기를 읽을 수 있게 남기고 확인되지 않은 독음·대응은 비워 둔다.
- 새로운 정규화 규칙은 공통 모델/유틸리티로 재사용하되, 편집 가능한 캔버스 표현과 읽기용 DOM을 하나의 거대한 UI로 합치지 않는다.
- 기존 판의 좌표와 수업 때 확정한 뜻은 자동 재생성하지 않는다. 새 레이아웃이 필요하면 새 표현과 명시적 수정부터 적용하고 판본을 구분한다. 단순히 판을 여는 것으로 마이그레이션하지 않는다.
- 기존 원문·개인 단어장·SRS에 일괄 덮어쓰기나 대량 AI 재분석을 하지 않는다. 새 AI 공급자도 추가하지 않는다.

**검증 예제 설계**

최초 60사례를 제안한다: 일본어 24, 중국어 24, 영어/프랑스어 12. 단어 전체 독음, 오쿠리가나, 작은 가나·장음, 간체·번체·신자체, 다의자, 라틴 혼합, 성조/음절 불일치, 긴 표현·뜻, 누락 데이터, 직접 수정·재접속을 나눈다. 의미 정답은 출처를 확인한 자료로 확정하고 AI의 출력 자체를 정답으로 삼지 않는다.

전체 사례는 모델 검증으로, 대표적인 고위험 사례 10개는 토글 8조합·글자만/카드·뷰어/설명판/발표 화면에서 직접 검수한다. 기존 저장 판 재접속 전후 요소 ID·좌표·훈음 숨김·뜻·출처가 불변이어야 한다. 중국어 대조 정보가 학습 본문에 불필요하게 중복되는지도 점검한다.

| 차수 | 주요 파일/책임 | 끝나는 기준 |

실제 착수 때 각 파일의 최신 변경과 선행 PR head를 확인하고 격리된 작업 공간을 사용한다. 저장소 문서·보드의 이미 완료된 ‘후속’ 항목은 해당 차수의 자기 범위에서 바로잡는다. 세계 생성용 SPEC/PNG/도시 파일 규칙은 이 웹 설계와 구분한다.

이번 설계에서 운영 merge·DB/Storage 변경·미참조 파일 삭제·새 환경 변수·PDF·음성·팀별 시험·대량 콘텐츠 재작성은 진행하지 않는다. 운영 통합 순서는 기존 PR 상태를 확인한 뒤 별도 절차로 다룬다.

**원격으로 완료 가능한 범위:** 설계, 합성 데이터 구현/검수, 코드·권한 계약 테스트, Chrome/WebKit 검사, 미리보기 준비.

**귀가 후 남는 범위:** 실제 교사 계정 전체/부분 복사→저장→재접속, 개인 노트 실제 누적 정리, 별도 학생 계정, 물리 iPad/Pencil·손바닥·회전·소프트 키보드. 로그인 대기 때문에 앞의 설계·개발을 멈추지 않는다.

## 7. 승인 시 고정할 제품 결정

1. 날짜 행의 기본 행동은 ‘살펴보고 가져오기’, 과거 수업 이동은 명시적 보조 행동.
2. 날짜 목록은 기본 30개+더 보기, 기간 선택은 접어둠.
3. 큰 판은 실측 후 최적화하며 기존 저장·복구·필기 좌표를 보존.
4. 언어 표시는 기존 위/아래/오른쪽 구조를 유지하고 자형과 뜻 대응을 구분.
5. 성능·표시 목표는 이번 설계의 제안이며 아직 구현/실측 완료를 의미하지 않음.
