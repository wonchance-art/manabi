## 0. 결론

1. **390px에서 라벨 툴바 한 줄은 「시리즈 내비가 없거나, 소유자가 아니면」만 성립한다.** 실측(내용 폭 366px): 라벨 도구 묶음 237.9px(듣기 67.9 · Aa 44 · 학습 70 · ⋯ 44 + 간격). 뒤로 44 + 도구 = 281.9 → 한 줄. 그러나 교재·시리즈 자료의 ‹ 3/20 › 내비(124.7px)가 있고 자료 소유자(⋯ 표시)이면 406.6px → **두 줄(툴바 58 → 109px)**. 소유자가 아니면 358.6px로 7.4px 남는다. v2-AD 시안의 「390에서도 4개 라벨이 들어갔다」는 시리즈 내비가 없는 경우의 측정이다. 해결안 셋 중 고르는 것이 Q1이다.
2. **⋯은 라벨이 없다.** 정본 목업(🔊 듣기 · Aa · 학습 · ⋯)과 합격 기준(「툴바 버튼은 모두 보이는 라벨」)이 충돌한다. ⋯은 소유자에게만 보이는 「자료 관리」다(`ViewerPage.jsx:2768`). Q2.
3. **자동 진행 떠 있는 버튼은 R0 #1356 문장 이동 막대와 같은 바닥 자리를 두고 다툰다.** 자동 진행은 「집중 + 지정 문장」에서만 돌고(`:1209`), 시작하면 문장을 지정하므로(`startPacer`, `:1203-1208`) **진행 중에는 항상 이동 막대가 떠 있다**(막대 조건 = 지정 문장 있음 + 패널 내용 없음). 둘 다 `position:fixed; bottom:8px`이면 겹친다. 제안: 한 자리 규칙 — 지정 문장이 없으면 단독 「▶ 자동 진행」(119.7px), 있으면 이동 막대 안의 ▶/■ 아이콘 버튼(44px). 막대 안에 「▶ 자동 진행」 글자 버튼(107.3px)을 넣으면 390에서 넘친다(빈 폭 93px, 실측). Q3.
4. **새 단어 밑줄은 #1354가 만든 「띠 밖 첫 칸」을 그대로 쓰면 된다.** 지금 저장·복습 밑줄이 쓰는 규칙(`index.css:3013-3027` — `content-box` + `padding-bottom: var(--hl-mark-gap)` + 문형 밑줄이 있으면 한 칸 더)에 `.word-token--new, .word-token--met`를 더하고, `--hl` 모드의 새 단어 면 칠(`:2965-2967`)과 지정 혼색(`:3001-3003`)을 밑줄로 바꾼다. 좌표를 새로 정하지 않으므로 #1354의 실글꼴 재조정 값(`--hl-mark-gap`·`--hl-frame-*`)을 그대로 따라간다. 밑줄 색 `--ws-new-ln`의 바탕 대비는 종이 5.12 · 밝게 5.17 · 어둡게 5.88(비텍스트 3:1 통과).
5. **집중 흐림 0.28 → 0.5 대비(계산)**: 본문 글자 종이 1.77 → **3.08**, 밝게 1.78 → 3.09, 어둡게 2.34 → **4.41**. 큰 글자 기준 3:1은 본문 글자만 넘는다. **병음(회색)은 종이 2.10·어둡게 3.14, 성조 색 병음은 종이 2.10~2.33, `--hl` 꺼짐의 저장 단어(글자 0.6)는 종이 1.86**으로 여전히 3:1 아래다(보고만 — 0.5는 오너 확정값). 실제 적용 규칙은 `reader-controls.css:53`(.28)이고 `index.css:2478`(0.18)은 특이도에 져서 죽은 값이다.
6. **본문 테두리 카드는 테두리만 지우면 끝나지 않는다.** 본문은 `--reader-paper`(종이 #fffefb), 그 바깥은 `--reader-surface`(#f6f4ee)라 색 차이로 카드가 남는다(`reader-controls.css:276,300`). 선택 띠(`--picked-bg`)·상태 띠는 종이 색 기준 불투명 혼색이라(`:52`, `index.css:2949-2958`) 바탕을 바꾸면 그 대비도 달라진다. Q5.
7. **수집 칩은 #1331(10-01)이 지웠고, 그 수는 「이 자료」가 아니라 전체 단어장 표면 수였다**(`savedCount = savedWords.surfaces.size`, `:2125`). 정본 목업 「2개 수집」은 이 자료 기준으로 읽힌다. 이 자료 기준 수는 `materialFit(json, savedWords)`(아는 단어 합치기 전)로 추가 조회 없이 나온다. Q4.
8. **Aa 창 높이는 지금 탭마다 다르다.** 390 zh: 글자 717 · 표시 717 · 읽기 688(85dvh 상한에 걸림), 영어 표시 598. 1280 zh: 651 · 658 · 614, 영어 표시 525. 「표시」를 평평하게 펼치면 zh 표시 탭 본문이 241 → 534px라 390에서는 고정 높이 안에서 스크롤이 생긴다(약 170px, 추정). 언어 설정(113px)이 맨 위에서 빠지는 만큼 다른 탭은 여유가 생긴다.
9. **세 PR로 나눈다**: ① 크롬(툴바 라벨·READING ROOM·통계 줄·카드·자동 진행 자리) → ② 본문 표시(새 단어 밑줄·흐림 0.5, CSS만, #1354 병합 뒤) → ③ Aa(탭 맨 위·평평한 표시 탭·범례·언어 선택·글자 하단·창 높이 고정). ③은 CI e2e 두 개(`viewer-language-settings`·`korean-learning`)가 언어 버튼 이름으로 누르므로 계약 개정이 가장 많다(§6).

## 4. 새 단어 밑줄 — #1354와의 정합

- #1354가 정한 자리: 띠(면 칠) 가장자리는 글자 잉크에 붙어 있으므로 선은 모두 띠 **밖** 고정 px 자리에 그린다 — ① 띠 아래 첫 칸(`--hl-mark-gap`): 문형 밑줄, 없으면 저장·복습 밑줄 ② 선택 테두리 `--hl-frame-top/bottom` ③ 병음 기준점(`index.css:2592-2601`). 값은 실글꼴로 재조정 중이다.
- AD-R2는 **값을 만들지 않고 규칙에 이름만 더한다**: `:is(.reader-area, .reader-settings__preview) .reader-area--hl` 아래 새 단어·만난 말의 `::before`를 `box-sizing:content-box; padding-bottom:var(--hl-mark-gap); background-clip:content-box; background:transparent; border-bottom:1.5px solid var(--ws-new-ln)`로, 문형 표지와 겹치면 `padding-bottom: calc(var(--hl-mark-gap) * 2 + 1.5px)`(저장·복습과 같은 식). 파일 순서·특이도 주석(「이 블록을 위로 옮기지 말 것」)을 지킨다.
- 겹침: 새 단어는 저장·복습과 동시에 걸리지 않는다(`wordStateOf` 우선순위 due > saved > known > met > new, `wordState.test.js`). 새 단어 + 문형만 겹친다 → 둘째 칸.
- 지정 중: 지금 혼색 규칙(`:3001-3003`)을 지우고 중립 지정 띠 + 밑줄을 남긴다. 선택 테두리(`--hl-frame-bottom` 5px)는 밑줄(띠 아래 1px + 1.5px) 바깥이라 닿지 않는다 — e2e 기하로 확인(§6.2).
- 「만난 말」: 같은 `:is(...)` 묶음이라 따라온다(R0 버그 11 계약 「별도 색 토큰 부활 금지」 유지).
- 밑줄 두께 1.5px는 제안값이다(「얇은」 — 저장 밑줄 2px보다 얇게, 문형 밑줄 1.5px와 같은 두께·다른 색). 문형 밑줄(회색 `--pattern-line`)과 색으로만 구분되므로 Aa 범례에 둘 다 싣는다.
