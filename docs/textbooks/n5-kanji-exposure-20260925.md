2026-09-25 KST. 대상 웹 후보 `c6ed2c215bbf36a50fe555cb`, 직전 후보 `486ee7a5c71a4ff19062d808`.

## 학습 흐름과 명칭

- 교재의 문항은 **연습**, 앞 과의 표현을 다시 쓰는 묶음은 **연결 연습**, 다음 날 회상은
  **다음 날 다시 꺼내기**로 표시한다. 화면 제목·목차·버튼의 접근성 이름도 함께 맞춘다.
- 교재 상단의 저장 표현 진입은 **담은 표현**. 하단 전체 앱 **복습**과 교재 끝의
  **담은 표현 복습하기**는 실제 저장 표현 복습 기능이므로 유지한다.
- 문항을 새로 추가하거나 FSRS 일정을 만들지 않는다. 내부 `review` 주소, 문항 ID,
  `data-save`, 출처 ID는 유지하고 사용자 입력은 변환하지 않는다. 판본별 답안 분리는 기존대로다.

## 감사 방법과 한계

`python3 scripts/textbook/audit-n5-kanji.py --edition <판본>`으로 렌더링된 42과의 일본어
한자 노출을 순서대로 추적한다. 한자 본문·ruby 독음·문항·해설을 구분한다. 한국어 표제,
목차 링크, 권말 색인은 본문 첫 노출로 세지 않는다. 표의 인접 가나와 안내 문맥을 함께 남긴다.

`firstBody`에는 설명·어휘·예문·읽기 안내가 포함된다. `firstRuby`는 위에 붙은 독음이
처음 있는 위치이며, **옆의 가나 표기나 한국어 설명의 효과를 자동 판정하지 않는다**.
`firstUnassistedQuestion`도 해당 토큰에 ruby가 없다는 뜻이지 학습자가 도움 없이 풀 수
있다는 인증은 아니다. 안내에 독음이 먼저 있거나 표에서 익히도록 한 경우는 맥락을 읽어 판단했다.

1–5과 본문의 일본어 한자는 0개다. 6과 円부터 시작하고, 10과 시각과 11과 달력·단위는
안내와 표에서 읽기를 먼저 제공한다. 12과의 `まち → 町` 같은 기존 안내도 유효하다.
이 경로를 보존하고 모든 한자에 일괄 후리가나를 추가하지 않았다.

## 색인과 본문 범위의 차이

권말 한자 색인 103자와 본문·문항 103자는 **수가 우연히 같고 집합은 다르다**.
공통은 56자다. 본문 쪽에만 있는 47자:

`付住体使全冊写匹厚受回場好帰度持教方旅早明春昨暑曜枚楽橋歳熱物申町真箸終絵締自要近速邪部閉階風`

색인 쪽에만 있는 47자:

`七万三上下九二五八六北十千南口古右四国外女子学山川左年手東校母父男百目社空立耳花西言足週道長魚`

예를 들어 색인의 名前는 1과를 가리키지만 1과 본문에서는 가나로 다루고 한자 표기는 41과에
나온다. 이 차이를 숨기거나 색인 전체를 실제 한자 최초 도입으로 해석하지 않는다. 대표 어휘의
학습 과와 한자 표기의 도입 과는 다른 개념이다. 이번에는 색인 내용·주소를 그대로 보존했다.
다음 후보는 **색인의 안내 기준과 본문 학습 연결을 정합화하는 일**이다. 글자 수 확대보다
찾아간 과에서 해당 표기와 읽기 도움을 만날 수 있게 하는 것이 우선이다. 시험 범위의 완전성은
별도 근거가 필요한 평가이며 이번 감사로 인증하지 않는다.
