# manabi 웹 v2 — 자료 가져오기와 읽기 왕복

2026-09-07 KST · 오너 「작업 개시」. 앞선 검토의 검색 연결 수정·가져오기 안정화·읽기 왕복을 구현한다. Base는 서재·발견 PR #1283이다.

## 적용

- 헤더 검색은 회원의 내 자료 / 비회원의 공개 자료로 연결하고, 실제 검색 입력에 키보드 포커스를 준다.
- 원문 저장 직후 읽기 입구를 제공한다. 원문과 분석 준비 상태를 구분하고, 실패·중단 후 같은 자료 ID에서 재시도한다. 입력 중 실패는 폼을 보존하고, 저장 확정 뒤에는 원문·언어·출처를 고정한다.
- 한 화면에서 중복 클릭은 같은 저장 요청으로 합친다. 응답이 유실된 요청은 계정과 요청 식별자로 조회한 뒤 다시 저장한다. 새 DB 테이블이나 마이그레이션은 없다.
- 분석 배치 저장은 실제 변경된 행을 확인한다. 저장 실패를 완료로 표시하지 않는다. 재시도는 성공한 토큰을 재사용하고 남은 줄을 처리한다. 링크 출처·PDF/EPUB 비공개·노트 비공개는 보존한다.
- 분석 중 원문을 열면 기존 분석을 멈춘 뒤 뷰어로 이동한다. 노트는 분석을 요청하지 않는다. PDF 범위 가져오기를 읽기 완료로 오인하여 마지막 쪽으로 진도를 이동하던 처리는 제거했다.
- 자료와 PDF의 ‘내 서재’ 복귀 링크에 검색·분류·펼친 목록 수·스크롤을 연결한다. 복귀 주소는 `/materials`의 허용된 탐색 파라미터만 받으며 외부 주소는 받지 않는다.
- 읽기 위치는 스크롤/토큰 선택에서 기록한다. 저장 요청은 순서대로 전송하고, 페이지 이동 직전 대기 중인 값을 보낸다. 계정 전환은 이전 대기값을 폐기한다. 실패 시 읽기 화면에서 다시 저장할 수 있다.
- 복습에서 원문을 열 때 토큰 강조가 어휘 조회 후 사라지던 현상을 수정했다. 강조 상태를 React가 렌더하여 후속 데이터 갱신에도 유지한다.
- 원문/예문 렌더러와 기존 복습·FSRS·문맥 저장을 재사용한다. 소스 토큰·판본·복습 일정 의미를 바꾸지 않는다.

## 검증

- 변경 helper: 중복 클릭, 응답 유실, 조회 실패, 소유자 분리, 중단 복구, 저장 권한 변경, 안전한 복귀 주소, 직전 위치 전송과 요청 순서 검증.
- 브라우저: 격리된 HTTP fixture로 실제 UI → 저장 요청 → 분석 결과 → 읽기 → 표현 저장 → 복습 → 원문 복귀를 검사한다. 외부 AI나 개인 계정 자료에는 쓰지 않는다.
- 기존 노트·출처·뷰어 판면 계약을 유지한다. 기존 source-string 검사 두 파일은 저장 helper 추출과 ‘PDF 가져오기 ≠ 읽기 진도’ 변경에 맞게 갱신했다. 행동 검증을 `materialImport.test.js`와 `reading-loop.e2e.mjs`로 보강했다.
- 전체 단위 검사: 347파일 / 3,770개. 최종 전체 명령은 3,766개 통과, 변경 없는 `studiesRefs.test.js`의 beforeAll 60초 초과로 4개 미실행. 해당 파일 단독 재실행은 4개 모두 통과(21.89초). 전체 명령이 일괄 green이었다고 보고하지 않는다.
- 변경 helper 22개(가져오기 6, 복귀 주소 10, 위치 writer 6). 변경 파일 ESLint 오류 0, 기존 hook 경고 4. `git diff --check` 통과.
- Vercel 실행 코드 `ea6d42030e48ea04ee8c99a7f612e70585c1f150`: Next 15.5.21 빌드 완료, 474페이지 생성. 콘텐츠/커리큘럼 오류 0(기존 경고 11). 후속 커밋은 검수 하니스와 문서·보드만 변경한다.
- 최종 배포 브라우저 20조건 통과 / pageerror 0. 실제 페이지 코드를 쓰되 인증·저장·분석 HTTP는 명시적 fixture로 격리한다. 실제 개인 계정이나 외부 AI를 호출한 검증으로 오인하지 않는다.
- 320/390/768px 긴 제목·복귀 링크 가로 넘침 0, 1440/390px 가져오기 화면과 실패/완료 화면을 직접 렌더 확인.
- 검수 중 로그인 직후 URL만 `/home`으로 바뀌고 본문은 아직 로딩 중인 순간에 다음 이동을 보내면 URL과 본문이 어긋나는 전환 사례를 확인했다. 홈 제목이 표시된 뒤 검색하면 정상이며 최종 하니스는 실제 홈 표시를 기다린다. 전환 도중 연속 탐색의 재현·해결은 후속 확인 사항으로 남긴다.

## 범위와 한계

- 기본 붙여넣기 및 링크/PDF/EPUB에서 단일 글로 넘겨받는 저장 경로를 개선했다. 여러 챕터를 한꺼번에 등록하는 기존 경로는 유지한다.
- 처리 중인 브라우저를 닫아도 서버에서 분석을 계속하는 작업 큐를 새로 만들지는 않았다. 이미 저장된 원문은 서재에서 열고, 기존 뷰어의 중단된 분석 복구를 사용할 수 있다. 원문이 저장되기 전 폼의 새로고침 복원은 별도다.
- 원래 작업 공간의 미커밋 뷰어·PDF 변경을 덮어쓰지 않았다. 격리된 최신 웹 PR 계열에서 변경했다.
- 음성·PDF 교재 조판·원고 저작·북마크·통합 검색·기기 간 교재 진도 동기화·월드·운영 DB/환경 변경 제외. merge/force-push 및 운영 승격 없음.

## 선례 선택

| 선택 | 적용 |
|---|---|
| 기존 `analyzeText(existingJson)` 재사용 | 성공 토큰·실패 줄 계약 유지, 신규 분석기 없음 |
| 기존 `useReanalyze`, `reading_progress`, FSRS 재사용 | 읽기·재분석·원문 출처를 기존 정본에 연결 |
| 현재 Supabase insert/update/select 계약 | 반환 오류와 실제 변경 행 검사. 공식 문서: https://supabase.com/docs/reference/javascript/insert · https://supabase.com/docs/reference/javascript/update |
| 별도 업로드/상태 머신 패키지 도입 안 함 | 기존 텍스트·PDF·EPUB 입구와 비공개 정책을 유지하는 범위이며 새로운 파일 처리 엔진이 필요하지 않음 |
