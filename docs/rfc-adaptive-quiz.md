# RFC — 적응 출제: 만남 인지 슬롯 (시간 없는 적응) v1

- 상태: **제안(승인 전 구현 금지)** — UI 규약대로 목업 A·B 동봉, 목업 합의가 곧 착수 조건
- 기준: `origin/main` `585f55aa9d7a7282f814f981c6286f29060ec793`
- 발주: rfc-vocab-encounter §7 보류 항목("적응 출제 — 별도 RFC")의 이행.
  기원은 kana-dojo 검토 필터 통과분 "**시간 없는** 적응 출제"(2026-08-22)이며,
  만남 모델 전체(§4.2~§4.8, #1090~#1102) 완결 후 오너 지시 "적응 출제 RFC도 ㄱㄱ"(2026-08-23).
- 원칙: **타이머·콤보·보상·스트릭 없음**(분위기 필터 — kana-dojo의 시간 압박 기계는 배제).
  **FSRS·SRS 정책 무변경**(audit-card-srs 별도 트랙). 기존 적응 부품 재사용 — 중복 신설 금지.

## 1. 결론

/study 일일 세션에 **"만난 말" 인지 문항 슬롯(상한 2)** 을 더한다. 월드·뷰어에서
마주쳤지만 아직 담지 않은 정본 어휘가, 담김(단어장) 이전에도 세션에 가볍게 등장해
숙련 사다리의 **rung 0(노출 전)→1(인지) 다리**를 놓는다. 이것이 두 학습 순환(자료
읽기 ↔ /study 일일 세션)을 만남 데이터로 잇는 마지막 이음새이며, 서버 정본
`user_vocab_encounters`(§4.5)가 이 RFC의 전제 인프라다.

## 2. 현행 적응 실측 — 이미 있는 것 (2026-08-23 전수 조사)

적응은 이미 3축으로 돌고 있다. 이 RFC는 **선정 축의 공백 하나**만 채운다.

| 축 | 부품 | 동작 |
|---|---|---|
| 선정(무엇을) | assembleStudyMaterials | FSRS due 어휘 4 · due 문법 2 · 다음 새 챕터 1 · 독해 슬롯(테마 로테이션+관심사 70%) |
| 선정(보강) | 워밍업 | 최근 24~72h 이벤트 어휘로 인지형 2문항(문단 생성 레이턴시 가림, 오답 우선) |
| 선정(약점) | computeWeakness | 오답률×ln(표본) 가중 상위(cap 20)를 내일 문단 재료로 재주입 |
| 타입(어떻게) | rung 사다리 0~5 | review_events에서 유도(순수 함수) — 인지→단서회상→자유회상→청각→산출, 2연속 규칙 승강 |
| 강도(얼마나) | EWMA 다이얼 | 채점 이벤트만(ui·dict 제외), 표본 20 미만 무조절, easy면 신규 재료 게이트(gateNewMaterialsByDial) |

- 예산: 세션 MAX_ITEMS 10 하드캡(기획 H3). 셔플 없음(조립 결정적, 렌더 몫).
- 문항 재료: cloze 예문은 정본 레지스트리에서 서버 조립(buildVocabExampleMap).

## 3. 공백 — 만남이 출제에 들어오지 않는다

- due 어휘 조회는 `user_vocabulary`(담김 이후)뿐 — **만난 말(§4.2·§4.5)은 세션이
  모른다**. rung 사다리에 0(노출 전)이 정의돼 있고 만남 기록이 정확히 그 실증인데
  미연결.
- 만남→담김 다리는 현재 수동 버튼 2곳뿐(NPC 완주 카드·사전 [+ 담기]) — 마주친 말을
  다시 만나 볼 계기가 학습 웹 순환 안에 없다.

## 4. 제안

### 4.1 만남 인지 슬롯 (R1)

- **후보**: `user_vocab_encounters(user_id, lang)` − `user_vocabulary(word_text)` −
  최근 review_events 등장 어휘(이미 조회하는 400행 재사용 — 최근 본 것 재출제 방지).
  조회 1개 추가(기존 병렬 Promise.all에 합류), 정본 대조·뜻은 이미 로드된 refLangs
  레지스트리에서(§4.7 buildRegistryIndex와 같은 표제어 인덱스 — 서버관 재사용 설계).
- **문항**: `vocab-choice`(인지)만 — rung 0 어휘에 vocabTypeForRung을 물으면 정확히
  choice가 나온다(사다리 정의 그대로, 새 분기 없음). 보기 풀은 기존 meaningPool 재사용.
- **예산**: 상한 2문항, **due 어휘가 4 미만일 때 남는 어휘 슬롯만** 사용(과부하 0 —
  due가 꽉 찬 날은 만남 슬롯 0). dial 'easy'면 0(gateNewMaterialsByDial과 같은 결 —
  신규 재료 취급).
- **기록**: 채점은 기존 review_events 적재 경로 그대로 `source:'vocab'`,
  `detail.qtype:'choice'` (+`detail.origin:'encounter'` 계측 표지). 이 어휘가 나중에
  담기면 deriveVocabRungs가 같은 item_key 이력을 그대로 읽어 **rung이 이어진다** —
  새 이음새 없음. FSRS(user_vocabulary) 무접촉.
- **게스트·미동기**: 서버 조립이라 서버 정본이 비면 슬롯 0으로 조용히 생략(§4.5
  무해성 계약의 연장). 로컬 만남만 있는 게스트는 대상 아님을 명시(동기화가 선행).

### 4.2 정답 직후 담기 제안 (R2 — 목업 B 승인 후)

- 만남 문항을 **맞힌 직후에만** [+ 담기] 한 줄 제안 — NpcDialog 완주 카드의
  `user_vocabulary` `ignoreDuplicates` upsert 선례 그대로(FSRS 무손상). 자동 담김
  금지(수집은 명시적이라는 기존 철학), 오답 시 무제안(압박 없음).

### 4.3 '시간 없는' 원칙

- 타이머·제한시간·속도 채점 없음(kana-dojo 배제분 유지). 적응은 선정·타입·강도
  3축뿐이며 이 RFC는 선정 축만 만진다. **만남은 채점 신호가 아니다** — EWMA
  다이얼·약점 집계에 유입하지 않는다(ui·dict 제외 원칙과 같은 결).

## 5. 목업 (승인 대상 — 배치·정보량 합의용, 문구·기호는 교체 가능)

**A. 세션 만남 문항 카드** — 기존 vocab-choice 카드 상단에 조용한 한 줄:

```
🈁 만난 말 — 월드·읽기에서 마주친 말이에요

   替え玉
   ① 곱빼기   ② 사리 추가   ③ 계산   ④ 포장
```

**B. 정답 직후 담기 제안** — 정답 피드백 줄 아래 1줄(오답이면 없음):

```
✓ 정답! 사리 추가
[+ 단어장에 담기]   괜찮아요, 넘어갈게요 →
```

## 6. 비목표

- FSRS·SRS 정책 변경, 담김 전 어휘의 FSRS 편입(담김은 계속 명시적 선택)
- 타이머·콤보·속도 보너스·보상·스트릭(분위기 필터 — 전 RFC와 동일)
- LLM 실시간 문항 생성(출제는 정본·결정적 조립 유지)
- i+1 자료 추천(evaluation-and-strategy P0 "AI 난이도 적응형 추천" — 별도 트랙)
- 만남 **출처 문맥** 저장(어느 문장에서 만났는지 — 스키마 확장이라 후속 gate;
  v1 cloze 재료는 기존 정본 예문 그대로)
- 만남 신호의 난이도 다이얼 유입
