## 1. 권장 방향

원본을 읽다가 원하는 구간을 골라 공부하고, 저장한 표현의 복습에서 그 구간과 원본으로 돌아오게 한다. 사용자가 자료 형식을 고르거나 새 학습 자료의 제목·폴더를 다시 입력할 필요가 없어야 한다.

사용자의 선택은 ‘어떤 부분을 공부할지’에 집중시킨다. 원본 읽기 화면에는 `학습할 부분 고르기`, 선택 후에는 `이 부분 공부하기`를 둔다. 학습 화면에서는 이미 있는 표현 저장·복습을 사용한다.

```text
내 서재의 자료 한 권
    └ 원본 읽기 — 작성한 글 / 첨부 파일
         └ 구간 선택 → 확인 패널 → 이 부분 공부하기
              └ 기존 학습 화면
                   ├ 표현 저장 → 기존 복습 → 표현이 있던 학습 구간
                   └ 원본의 이 부분으로 → 같은 파일·쪽·장·문장
```

서재에는 원본 한 건을 유지한다. 학습 구간은 그 자료 아래에 붙고, 별도 책 표지를 계속 만들지 않는다. 구간을 읽은 사실을 책 전체 완독으로 계산하지 않는다.

## 3. 화면과 조작

### A. 원본을 읽을 때

기존 제목·첨부 선택·읽기 영역을 유지한다. 읽기 도구에 `학습할 부분 고르기` 한 개를 추가한다. `학습 구간 3`은 실제 구간이 생겼을 때만 같은 자료의 펼침 목록으로 나타난다.

현재 하단에 있는 본문 학습 안내와 새 안내를 두 군데서 반복하지 않는다. 구간 학습이 대표 입구가 되고, 기존 긴 본문 전체 학습은 자료 도구에서 계속 사용할 수 있게 한다. 그 기존 기능의 주소·분석 결과를 이번 구간 상한 때문에 없애지 않는다.

데스크톱에서는 텍스트를 드래그하면 선택 가까이에 `이 부분 공부하기` 진입 버튼을 표시한다. 버튼을 누르면 선택을 고정하고 확인 패널을 연다. 단순 드래그·복사·패널 열기만으로 서버 저장이나 AI 분석을 시작하지 않는다.

모바일에서는 기본 길게 누르기·복사 메뉴를 보존한다. 선택이 끝나면 읽기 도구의 버튼을 활성화한다. 네이티브 선택 핸들과 겹치는 팝업을 강제로 띄우지 않는다.

드래그가 어렵거나 키보드를 쓰는 사용자는 `학습할 부분 고르기`에서 현재 쪽/장의 텍스트를 펼쳐 문단을 누른다. 이어지는 문단을 추가하거나 편집 가능한 범위에서 일부 글자만 선택할 수 있다. PDF의 문단 경계를 확신할 수 없으면 읽기 순서의 텍스트 블록으로 보여준다. 줄을 문장이라고 임의로 명명하지 않는다.

첫 릴리스에서는 하나의 본문·PDF 한 쪽·EPUB 한 장 안의 연속 구간을 고른다. 여러 파일이나 떨어진 구간을 합치는 편집기는 만들지 않는다.

### B. 확인 패널

데스크톱은 읽기 폭을 바꾸지 않는 작은 오버레이 패널, 모바일은 하단 시트다. PDF를 밀어 폭을 바꾸면 텍스트 레이어가 다시 그려질 수 있으므로, 패널을 열기 전에 선택 문자열과 출처를 메모리에 고정한다.

```text
이 부분 공부하기                              닫기

자료 제목 · 첨부 이름 · 12쪽
┌─────────────────────────────────────┐
│ 고른 원문이 그대로 보입니다.          │
│ 문맥을 확인할 수 있도록 여유 있게 표시 │
└─────────────────────────────────────┘

일본어 ▾                              내용 다듬기
선택한 구간의 뜻과 표현을 준비합니다.

                             [ 이 부분 공부하기 ]
```

- 제목·자료 종류·저장 위치를 다시 묻지 않는다. 제목은 원본과 위치로 구성한다.
- 학습 언어는 자료의 명시된 언어를 기본값으로 쓴다. 미지정이면 선택을 요청한다. 자동 추정만으로 일본어를 기본 확정하지 않는다. 네 언어 모두 제공한다.
- 잘못된 줄바꿈은 `내용 다듬기`에서 수정한다. 수정 전 추출 문자열과 학습용 수정 문자열을 구분해서 보관한다. AI로 원문을 자동 교정하지 않는다.
- 긴 선택은 패널 안에서 전체를 읽을 수 있게 한다. 서버로 전송할 내용을 말줄임표로만 확인시키지 않는다.
- 한 번에 최대 **1,500자**를 초기 제품 상한으로 제안한다. 이는 검증된 최적 학습량이 아니라 작은 구간에 집중하고 비용을 제한하기 위한 시작값이다. 초과분을 몰래 잘라내지 않고 범위를 줄이게 한다. 공백만 있는 선택은 시작할 수 없으며 짧은 한 단어는 허용한다.
- 버튼 클릭 한 번으로 구간 생성/재사용과 분석 시작을 연결한다. 다음 화면에서 다시 ‘본문 분석하기’를 누르게 만들지 않는다. 이미 분석된 동일 구간은 곧바로 연다.
- 닫기는 원래 읽던 위치와 포커스로 돌아간다. 저장 전 취소는 새 자료를 남기지 않는다.

### C. 학습 화면

기존 `/viewer/:id?study=1` 화면을 사용한다. 위에는 원본과의 관계를 짧게 보여준다.

```text
← 원본의 12쪽으로                   내 서재
자료 제목 / 12쪽에서 고른 부분

선택한 구간의 본문
단어를 누르면 기존 표현 상세
필요한 표현만 [저장]
```

원본·학습 화면은 각각 고유 주소를 갖되 같은 자료 안을 오가는 경험으로 만든다. PDF와 학습 본문을 항상 나란히 띄우는 이중 뷰어는 첫 범위에 넣지 않는다.

분석 중에도 고른 원문은 즉시 읽을 수 있다. 생성 완료·분석 진행·부분 실패를 구분한다. 준비된 표현부터 사용할 수 있고, 실패한 부분은 같은 구간에서 재시도한다.

분석된 모든 단어를 자동 저장하지 않는다. 사용자가 저장한 표현만 기존 어휘·복습 경로를 따른다. 글 전체 북마크, 선택한 학습 구간, 저장한 표현은 각자의 의미를 유지한다.

### D. 서재와 원본으로 돌아왔을 때

원본 자료 아래의 `학습 구간`을 펼치면 위치·짧은 인용·언어·준비 상태를 보여준다. ‘3개’는 생성된 구간 수이며 학습 완료 수가 아니다. 첫 화면에는 소수만 표시하고 나머지는 이어서 불러온다.

```text
자료 한 권
    학습 구간 3
    ├ 12쪽 · 인사하는 장면…                 열기
    ├ 18쪽 · 약속 시간을 정하는 문장…       열기
    └ 3장 · 길을 묻는 대화…                 열기
```

최근 열람 카드도 같은 원본 한 건으로 묶는다. 마지막으로 실제 열린 화면이 학습 구간이면 그 구간으로, 원본이면 해당 첨부로 돌아간다. 구간을 만들기만 했거나 패널을 열기만 한 동작은 최근 열람으로 기록하지 않는다.

저장 표현의 복습에서 ‘출처’를 누르면 그 표현이 있는 **학습 구간**으로 돌아간다. 거기에서 ‘원본의 이 부분으로’를 누르면 동일 첨부의 해당 위치를 연다. 정확히 일치하는 선택은 강조하고, 찾지 못하면 해당 쪽/장과 보관한 인용을 보여준다. 비슷한 문장에 임의로 표시하지 않는다.

## 4. 디자인 기준

- 기존 manabi 로고·서체·언어 색상 유지. 일본어 붉은 모브, 중국어 세이지, 프랑스어 잉크블루, 영어 승인된 계열을 기존 토큰에서 가져온다.
- 본문은 밝고 차분한 면에 유지한다. 강조색은 선택 표시·핵심 버튼·출처 표시에 제한한다.
- 확인 패널의 원문은 분명한 테두리와 내부 여백을 가진 인용 박스로 만든다. 아이콘이나 상태 배지를 본문보다 크게 만들지 않는다.
- 기존 자료에 기본으로 여러 도구 카드를 펼치지 않는다. 선택한 순간에 필요한 조작이 나타난다.
- 새 좁은 화면 대응은 기존 UI 규약에 따라 컨테이너 기준으로 설계한다. 320px·390px·768px·1280px와 확대 200%에서 확인한다.
- 터치 조작 영역은 최소 44px를 목표로 한다. 시트가 하단 메뉴·홈 인디케이터·키보드와 겹치지 않도록 여백과 스크롤을 확보한다.
- 키보드로 진입·구간 선택·언어 변경·시작·닫기가 가능해야 한다. 패널 열기 후 포커스 이동, Escape 닫기, 닫힌 뒤 포커스 복구를 구현한다. 키보드 포커스 이동을 곧바로 저장으로 연결하지 않는다.
- 일본어·중국어의 학습 독음은 기존 정책을 재사용한다. 영어·프랑스어에는 새 독음을 붙이지 않는다. 첨부 원본 자체의 조판은 변경하지 않는다.

## 5. 출처와 데이터 계약

새 전역 ‘하이라이트함’이나 별도 단어장을 만들지 않는다. 기존 `reading_materials`의 비공개 학습 자료를 재사용하고, `metadata.composer.role='study'`와 `parentId`로 서재 원본에 묶는다.

아래는 개념 필드다. SQL 스키마 확정안이 아니며 구현 시 기존 CHECK·RLS·목록 응답과 함께 검증한다.

| 보관 정보 | 용도 |
|---|---|
| 소유자·원본 자료 ID | 권한 및 서재 묶음 |
| source kind, 원본 revision 또는 첨부 hash | 어느 판본/파일에서 가져왔는지 식별 |
| PDF 실제 쪽 번호 / EPUB spine 경로·순서 / 본문 구간 | 원래 위치로 복귀 |
| 선택 문자열 exact, 짧은 prefix/suffix | 같은 문장이 반복될 때 올바른 위치 구분 |
| 위치 start/end와 텍스트 추출 규칙 version | 빠른 위치 확인과 파서 변경 영향 구분 |
| 수정 전 인용·학습용 본문·언어 | 원문 보존 및 수정한 텍스트의 학습 |
| 중복 방지 키 | 두 번 클릭·새로고침·응답 유실 시 같은 구간 재사용 |

출처 정보는 기존 불변 composer 메타데이터 안의 버전 있는 객체로 확장하는 방향이 적절하다. 서버에서 부모 소유권·비공개 여부·첨부 소속·허용 범위·크기를 검사한다. 클라이언트가 보내는 저장소 경로를 그대로 신뢰하지 않는다. 원본 텍스트와 출처는 고정하고 분석 결과·진행 상태만 갱신한다.

파일 파싱은 현재처럼 브라우저에서 수행할 수 있다. 서버가 출처 소속을 검증했다는 사실을, 선택 문자열이 실제 PDF와 완전히 일치함을 서버가 인증한 것으로 해석하지 않는다. 복귀 시 실제 텍스트와 다시 대조한다.

첨부를 교체해도 과거 구간은 당시 hash와 retainedAssets의 원본을 참조한다. 현재 첨부 선택 목록에 없더라도 출처 링크로 해당 보관 파일을 열 수 있는 읽기 경로가 필요하다. 작성 본문이 수정되면 과거 구간은 당시 인용을 보여주며 현행 본문에 틀린 위치 표시를 하지 않는다.

원본의 완전 삭제나 권한 상실 시 기존 삭제 정책을 우회해 파일을 다시 가져오지 않는다. 접근 가능한 학습 구간이 남아 있다면 그 본문을 열고 원본 접근 불가를 표시한다. 새 자동 삭제·공유 정책은 이번에 추가하지 않는다.

## 6. 위치 지정에서 특히 주의할 점

**PDF:** 화면의 픽셀 좌표만 저장하면 화면 폭·배율 변경에 깨진다. 실제 쪽 번호와 텍스트 조각/문자 위치 매핑을 함께 보관한다. 원본 텍스트 레이어와 `reconstructPdfPageText`의 읽기 순서가 다를 수 있으므로 두 출력을 동일하다고 가정하지 않는다. 신뢰할 수 있는 매핑이면 문장까지, 불가능하면 쪽까지 복귀한다. 한 쪽 선택 중에는 필요한 렌더 노드를 유지하고, 페이지 전환으로 사라지는 DOM Range를 영구 출처로 저장하지 않는다.

**EPUB:** 제목이나 표시 순번만 저장하지 않는다. 같은 첨부 hash 아래의 spine 항목 경로·순서와 추출 텍스트 버전·문자열을 함께 저장한다. 현재 텍스트 파서는 원래 XHTML DOM을 유지하지 않으므로 CFI를 생성했다고 가장하지 않는다. 향후 정식 EPUB 렌더러 도입 때 별도 변환한다.

**문자열:** 위치 계산의 단위를 명시한다. Unicode code point 기준을 채택하고 브라우저 DOM의 UTF-16 offset은 변환한다. 일본어 요미, 프랑스어 결합 악센트, 이모지, 반복 문장, 줄바꿈을 테스트한다. 원문에 호환 정규화나 임의의 공백 제거를 적용해 출처를 바꾸지 않는다.

**중복 판정:** 동일 소유자·원본·원본 버전/파일·위치·학습용 텍스트·언어가 같으면 같은 자료를 사용한다. 같은 문장이 다른 쪽에 있다는 이유만으로 합치지 않는다. 자료 제목만 바꾼 경우 첨부의 동일 구간을 불필요하게 새로 만들지 않는다.

## 7. 분석·저장·진도

1. 구간 선택과 확인은 읽기 동작이다. 파일의 해당 쪽/장을 추출하며 AI 호출은 0이다.
2. ‘이 부분 공부하기’를 누르면 부모와 소스 버전을 재검증하고 고정된 학습 구간을 저장하거나 조회한다.
3. 학습 화면으로 이동해 같은 요청의 분석을 한 번 시작한다. 새로운 시도는 작은 구간만 분석한다. 기존 완료 구간은 분석하지 않고 연다.
4. 네트워크가 끊겨 저장 여부가 불확실하면 중복 방지 키로 조회한 후 재시도한다. 기존 레코드를 재사용할 때는 ID만 찾은 뒤 가짜 pending 상태를 조립하지 말고 실제 분석 상태를 다시 읽는다.
5. 복수 탭의 자료 중복뿐 아니라 중복 분석도 막는다. 새 구간은 서버의 조건부 상태 전환과 요청 식별자로 실행 소유권을 관리한다. 오래된 응답이 새 분석 결과를 덮지 못하게 하고, 새 시스템을 만드는 대신 기존 분석 경로에 필요한 제어를 좁게 보강한다.
6. 분석 도중 나가면 원문과 확인된 결과는 남긴다. 브라우저를 닫아도 작업이 반드시 완료된다고 약속하지 않는다. 중단된 구간에서 이어서 준비할 수 있게 한다. 페이지 이탈 전 비동기 함수를 던져 두고 전체 페이지 이동하는 기존 PDF 방식은 복제하지 않는다.
7. 준비·분석·열람만으로 `review_events`의 채점이나 FSRS 일정을 갱신하지 않는다. 표현 저장은 현재 정본, 실제 복습 채점도 현재 정본을 사용한다.
8. 구간 읽기 완료는 해당 구간에만 기록한다. 원본 책·N5 교재 전체 진도로 합산하지 않는다. PDF 추출 끝 쪽을 읽던 쪽으로 덮어쓰지 않는다.

하나의 분석 프롬프트에 원본 파일 전체를 보내지 않는다. 선택한 학습 텍스트와 필요한 범위의 언어 메타데이터만 전달한다. 출처 주소·저장소 서명 URL·개인 파일 이름은 모델 입력에 불필요하게 넣지 않는다.

## 8. 실패·예외의 실제 동작

| 상황 | 사용자에게 보이는 처리 |
|---|---|
| 언어 미지정 | 확인 패널에서 네 언어 중 선택. 원본은 그대로 읽을 수 있음 |
| 빈 구간·길이 초과 | 해당 입력 바로 옆 안내. 조용히 잘라내거나 빈 자료를 생성하지 않음 |
| 스캔 PDF·글자 추출 불가 | ‘이 쪽의 글자를 가져올 수 없어요’와 직접 입력 경로. 자동 OCR은 이번 신규 흐름에서 제외 |
| 다단·세로쓰기에서 순서가 깨짐 | 추출 본문을 확인·다듬기. 신뢰할 수 없으면 직접 입력. 정확한 문장 강조를 약속하지 않음 |
| 직접 입력한 구간 | 출처는 사용자가 고른 쪽/장까지. 자동 추출된 인용처럼 표시하지 않음 |
| 첨부 다운로드·파싱 실패 | 원문 화면에 재시도. 선택 준비 이전에는 학습 자료 생성 없음 |
| 선택 중 원본/계정 변경 | 해당 소스의 선택을 무효화하고 재선택. 다른 파일·계정에 이어 붙이지 않음 |
| 저장 성공·분석 실패 | 학습 구간과 원문은 유지, 같은 구간에서 준비 재시도 |
| 로그인 만료·권한 상실 | 내용을 공개 캐시로 넘기지 않고 재인증/접근 불가 안내 |
| 원문 위치 일치 실패 | 쪽·장으로 이동하고 보관한 인용 표시. 정확한 위치를 못 찾았음을 명시 |
| 모바일 화면 회전·글자 확대 | 고정된 선택 자료를 유지하고 범위와 원문 위치 재확인 |

직접 입력은 추출이 실패한 경우의 보조 경로다. 정상적인 선택마다 별도의 작성 단계를 추가하지 않는다.

## 10. 첫 완료 범위와 후순위

**첫 완료 범위**

- 새 통합 편집기의 작성 본문, PDF 한 쪽, EPUB 한 장에서 연속 구간 선택.
- 모바일/키보드용 문단·텍스트 블록 선택, 추출 실패 시 직접 입력.
- 언어·추출 내용 확인 후 한 번의 실행으로 기존 학습 화면 진입 및 준비.
- 중복 생성/분석 방지, 오류·중단·재시도 처리.
- 원본 단위 서재 묶음, 자료 안의 학습 구간 목록, 최근 열람의 정확한 모드 복귀.
- 기존 표현 저장·복습 출처 연결과 원본 쪽/장으로 돌아가기. 정확 매칭에 성공한 구간 강조.
- 과거 첨부가 보관 중인 경우 해당 파일의 출처 열기.

**후순위**

- 여러 쪽·여러 장·떨어진 문장을 합치는 선택.
- 자동 OCR 및 세로쓰기·복잡한 다단 PDF의 고급 레이아웃 복원.
- 외부 URL 본문 자동 가져오기, 웹 확장 프로그램.
- 원문과 학습 화면의 상시 분할 보기.
- 범용 색상 하이라이트·메모 관리, PDF 주석 파일 내보내기.
- 기기 간 원본 읽기 위치 동기화, 고아 업로드 정리.
- 기존 레거시 PDF 10쪽/OCR 경로 전체 이관 및 ‘오늘 학습’ 로컬 전달 구조 개편.
- 음성 제작과 PDF 교재 조판.

## 11. 구현 순서와 완료 기준

**구현 순서**: 출처·재사용 계약 → 본문/EPUB 선택 → PDF 선택 및 대체 입력 → 기존 학습 화면 연결 → 서재/복습/원본 복귀 → 데스크톱·모바일 통합 검수. 내부 작업은 나누되 사용자가 검토하는 결과는 이 한 흐름이 끝까지 연결된 상태로 준비한다.

1. 실제 비공개 원본에서 구간 선택 → 학습 → 표현 저장 → 복습 출처 → 학습 구간 → 원본을 왕복한다.
2. 선택 취소는 새 행 0, 연속 두 번 실행 및 응답 유실 재시도는 구간 1개, 동시 탭 분석은 유효 실행 1개를 확인한다.
3. 이미 분석한 구간을 다시 선택해도 기존 분석·표현 출처·복습 일정이 유지된다.
4. 동일 문장이 다른 쪽/장에 있을 때 출처가 섞이지 않는다. 수정 전 원본 인용과 학습용 수정 문장도 구분된다.
5. 첨부 교체·삭제 목록 이동 후 과거 구간은 보관된 첨부를 연다. 권한이 없으면 해당 파일을 표시하지 않는다.
6. 세로쓰기·다단·스캔·빈 쪽·결합 악센트·이모지·요미가 포함된 입력에서 선택·복귀의 한계를 정확히 표시한다.
7. 320/390/768/1280px, 200% 확대, 키보드에서 가로 넘침·선택 핸들 충돌·포커스 유실을 확인한다. 모바일 Chromium 에뮬레이션만으로 iOS Safari 검수 완료라 하지 않는다.
8. 원본 읽기 위치, 구간 읽기 완료, 표현의 FSRS 일정은 서로 독립임을 확인한다. 비소유자·비로그인 접근은 차단한다.
9. 대상 테스트·기존 작성/수정/서재/표현 회귀·빌드를 실행하고 검토 가능한 PR과 미리보기를 준비한다. 실제 검수에 사용하지 않은 문서 유형을 통과했다고 보고하지 않는다.

승인 후 구현할 제품 방향은 이 문서의 첫 완료 범위다. 현재 선택 UX·언어 기본값·서재 묶음에는 추가로 사용자 결정을 요청할 사항이 없다. PDF의 복잡한 조판은 지원 한계를 드러내는 보조 경로까지 포함해 검수하며, 자동 OCR 확대는 별도로 판단한다.


## 12. 구현 계약과 검수 기록
