# 개인 노트 충돌 복구 — 2026-09-27

## 문제와 처리

실계정의 개인 노트를 두 창에서 수정한 검수에서, 충돌 후 `최신 판 열기`를
눌러도 Codex IAB의 현재 초안과 오류 표시가 그대로 남았다. 개인 노트 어댑터에
명시적인 reload가 없어 공통 Canvas가 브라우저 새로고침으로 떨어지는 경로였다.
이 결과를 다른 브라우저 전체의 실패로 일반화하지 않는다.

버튼을 `초안 보관 후 최신 판 열기`로 바꿨다. 현재 계정의 원본 읽기 권한을
확인하고, 전체 초안을 기존 기기 복구 저장소와 비공개 새 노트에 보관한다.
사본의 제목·필기·페이지·정리 후보·독음·뜻·선택 상태·저장 어휘 연결·출처가
일치하는지 확인한 후 최신 원본을 다시 읽어 편집기를 교체한다. 같은 노트 주소에
머무르며, 성공 안내와 노트 정보의 `보관한 초안 열기`에서 사본을 다시 볼 수 있다.

- 원본을 PUT하지 않으며 최신 원격 변경을 덮지 않는다.
- 기존 개인 노트 POST의 소유자+importAttempt 멱등성을 재사용한다. 응답 유실과
  반복 클릭/재시도에도 같은 초안의 사본을 중복 생성하지 않는다.
- 보관 또는 최신 판 조회가 실패하면 현재 초안과 확인된 사본 링크를 유지한다.
- 복구 중 추가 입력/지연된 필기 변경이 있으면 전환을 중단한다. 다른 창의
  로컬 변경도 기존 복구 저장소에 남기며 CAS 충돌 시 덮어쓰지 않는다.
- 닫힌 노트/변경된 계정의 늦은 응답을 적용하지 않는다. 401/403/404인 원본은
  오프라인 캐시로 부활시키거나 새 사본으로 전송하지 않는다.
- 복구 중 필기면은 보기 모드이며 완료 후 노트 정보 버튼으로 키보드 초점을 돌린다.

기존 IndexedDB/CAS·노트 API·Excalidraw를 재사용했다. 별도 저장 체계·의존성·DB
마이그레이션은 필요하지 않았다. 일반 수업 판의 최신 판 열기 경로는 유지한다.
개인 뜻/FSRS, 운영 병합, DB/env/Auth 설정, 공개 교재 포인터와 alias 변경은 제외한다.

  권한 거절/진행 중 추가 입력/지연된 필기 flush/다른 창의 로컬 변경/종료된 세션/

  원본 재접속 경로를 추가했다. 합성 Auth/HTTP와 일회용 PostgreSQL을 사용한다.
