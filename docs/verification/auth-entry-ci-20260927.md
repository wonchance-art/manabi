# 로그인 복귀의 정기 검수 연결

2026-09-27 KST. 개인 노트 로그인 수정의 최종 리뷰에서 선정한 독립 후속이다.

## 문제와 적용

기존 `auth-entry.e2e.mjs`는 수업·단어장·개인 노트의 로그인 목적지를 검사하지만
별도 실행만 가능했다. 출시 검사에서 빠지면 내부 로그인 링크의 query/hash 누락이
다시 발생해도 통합 CI가 통과할 수 있었다.

기존 QA 실행기에 `qa:auth-entry`를 연결했다. Chromium과 WebKit이 수업·단어장·
일반 노트·정리 목록·특정 표현·새 노트를 각각 1440/390px에서 검사한다. 정리 상태,
표현이 있던 판, 중국어/교재 설정, 키보드 진입, 이메일 복귀와 Google PKCE 요청의
목적지를 확인한다. 로그인만으로 노트/단어를 만들지 않는지도 유지한다.

`qa:release`와 기존 CI는 이 두 단계를 포함해 총16단계를 실행한다. 새 워크플로,
별도 검수 프레임워크, 예약 실행은 만들지 않는다. 기존 Playwright 고정 버전,
`qa-runtime`의 브라우저 시작·종료·실패 trace와 `qa-state`의 증거 검증을 재사용한다.
macOS Google Chrome 경로에 고정됐던 실행을 공통 브라우저 경로로 바꿔 Linux CI와
일치시켰다. 이전 단독 실행의 `QA_ENGINE`은 호환하되 프로필의 `QA_BROWSER`를 우선한다.

수업·단어장·노트·화면 네 필수 그룹, 종료 완료, 프로세스 성공과 오류0을 모두
충족해야 성공이다. 일부 그룹 누락·실패·변조된 보고서·다른 입력은 재사용하지 않는다.
브라우저 시작 실패도 보고서에 남기고 실패로 종료한다.

## 검수와 증거

- 계약 검사: 필수 두 브라우저/네 그룹, 불완전·실패·변조 결과와 입력 변경 시 재사용 거절.
- 전체 단위441파일 4,686 PASS/기존1skip. 변경 실행기·브라우저 검사·계약 lint와 diff 통과.
- 의도적인 잘못된 브라우저 실행: `unknown_qa_browser`, exit1, 그룹0, 종료 완료 기록.
  이를 성공 증거로 수용하지 않는 것을 확인했다. 정상 실행 수치에는 포함하지 않는다.
- 새로운 합성 빌드에서 프로필의 Chromium/WebKit 각각36항목 PASS, 네 그룹 충족,
  오류0·종료 완료. 모바일 새 노트 화면도 직접 확인했다. 중국어 선택/교재 연결은
  유지되며 제목 예시의 일본어 고정은 이미 기록한 후속 항목으로 남긴다.
- 최종 프로필 실행·동일 입력 재개·CI의 결과와 정확한 후보는 PR #1321, 이슈 #150의
  인계 및 `.qa/closeouts/auth-entry-ci-20260927`에 기록한다. 새 입력 지문에 맞춰
  빌드한 합성 환경을 사용하며 실계정 로그인으로 세지 않는다.

## 범위와 다음 방향

제품 UI·노트 본문·계정 권한·개인 뜻·FSRS·교재 파일/판본과 운영 DB/env/Auth 설정은
변경하지 않는다. 실행되는 앱 코드는 기존 Preview와 같아 이 검수 연결만으로 재배포나
재로그인을 요구하지 않는다. 기존 실제 Google Preview 복귀 문제를 해결한 것으로
표시하지 않는다. 실제 교사/별도 학생/개인 노트 복구와 물리 기기 확인은 남아 있다.

이번 결과의 핵심은 이미 발견한 결함을 지속적으로 검사하는 것이다. 다음 독립 개선
후보는 앞서 확인한 새 노트 제목 예시의 언어 고정이다. 선택 언어와 예시가 일치하되
작성한 제목은 유지하는 것이 완료 조건이다. 실제 계정 출시 검수는 정상 Preview 로그인과
기존 관리자 접근 승인 조건이 해소되면 이어간다. 운영 출시와 N5 새 판본 발행은 구별한다.
