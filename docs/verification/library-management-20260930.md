## 보존 및 권한 검토

개인 상태는 정본 키만 참조한다. 새 문서 본문·토큰·파일 사본을 만들지 않는다. 새 상태의 created_at은 고정하고 정리로 원본 작성 시각을 대체하지 않는다. 늦은 열람 갱신은 상태를 복원하지 않는다. 원문 접근 권한을 잃은 행은 일반 이름만 보여주고 본인 참조를 휴지통으로 옮길 수 있다. 복원은 현재 원문 권한을 다시 검사한다.

새 공개 테이블에는 owner RLS와 명시적 grants를 둔다. 작업 manifest는 비공개 `library_private` 스키마, invoker 함수, owner RLS를 함께 사용한다. 이 스키마를 Data API의 exposed schemas에 추가하지 않는다. public RPC는 anon/PUBLIC 실행을 회수한다. 브라우저 관리자 우회나 service role은 없다.

폴더를 삭제해도 기존 membership-only 공개 자료와 판본 참조는 전체/미분류에 남는다. 기존 권한을 가진 서버의 계정 제거 cascade는 유지하며, authenticated 클라이언트의 원본 삭제는 거절한다.

정리 작업과 레거시 membership 쓰기는 같은 owner transaction advisory lock 및 revision 경계를 사용한다. 재접속에는 요청 ID와 실행/취소 방향만 보관한다. undo는 해당 작업의 최소 필드/소속 변경만 역적용하며 이후 변경이 있으면 충돌로 남는다. 서버 선택 결과를 고정해 새 유입 자료를 포함하지 않고, 한 호출에서 최대 100개만 처리한다. 전체 5,000개 한도를 초과하면 거절하며 조용히 잘라내지 않는다.

- 131개 manifest: 100+31 분할 적용, 응답 유실 후 동일 결과, 이후 유입 자료 제외, 100+31 undo 확인.
- 3,000개 선택·prepare·첫 100개 적용: 로컬 1,466ms, 결과 JSON 242,772 bytes. 로컬 단일 실행의 관찰값이며 운영 처리량 보장 아님. 5,001개 선택 거절 확인.
- 오래된 DB DELETE 거절, PDF 원본/썸네일 보존과 미참조 파일 정리 허용 확인.
- 단위 집중 51개 통과. 최초 전체 4,348개 중 기존 오류 안내 문자열 누락 1개 실패 → 실제 안내를 복원해 해당 10개 재검수 통과. 최종 전체 결과는 아래 마무리에서 구분한다.
- JSX 명시 검사 오류/경고 0. 전체 lint 오류 0 / 기존 학습 모듈 경고 2.
- 최초 빌드는 기본 Node heap 한도로 OOM/SIGABRT. 로컬 재시도만 `NODE_OPTIONS=--max-old-space-size=4096` 사용. 앱 설정/운영 env 변경 없음.
- 첫 브라우저 검수: 폴더/이동/휴지통/복원 및 65개 전체 결과 선택·응답 유실 후 재연결 통과. 세 번째 흐름은 즐겨찾기 동명 버튼 선택자에서 실패해 dialog/위치 탐색으로 범위를 좁혔다. 최종 재검수는 아래 마무리에서 구분한다.
- 실행 취소 중 응답 유실 뒤 새로고침하면 취소 방향이 사라질 수 있는 반례를 보완했다. 기존 폴더만 참조하던 자료의 폴더 삭제 후 유지, 검색된 책 하위 글로 바로 가기, 서버 계정 제거 cascade도 최종 SQL 검수에 포함했다.
- 첫 4GiB 빌드 통과(5.5분 compile). 최종 코드 빌드와 전체 단위 검사를 병렬로 실행한 검수는 기존 studiesRefs 대형 hook 60초 초과가 발생해 그 테스트 실행을 중단했다. 앱이나 기존 테스트 timeout을 바꾸지 않고 순차 재실행한다.
- 최종 브라우저/전체 검사/빌드: 진행 중. 통과로 선기록하지 않음.

## 도입·복원 경계

1. 최종 로컬 후보/SQL/브라우저를 검수하고 draft PR로 인계한다.
2. 외부 DB 적용, Preview/운영 배포·병합은 새 기능의 해당 대상·범위 승인을 따른다. 과거 N5 승인으로 실행하지 않는다.
3. 추가형 migration을 먼저 검수·적용하고 코드와 계속 쓸 QA 주소를 같은 계약으로 맞춘다. 기존 UI는 catalog에서 휴지통을 숨기고 hard DELETE를 거절하지만 새 복원 UI가 없으므로 오래된 Preview를 계속 사용하는 호환 완료로 보지 않는다.
4. 새 스키마 미지원 시 새 쓰기를 실패로 알린다. 원본 DELETE로 fallback하지 않는다.
5. 복원은 새 상태를 읽는 호환 배포로 한다. 새 테이블/폴더 상태를 없애거나 상태를 무시하는 구버전으로 돌리지 않는다.

## 남은 한계

실제 Supabase 적용/advisors, 다중 DB 연결 경쟁, 실계정·실제 기기, 운영 동작은 미검수다. PGlite는 실제 PostgreSQL 쿼리/RLS를 실행하지만 네트워크·운영 설정·동시 다중 연결을 증명하지 않는다. synthetic 브라우저 계정을 실제 로그인으로 계산하지 않는다. 영구 원본 삭제 버튼은 제공하지 않는다. 휴지통은 저장 공간을 비우지 않으며 자동 비우기도 없다.
