## 이어서 실행할 순서

1. 최종 통합 head의 CI, main과의 충돌·소스 동일성, 실제 배포 버전을 재확인한다.
2. 정상 교사/학생의 분리된 계정으로 설명판 저장·재접속 → 수업 표현 → 학생 원본 → 뜻/독음 → 직접 단어 저장 → 복습·같은 출처 복귀를 검수한다. 개인 노트 후보 누적·선택 저장·재접속도 확인한다. 기존 수업을 임의 시험 데이터로 쓰지 않는다.
3. 물리 iPad/Pencil·소프트 키보드·회전·교실 네트워크는 자동 WebKit 결과와 구별해 기록한다. 필수 조건을 통과시키기 위해 미실행을 성공으로 바꾸지 않는다.
4. 승인된 통합 범위의 출시 검수 충족 후 #1321의 최신 head를 지정해 main에 병합한다. 자동 운영 배포의 실제 merge SHA·환경·배포 ID·핵심 동선을 확인한다. 기존 공개 N5는 그동안7f를 유지한다.
5. 새 N5 공개는 별도 발행 범위에서 진행한다. 운영과 계속 사용하는 고정 QA에12d 파일이 모두 있는지 먼저 확인하고, 최신 초안/공개 version을 대조한 뒤 공개 포인터를 전환한다.

## 복구 조건

운영 main과 이전 고정 QA 코드에는12d 파일이 없다. 따라서 미리보기에서 공유 DB의 공개 포인터를 먼저12d로 바꾸면 운영 교재가 열리지 않을 수 있다. **웹 배포가 먼저, 교재 발행이 나중**이다.

새 판본 발행 후 내용 문제가 생기면 새 코드를 유지하고 공개 포인터를7f로 복원한다.12d 발행 기록·출력 파일과 그 판본에 저장한 표현의 출처는 계속 제공한다. 코드까지 되돌려야 한다면 모든 발행 판본과 새 저장 계약을 지원하는 호환 배포가 필요하다. 과거 운영 배포로 무조건 rollback하거나 DB/Storage를 삭제하는 방식은 쓰지 않는다.
