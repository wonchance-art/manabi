## 승인 요청 규약

AGENTS.md·CLAUDE.md·quality-workflow.md의 '오너 수동' 실행 제한을 정정했다.
사용자가 구체적으로 승인한 대상과 변경 범위는 실행·재개·검수·마무리마다 다시 승인받지 않는다.
검수·시크릿 보호·다른 작업 보존·병합 조건은 유지한다.

포괄적으로 미래 운영 변경을 자동 허용하는 첫 문안은 자동 승인 검토에서 거절됐다.
그 문안은 적용하지 않았다. 반영한 문안은 **유효한 기존 승인에 대한 중복 요청 금지**이며,
승인되지 않은 별도 대상/범위의 운영 변경을 허용하지 않는다.

## 실제 계정 검수

기존 로그인과 고정 QA 주소에서 새 일반 비공개 자료 하나를 만들었다. 본문은 자체 작성한
두 단어이며, 기존 발췌 자료를 새 일반 저장 경로의 증거로 잘못 사용하지 않았다.

1. A/B 두 창이 같은 내용을 연 상태에서 B가 두 번째 단어를 먼저 수정하고, 오래 열린
   A가 첫 번째 단어를 저장했다. UI와 실제 DB에서 두 수정이 함께 남고 원문은 같은 것을 확인했다.
2. A에 미저장 입력을 남기고 B가 같은 단어를 다른 뜻으로 저장했다. A의 저장 시
   최신 서버 뜻을 보여주고 입력은 유지했으며 저장 버튼은 확인 전 비활성화됐다.
3. “현재 내용 확인”만 누른 뒤 DB를 조회했다. B의 뜻이 그대로 남고 저장은 일어나지 않았다.
   키보드 초점은 저장 버튼으로 이동했다. Enter로 명시 저장한 뒤 B를 새로 열어 A의 뜻을 확인했다.
4. 충돌 안내를 직접 화면으로 확인했다. 데스크톱에서 내부 스크롤·키보드 접근·확인 버튼을
   확인했다. 브라우저 오류는 두 검수 창 모두 0이다.
5. 기존 원본/발췌 두 행과 개인 단어 전체의 전후 해시가 같고 개인 단어 수는 2개로 그대로다.
   따라서 이 검사 중 기존 개인 뜻·FSRS 값에 쓰기가 없었다. 검수 자료는 ID·제목·소유자·
   비공개 여부·원문·검수 마커를 모두 한정해 한 행만 정리했다. 기존 자료는 삭제하지 않았다.
6. 원래 발췌 자료로 복귀해 본문·원본 링크·기존 단어창을 다시 확인했다.

실제 두 브라우저 창의 순차 경합을 검수한 것이며 독립 DB 연결의 같은 순간 잠금 시간
측정은 아니다. 보조 검수 창은 viewport override가 390px 요청 뒤에도 1280px로 남아
좁은 화면의 충돌 조작을 수행하지 못했다. 활성 탭에서는 390×844가 실제 적용되어 기존
발췌의 긴 제목·단어창·하단 저장 버튼을 직접 확인했고 가로 넘침은 0px였다. override는
해제했다. 이 화면 검사와 합성 Chromium/WebKit CI를 물리 휴대폰/iPad 검수로 합산하지 않는다.

승인 중복 요청 정정만으로 통합 PR의 전체 교사/학생·물리 iPad/Pencil 검수나 운영 병합이
완료되지는 않는다. 제품 코드·기존 서체·QA 판정 기준은 이번 활성화에서 바꾸지 않았다.

## 결과 리뷰와 다음 방향

승인된 함수 활성화와 일반 뷰어 두 창의 저장 보존은 DB → 새 배포 → 실제 계정까지 확인했다.
코드가 있어도 DB가 준비되지 않은 상태를 해소했고, 이미 승인한 실행마다 다시 묻는 규약도
정정했다. 운영 웹은 전환하지 않았다. 통합 PR은 교사/학생 수업 전체·물리 iPad/Pencil 등
기존 출시 조건이 남아 draft/NOT_RELEASE_READY를 유지한다.

다음 독립 구현의 우선은 기존 N5 감사에서 선정한 42과와 긴 과의 학습 경로·누적 복습을
새 판본 초안에서 다듬는 일이다. 기존 발행본·과/문항 ID·출처를 보존하고 웹의 이어 읽기와
정답 가리기·표현 저장·복귀를 확인하는 것이 완료 조건이다. 전체 목차 재작성·PDF·음성은 제외한다.
동시에 출시 전 실계정 교사/학생과 물리 기기 검수는 별도 조건으로 남긴다.
글꼴 실패가 반복되면 같은 배포를 반복하기보다 기존 서체의 로컬 번들 방식을 검토한다.
