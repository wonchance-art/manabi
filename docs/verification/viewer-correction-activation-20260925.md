2026-09-25 KST. 오너의 “승인함. 그리고 수동 승인 요청 규칙 제거 바람”에 따른

## DB 적용 완료

- 실행 전 원격 94개와 로컬 95개 이력을 대조했다. 차이는
  `20260924114728_viewer_token_correction_atomic.sql` 한 건이며 원격 전용 이력은 없다.
- 기존 직렬화된 [Supabase Migrations 실행 36018417851](https://github.com/wonchance-art/manabi/actions/runs/36018417851)
  에서 해당 SQL만 적용했다. `Link & db push`는 SUCCESS이며 미설정 skip이 아니다.
- 적용 후 로컬/원격 이력 95개 일치. 함수 본문 MD5는 로컬/원격 모두
  `1a5dc32288e4141c1eee3ac41ead0293`이다.
- SECURITY INVOKER, 고정 search_path, authenticated 실행 허용/anon 거부를 확인했다.
  기존 자료 RLS와 trigger/policy 해시는 전후 동일하다. 보안 advisor 61개는 기존과 같으며
  새 항목 0개다. 기존 항목 전체를 이번 작업에서 해결했다고 주장하지 않는다.
- `scripts/verification/viewer-token-correction.sql`을 실제 DB에서 실행했다.
  알려진 자체 검수 자료의 소유자를 내부에서 선택하고 authenticated 역할로 합성 자료만
  검사했다. 서로 다른 토큰, 동일 토큰 충돌/무변경, 명시 확인, 응답 유실, 원문 변경,
  허용 외 필드, 없는 토큰, 타 사용자/비로그인 거부 10검사 PASS. 모든 쓰기는 ROLLBACK,
  검수 행 잔존 0이다. 사용자 식별자·인증 정보는 출력하지 않았다.
- 이 SQL 검수는 실제 로그인 브라우저 검수나 원격 두 연결의 동시 잠금 측정을 대신하지 않는다.

## 승인 요청 규약

AGENTS.md·CLAUDE.md·quality-workflow.md의 '오너 수동' 실행 제한을 정정했다.
사용자가 구체적으로 승인한 대상과 변경 범위는 실행·재개·검수·마무리마다 다시 승인받지 않는다.
검수·시크릿 보호·다른 작업 보존·병합 조건은 유지한다.

포괄적으로 미래 운영 변경을 자동 허용하는 첫 문안은 자동 승인 검토에서 거절됐다.
그 문안은 적용하지 않았다. 반영한 문안은 **유효한 기존 승인에 대한 중복 요청 금지**이며,
승인되지 않은 별도 대상/범위의 운영 변경을 허용하지 않는다.
