# N5 말하기·작문 지시와 활용 도움 교정

2026-09-28 KST. 오너의 ‘설명판은 따로 남겨두고 교재부터’ 지시에 따라
설명판 추가 개선은 별도 후속으로 보존하고 N5 학습 내용부터 점검했다.
기준 후보 `8f6d1f66189502aafa146305` → 새 검토 후보 `f09e3e1faa4ee5a35b0fb2a6`.
공개 판본 `7f572327dc67893e9453246c`와 기존 판본·DB 포인터는 유지한다.

## 학습자가 겪던 문제

39·42과 별도 연습의 질문·보기·답·해설을 먼저 대조한 뒤, 일반 41과의 말하기
82개와 작문 41개의 지시·힌트·예시·자기점검을 함께 읽었다. 이번 범위에서 종합
연습 정답을 바꿀 근거는 찾지 못했다. 다만 자유롭게 자기 문장을 만드는 단계에서
힌트를 그대로 따르면 배운 활용과 어긋날 수 있는 부분을 확인했다.

| 위치 | 전과 후 |
|---|---|
| 1과 말하기 2 | 누구를 소개하는지 불분명 → 옆 사람을 선생님으로 소개한다고 명시. `せんせいです` 자체를 틀린 문장으로 판정하거나 새 호칭 규칙을 요구하지 않는다. |
| 5과 말하기 2 | 묻고 답하라고 하지만 예시는 답 한 문장 → 주어진 `だれのですか`에 응답하는 과제로 정합화. |
| 4과 작문 | 틀/예시는 `あの`인데 점검은 `この` → 실제 작성한 `あの＋명사`와 거리 조건을 확인. |
| 17과 작문 | 두 행동을 쓰는 과제의 두 번째 틀이 `も`, 예시는 `を` → 예시와 같은 두 개의 `を` 틀. `も`를 쓴 자연스러운 답을 오답 처리하지 않는다. |
| 24–27·31·32·42과 작문 | `＿＿て`·`＿＿た`를 고정 접미사로 오해할 수 있음 → `［て형］`·`［た형］` 자리에 활용한 동사 전체를 넣도록 표시. `読んで`·`読んだ`도 해당 형태라는 자기점검을 함께 제공. |

예를 들어 `＿＿てもいいですか`의 글자 틀에 `読んで`를 그대로 넣으면 형태를
중복할 수 있다. 개정 후에는 `［て형］もいいですか`에 `読んで`를 넣는다.
이는 기존 설명이 문법적으로 전부 틀렸다는 판단이 아니라, 작문 도움말의 모호성을
줄이는 편집 판단이다. 정답 예시와 문제 수를 늘리지 않는다.

### 근거와 한계

- [도쿄외국어대 て형 설명](https://www.coelang.tufs.ac.jp/mt/ja/gmod/courses/c02/lesson23/step1/explanation/043.html)은 동사 활용에 따라 `て`/`で`로 끝나는 형태와 여러 연결을 제시한다.
- [같은 대학 동사 그룹 표](https://www.coelang.tufs.ac.jp/mt/ja/gmod/courses/c02/lesson21/step2/card/039.html)는 `読む`의 て형/た형을 구별한다.
- [たり 설명](https://www.coelang.tufs.ac.jp/mt/ja/gmod/courses/c02/lesson26/step2/explanation/050.html)은 완성된 た형 뒤에 `り`를 붙이는 구조를 명시한다.

이 근거와 원고를 작성 에이전트가 대조했다. 독립 일본어 감수·실제 초보 학습자의
사용성 평가·시험 범위 충족 증거는 아니다. 39·42과 답을 유지한 것도 모든 대안
해석의 부재를 자동 증명한 결과로 취급하지 않는다.

## 구현과 보존

기존 `build-n5-copy-review.py`를 수정 없이 재사용했다. 교정 정본은
`scripts/textbook/n5-production-review.json`이다. 원고의 정확한 이전 문자열과
실제 해당 페이지 출력이 맞아야 생성하며, 18필드/11쪽만 교정한다.

- 42과/499페이지/번들 출처 ID 1,144개, 정답·보기·문항 ID·입력 키·페이지 순서 유지.
- 이전 8f·12d 등 모든 판본은 그대로 두고 관리자 후보 목록 첫 항목에 새 후보 추가.
- JS/CSS·후리가나·예문 상자·상속 음성은 그대로다. 새 음성/PDF 작업 없음.
- 브라우저 답안은 판본별로 분리. 이전 답을 새 판본으로 자동 이관하지 않는다.
- 계정 단어·개인 뜻·복습 일정·원문 출처·교재 발행 포인터를 변경하지 않는다.
- 구조 감사의 `sourceAnchors`는 페이지 별도 ID까지 포함해 번들 출처 ID 개수와 다르다.

| 재사용 검토 | 결정 |
|---|---|
| 기존 원고 교정기·본문 렌더러·정답 저장 | 그대로 채택. 새로운 학습/발행 시스템을 추가할 이유 없음. |
| 기존 교재 보존 계약·로컬 합성 역할 브라우저 검수 | 새 후보를 넣어 사용. 실제 로그인 증거와 구분. |
| 외부 문제은행·추가 UI 라이브러리 | 배제. 문제 수보다 이미 있는 과제의 설명 일관성을 고치는 범위. |

`.qa/runs/n5-production-review-20260928/`)와 빌드 실행
`.qa/runs/2026-09-27T19-38-26-903Z-99254/`에 보관한다. 브라우저는 현재 제품 빌드와
로컬 fixture만 사용했다. 서버 학습 기록이나 실제 사용자 계정에는 쓰지 않았다.

최초 새 보존 검사에서는 실제 탐색 링크와 새 판본 CSS 주소를 같은 것으로 비교해
실패했다. 탐색 링크와 자산 주소를 구분해 검사하도록 고쳤고, 실패한 실행을 통과로
재분류하지 않는다. 최초 로컬 브라우저 실행의 포트 bind는 sandbox EPERM으로
중단되었으며, 로컬 실행 권한으로 재시도해 위 결과를 얻었다. 임의 테스트 생략이나
제품 권한 우회는 없었다. 빌드가 자동 생성한 서비스워커 해시 변경은 제외했다.

미리보기 배포와 PR의 최종 head·검사 결과는 #1321/#150 최종 인계 및 로컬 closeout에
기록한다. 이 문서의 자동/합성 검수 통과가 운영 출시 또는 새 판본 발행은 아니다.

## 로드맵과 다음 방향

이번에 닫는 조건은 ‘생산 연습의 지시·힌트·점검 기준이 학습한 활용 및 예시와
서로 맞는다’는 것이다. 웹 출시·새 교재 발행·청해 완성을 의미하지 않는다.
다음 교재 작업은 **초급 첫 12과의 학습 부담과 선행 어휘 점검**을 우선한다.
문자 준비 직후 요구하는 가족 호칭·층수·수량/날짜가 설명→따라 하기→혼자 하기
순서로 연결되는지 실제 페이지를 따라 확인하고, 학습 전에 필요한 도움이 빠진
부분만 보완하는 것이 완료 조건이다. 외부 언어 감수는 별도 후속으로 유지한다.

수업/설명판의 교재 없는 팀 진입 문제와 별도 학생·물리 기기 검수는 남겨 두며,
최신 사용자 지시 전에는 다음 자동 작업으로 선정하지 않는다. 운영 웹 출시의
기존 조건 역시 삭제하지 않는다. 새 판본 발행은 운영에 해당 파일이 존재한 후
별도 기존 승인/완료 조건을 확인하는 단계다.
