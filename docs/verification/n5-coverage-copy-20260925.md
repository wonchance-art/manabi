## 추가 글을 독립 전이로 세지 않은 구체적인 이유

`u42-text-plus`의 안내는 장소 지시·명사 앞 표현·어제/지금/내일을 먼저 짚는다.

- `wp-text-1`: cue가 ‘앞에서 나온 ほんや’를 받으라고 알려 준다. 보기 それ/その/そこ/どの 중 `で` 앞에서 장소가 되는 것은 そこ라서 앞선 글의 실제 사건을 읽지 않아도 상당 부분 해결된다.
- `wp-text-2`: cue가 뒤의 명사 ほん을 강조한다. 보기 それ/そこ/どれ/その 중 명사 앞 형식은 その다. 내용 연결보다 형식 구분이 답을 결정한다.
- `wp-text-3`: cue와 제목이 내일 계획/희망을 알려 주며, つくりたいです 외 세 보기는 모두 과거다. あした만으로 후보를 좁힐 수 있다.

세 문제의 정답이 틀렸다는 뜻은 아니다. 현재 목적에 맞는 안내 연습이다. ‘글 전체를 읽어 판단하는 새 연습까지 확보됨’으로 평가하는 것이 부정확하므로 완료 조건을 나눴다.36과 A/B는 스스로 읽는 대표로 남지만 모두 연결어 구분에 집중된다.

## 다음 한 작업의 설계와 완료 조건

**42과에 도움 없는 글 속 문법 전이 한 묶음**을 기존 연습 렌더러로 추가한다. 앞의 안내형3문항은 그대로 두고 다음 위치에 연결한다. 새 문제/저장 키를 사용하며 기존 답안을 이식하지 않는다.

- 학습 상황: 이미 배운 학교·약속·준비물 등의 일상 장면. 처음 만나는 비핵심 어휘만 중립적인 뜻 도움으로 안내한다. 풀이 유형·완성 번역·정답을 정하는 cue는 앞에 노출하지 않는다.
- 한 덩어리 글의 앞뒤 내용으로 지시 대상, 시간/계획 변화, 문장 관계를 판단한다. 접속어만 채우는 단문3개로 분해하지 않는다.
- 보기는 먼저 해당 빈칸에 문법적으로 들어갈 수 있는지 확인한다. 문법 오류 때문에 지문을 읽지 않고 제거되는 보기만으로 구성하지 않는다. 문맥으로 유일하게 결정되고 다른 자연스러운 해석도 검토해야 한다.
- 해설은 정답 근거가 되는 실제 문장과 각 오답이 글의 어떤 정보에 어긋나는지 보여 준다. 정답형태 설명만 반복하지 않는다.
- 검수 완료 조건: 독립 자력 풀이의 반례 검토, 한국어 질문/보기/후리가나에 정답 노출 없음, 기존/신규 답안 분리·새로고침·설명 복귀, 좁은 화면·키보드·실제 교재 서체 확인. 이는 합격률·전체 문제량 충족 판정이 아니다.

그다음은 서로 다른 형식의 짧은 글/안내 전이, 이어 문맥 어휘·의역·혼합 표기를 검토한다. 출제 비중을 근거 없이 가정하여 횟수를 할당하지 않는다. 독립 감수/실학습자·청해는 계속 별도다.

## 검수 중 수정한 점·한계

- 첫 빌드는 로컬 Node 기본 heap 한도에서 실패했다. 검수 프로세스만8192MiB 한도로 실행해
  제품 빌드를 완료했다. 운영/원격 환경 변수를 변경하지 않았다.
- 최초 브라우저 검사는 앱 책 홈에서 패키지 cover ID를 찾으려다 실패했다. 검수 대상을
  분리한 뒤 **두 브라우저 전체를 다시 실행해** 정상 종료까지 확인했다. 제품 결함으로
  판정하거나 실패를 제외한 합계로 보고하지 않는다.
- 글자 수는 선택지/공백 제외,문장부호/제목/숫자/빈칸 포함 자체 집계다. 문장 자연스러움,
  오답의 유일성,학습 효과를 자동 검사만으로 인증하지 않는다.
- 로컬 합성 계정은 실제 원격 관리자·학생,실제 DB,물리 iPad 검수를 대신하지 않는다.
- 운영 발행·DB/env·merge·PDF·새 음성은 범위 밖이며 현재 published pointer는 원본이다.

로컬 증거는 `.qa/n5-coverage-copy/`. 최종11개 구현/검수 입력의 해시를 고정하고 문서·보드만
갱신한 최종 커밋과 다시 대조한다. 원격 CI·별도 Preview READY·공개 버전·접근 차단은 최종
커밋 후 확인하며 **최신40자 head와 원격 결과는 PR #1324/#150 CODEX_DONE 인계가 정본**이다.
`qa:closeout`에는 최종 재검수·반례·다음 방향을 기록한다.
