# 실제 뷰어 전용 자동 검수 · 2026-09-24 KST

## 목적과 구현

뷰어의 회귀를 찾으려면 이전에는 긴 수업 설명판 동선을 먼저 완료해야 했다. 기존
`verifyPersonalReaderDesign`과 Auth/HTTP/PGlite 준비를 그대로 재사용하되 실제 뷰어를
독립된 검사로 실행한다. 새 UI 하니스나 검수용 제품 분기는 만들지 않는다.

- `qa:reader-app`: 실제 ViewerPage의 단어창, Aa 키보드/집중, 200% 확대,
  자료 한정 뜻 저장/실패 재시도/새로고침/본문 초점 복귀. Chromium·WebKit.
- `qa:reader`: 위 2단계 + 기존 컴포넌트 6단계.
- `qa:classroom`: SQL + 실제 뷰어 + 기존 교사/학생 동선. 원래 범위 유지.
- `qa:release`: SQL → 실제 뷰어 → 컴포넌트 → 수업 → 노트. 전체 14단계,
  실제 뷰어 중복 실행 없음. 단계별 필수 그룹·정리·브라우저·재개 검증 유지.

뜻 선택만으로 저장하지 않고, 저장 결과 행이 없으면 실패를 표시하며 후보를 유지한다.
재시도 후 일회용 DB 전체 자료/개인 단어장의 전후 비교로 지정 토큰 하나만 바뀌었는지
검사한다. 원문·다른 출현 위치·다른 자료·병음·메타데이터·개인 뜻·SRS 보존을 확인한다.
공유 사전/개인 단어장 쓰기는 허용하지 않고 자료 교정 이력만 허용한다.

## 선례와 선택

| 대상 | 선택 | 이유 |
|---|---|---|
| 기존 실제 뷰어 검수 함수·수업 준비 코드 | 재사용 | 동일 UI/저장 경로를 검사하고 중복 하니스 방지 |

## 검증 결과

- 1차: 두 엔진에서 기존 화면 기준·접근성·Aa/집중/200% 확대 통과. 이어진 저장
  검사에서 집중 설정이 남아 첫 키 입력이 문장 선택으로 처리되어 실패했다.
  실제 Aa 설정으로 저장 검사의 시작 상태를 명시하고, 기존 집중 검사는 유지했다.
- 검수 프로필/증거 계약 3파일·12개 및 변경 파일 lint/diff 검사 통과.
- 로컬 빌드와 전체 단위 검사를 동시 실행할 때 메모리 여유가 적어 전체 단위 검사는
  중단했다. 이 실행을 통과로 세지 않는다. 필수 전체 단위 검사는 최종 원격 CI로 확인한다.
- 2차: 두 엔진에서 저장/실패 재시도/토큰 한정 DB 비교까지 통과했으나 최근 읽기
  기록을 부수 변경으로 잘못 판정했다. 실제 `reading_progress` 및
  `library_reading_activity`의 계정·자료·허용 필드를 확인하도록 수정했다.
  공유 사전/개인 뜻·SRS 쓰기와 다른 API 변경 요청은 계속 거부한다.
- 보완한 실제 UI 검사는 Chromium/WebKit 각각 8개 체크, 화면 기준 비교 3개씩,
  브라우저 오류 0, DB/브라우저 정리 통과. 코드가 동일한 직전 합성 앱 빌드를 재사용한
  로컬 점검이며, 실행 기록은 `.qa/runs/reader-debug-20260924/`다. 이를 최종
  프로필 실행이나 새 전체 빌드 통과로 바꾸어 표기하지 않는다.
- 휴대폰 단어창·Aa 설정·데스크톱 저장 결과 화면을 직접 검토했다. 제품 코드/DB/공개 자산 차이는 0이다. macOS 시각 기준은 그대로 유지했다.
- 1차 원격 CI35989323158: 새 빌드·429파일4,584단위(기존1 skip)·통합13/14 통과.
  Linux Chromium 단어창의 재생 문자기호만 50픽셀 차이로 실패했다. 원본/결과/차이
  이미지를 직접 확인했고, 374×440 크기와 주변 픽셀은 동일하며 원시 차이125픽셀도
  x324–338/y111–128의 기호 내부에만 있었다. 정확한 폰트 래스터화 원인은 확정하지
  않았다. 안정화/접근성 통과와 기호 가독성을 검토해 **독립 첫 진입 기준1장만 명시 승인**했다.
  비교 허용치20·변화 검출 canary·나머지 기준은 그대로이며 새 전체 CI를 다시 요구한다.
- 최종 커밋의 새 빌드·전체 단위 검사·14단계·동일 증거 재개는
  [PR #1321 검사](https://github.com/wonchance-art/manabi/pull/1321/checks)와 해당 head의
  #150 완료 기록이 정본이다. 최종 재검수/결과 리뷰/다음 방향은 로컬
  `qa:closeout reader-app-20260924`에 고정한다.

## 범위와 한계

이번 변경은 검수 코드·실행 항목·문서뿐이다. 제품 UI/저장 구현, 운영 DB/env/alias,
실제 계정·개인 자료를 변경하지 않는다. HTTP/Auth는 합성, 화면은 실제 ViewerPage,
저장은 일회용 PostgreSQL이다. 이 결과를 실계정·운영 RLS·실제 AI 의미 감수 또는
물리 iPad/Pencil 통과로 합산하지 않는다. 기존 전체 JSON 저장의 동시 수정 경합은
본 검사가 해결하거나 증명하는 범위가 아니며 별도 개선 후보로 남긴다.

## 결과 리뷰와 다음 방향

개인 뷰어 문제를 수업 전체 동선 완료 전에 독립적으로 재현할 수 있다. 실제 설정의
문장 우선 동작, 최근 읽기 기록처럼 정상적인 부수 동작도 검수 모델에 포함해야 한다는
점을 확인했다. 제품 변경으로 검사 상태 문제를 숨기지 않았다. 독립 시나리오의 Linux 기준1장은 위 근거와 정확한 해시로 별도 검토했으며 허용치를 낮추지 않았다.

다음 권장안은 legacy 자료의 동시 뜻 수정 보호다. 전체 분석 JSON을 보내는 현재 방식은
두 창이 서로 다른 표현을 수정해도 앞선 수정을 덮을 여지가 있다. 서버의 기존 값 비교와
토큰 단위 반영, 충돌 시 후보 유지/재확인을 설계하고 두 클라이언트 검수를 추가하는 것이
완료 조건이다. 이는 **후속 제안**이며 이번 QA 변경으로 해결했다고 표시하지 않는다.
교사/학생 실계정·독립 의미 감수·물리 iPad/Pencil은 통합 출시의 별도 확인으로 남는다.
