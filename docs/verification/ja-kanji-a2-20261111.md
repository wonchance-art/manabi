## 영향 (운영 읽기 전용)

- **원문 해시에 걸리는 자리:** raw_text 해시(sourceRevision)에 걸리는 문맥(vocabulary_contexts)이 0행이다.
- **그 밖의 기록:** 읽던 위치 · 책갈피 · 오늘의 소식 · 토큰 보정 · 이 자료에서 저장한 단어 모두 0이다.
- **읽기 진행:** 1행뿐이다(#45 · 가나 구간 · last_token_idx 0 · 완독). 바뀌는 첫 자리는 18이라 영향이 없다. 사전 검사가 이 조건을 강제한다.
- **저장 단어:** 일본어 단어장 27행 중 지금 N5 가나 토큰과 맞는 행이 0이라, 「저장됨/아는 말」이 끊기는 행이 없다.
- **복습 기록:** FSRS 카드는 단어장 행 id로 이어져 영향이 없다. review_events의 가나 item_key는 단어장 word_text로 잇는 구조라 자료 토큰 변경과 무관하다.
- **이어짐:** 자연 표기 134어 중 131어는 운영 분석기가 한자 표기에서 같은 표제어를 낸다. 그래서 뒤 과 한자 본문과 bases로 이어진다.
  - 예외 3어는 합성어 분할이다: 誕生日 → 誕生 + 日, 朝御飯 · 昼御飯 → 朝/昼 + ご飯.
  - 이 3어는 별도 과제다.

## 적용 경로 · 확인

- **경로:** main 병합 → supabase-migrations.yml(db push), 한 트랜잭션.
- **사전 검사:** 아래 중 하나라도 어긋나면 아무것도 바꾸지 않는다.
  - 자료별 개수가 위 표와 같다.
  - 보정 key의 옛 문자열이 같다.
  - 어간 불일치가 0이다.
  - 학습 기록이 0이다.
- **사후 검사:** 토큰 이음 = 원문 · 대상 밖 자료 md5 · 학습 계약 지문 넷.
- **크론:** difficulty는 비워 둔다. 다음 분석 작업 크론이 다시 센다.
- **적용 뒤 확인(SELECT):**
  - 백업 25행
  - 전환 14편 raw_text
  - 남은 가나 내용어
  - difficulty 다시 채워짐(다음 크론 뒤)

## 범위 밖 · 기록

- **교재 N5 10~42과:** 판본 번들은 「공개된 원고 · 출력 묶음은 바꾸지 않고 새 판본」 규칙을 따른다. 전환 경로는 WEB 세션이 조사한다. 같은 기준을 쓸 수 있도록 고정표 JSON `a2.criteria`에 기계 판독 칸을 두었다.
- **`src/lib/starter-content.js`(관리자 seed-starters):** 이미 운영 정본과 어긋나 있다(#18 제목이 다르다). 이번에는 손대지 않았다.
- **朝ご飯 카드 표제어:** 본문은 朝ご飯인데 표제어는 분석기 정본인 朝御飯이다. 카드 표제어가 朝御飯으로 보인다.
