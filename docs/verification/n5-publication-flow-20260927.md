# N5 후보 발행·학습 연결 정비

2026-09-27 KST · PR #1324 후속. 기준 c912d8930fa785d3ab9dfd17c33038ef8e2b71b2.

## 완료 경계

관리자의 최신 후보 선택 → 기존 초안 보관/명시적 교체 → 후보 확인 → 발행 후 표현 저장/원문 복귀를 연결한다.
운영 발행·병합·DB/환경 설정 변경·원고 재생성·PDF·새 음성은 포함하지 않는다.
원본 판본 7f572327dc67893e9453246c와 후보 12d69782944b95ef7a11e529의 파일은 그대로다.

## 해결한 문제

| 이전 | 변경 결과 |
|---|---|
| 관리자 편집기는 구판만 기본 후보로 제공 | 검증된 후보 목록과 선택 기능, 최신 후보 기본 선택. 실제 공개 판본은 DB 포인터로 따로 표시 |
| 후보 선택 시 기존 초안이 다른 구조일 수 있음 | 저장된 초안을 먼저 유지. JSON 내려받기 후 명시적 후보 채택, 저장 전에는 서버 초안 불변. 해시 확인과 기존 버전 비교로 충돌 방어. 미저장 편집이 있으면 후보 교체도 잠금 |
| 미발행 후보의 담은 표현·함께 읽기 링크가 404 | 관리자에게 검수 안내와 문화 글 제공, 같은 판본으로 복귀. 개인 표현 조회/자료 연결은 발행판에서만 실행 |
| 교재 내부 로그인 링크가 원문 위치를 잃음 | 판본과 문단을 로그인 복귀 주소에 포함. 예문·선택 표현·담은 표현 화면에 적용 |

`index.current`는 레거시 폴백으로 유지하고 `reviewCandidates`만 추가했다. 후보 목록은 공개 포인터가 아니다.
발행/복원은 기존 RPC와 불변 판본 계약을 재사용하며 개인 답안이나 FSRS를 새 판본으로 옮기지 않는다.

## 기존 구현·선례 채택

| 대상 | 판단/근거 |
|---|---|
| 기존 `publishedReading`, `candidate`, `bookHref`, `authEntryHref` | 채택. 같은 권한/원문 주소/로그인 복귀 계약 재사용 |
| 기존 초안/발행 RPC, PGlite, Playwright | 채택. 기존 SQL을 실제 일회용 PostgreSQL에서 실행하고 UI 실패 응답을 별도로 검수 |
| 별도 CMS·에디터·마이그레이션 | 도입하지 않음. 저장형 문항/판본/학습 출처를 그대로 보존하는 작은 연결 수정으로 해결 가능 |

Supabase 공식 [RPC](https://supabase.com/docs/reference/javascript/rpc), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [변경 기록](https://supabase.com/changelog)을 확인했다. SDK·SQL·권한 정책을 바꾸지 않고 기존 서버 계약을 사용한다.

## 검증

- 전체 단위 검사: 439파일, 4,651 PASS, 기존 1 SKIP.
- 관련 검사: 4파일, 28 PASS. 신규 5개 시나리오는 실제 일회용 PostgreSQL에 기존 마이그레이션을 적용했다.
- 발행 전 관리자/일반회원 구분 → 초안 교체 확인/오래된 버전 거부 → 새 후보 발행 → 표현 저장/중복/뜻 충돌 → 정확한 출처 → 구판 복원. 기존 단어 행(뜻·복습 시각·stability/difficulty/reps) 보존과 두 판본 불변을 확인했다.
- 회귀 검출: 후보 목록을 변경 전 상태로 잠시 되돌린 검사에서 최신 후보 기대값이 실패했고, 원상 복구 후 관련 검사 통과.
- lint 및 변경 공백 검사 통과.
- 첫 로컬 빌드는 기본 2GiB 힙 한도로 중단했다. 저장소 검수 프로필의 6GiB 설정으로 재실행해 480페이지 빌드 통과. 실제 Google 서체 다운로드의 연결 재시도가 있었고, 대역 서체를 쓰지 않았다. 첫 실패 로그를 보존했다.

- Chromium/WebKit 각 3개 동선 묶음·7개 화면 배치(1440/390/320px), 가로 넘침0·실행 오류0. 실제 앱에서 후보 메뉴/문화 글 왕복, 후보 변경과 503 실패 시 초안 유지, 내려받기 JSON 원본 일치, Enter로 후보 채택, 저장409 후 입력 유지/재시도, 게스트의 판본+문단 로그인 복귀 주소를 확인했다.
- 첫 UI 검사의 라벨 선택 오류와 화면 활성화 전 중복/클릭 타이밍 오류를 수정했다. 초기 재실행도 실패했으며 결과를 합산하지 않았다. 최종 검사는 두 엔진을 처음부터 끝까지 새로 실행하여 통과했다. 앱 코드를 우회하거나 로그인 권한을 확장하지 않았다.
- 최종 코드 재검토에서 백업 후 미저장 입력을 후보 채택으로 잃는 경로를 발견했다. 이전 실행본에 새 검사를 적용해 교체 버튼 활성 상태가 실패하는 것을 재현하고, 미저장 상태에서는 교체를 막는 UI/함수 보호를 추가했다. 같은 후보를 채택한 뒤 추가 편집을 초기화하는 재클릭도 막는다. 보강 후 전체4651PASS/기존1skip·두 엔진 전체 동선·실서체480페이지 빌드를 다시 통과했다. WebKit 후속 검사의 새 페이지 초기화 대기도 보완한 뒤 전체 재실행했다.
- Codex 직접 화면에서 관리자 판본 전환·담은 표현 안내·문화 읽기·31과 복귀를 확인했다. 넓은 관리자 화면과 390/320px WebKit/Chromium 캡처를 직접 검토했다.

## 증거 수준과 남은 범위

로컬 PostgreSQL은 SQL/RLS/RPC 동작을, 합성 인증/HTTP의 실제 앱은 화면 동작을 검증한다.
실제 Supabase 계정의 발행이나 OAuth 복귀, 물리 iPad, 독립 일본어 감수를 완료했다는 뜻이 아니다.
운영 교재는 이 작업으로 교체하지 않는다. 최종 exact head/Preview/CI는 PR #1324와 #150의 인계 기록을 따른다.

## 결과 리뷰·다음 방향

현재 누적 원고를 더 늘리기보다 발행을 준비하는 동선을 복구하는 것이 우선이었다.
다음 우선순위는 **실제 관리자 계정으로 후보·저장 초안을 대조하고 발행 준비 상태를 확인**하는 것이다.
완료 조건: 원격 최신 실행본에서 후보 선택/기존 초안 보존/검수 링크/OAuth 원문 복귀가 확인되고,
공개 발행에 남은 의미 감수·실기기·승인 범위가 구분되어 있어야 한다. 실제 발행은 별도 권한 범위를 확인한다.
독립 언어 감수와 물리 기기 확인은 검토자/기기가 필요하며, 추가 원고 확장보다 이 검증이 먼저다.

최종 로컬 빌드는 6GiB 힙과 글꼴 다운로드 최대8연결로 실행했다(로컬 실행 옵션만 조정). 실제 Google CSS/글꼴을 사용했으며 대역 응답·서체 교체·배포 설정 변경은 없다.
