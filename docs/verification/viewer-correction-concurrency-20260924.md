# 뷰어 자료 교정: 두 창의 수정 보존

2026-09-24 KST. PR #1321의 일반 자료 교정 후속. 별도 발췌 자료의 기존 RPC,
원본/판본/출처, 개인 단어의 뜻·FSRS와 공개 사전 기본 동작은 유지한다.

## 문제와 동작

이전 일반 뷰어는 클라이언트가 들고 있던 `processed_json` 전체를 저장했다.
두 창이 같은 자료를 읽은 뒤 서로 다른 단어를 고치면 마지막 요청이 앞선 교정을
덮을 수 있었다. 새 경로는 **서버에서 현재 자료를 잠깐 잠그고 선택 토큰만 비교·갱신**한다.

- 서로 다른 토큰: 두 교정을 모두 남긴다. 서버의 나머지 분석·메타데이터를 보존한다.
- 같은 토큰: 최신 뜻·발음·품사를 보여주고 입력/선택은 유지한다. “현재 내용 확인”은
  저장하지 않는다. 확인 후 저장 버튼으로 초점을 옮기고 명시적으로 저장해야 반영한다.
- 응답 유실: 서버 값이 이미 요청한 결과와 같으면 다시 쓰지 않고 현재 자료를 돌려준다.
  그 사이 다른 값으로 바뀌었으면 자동 덮어쓰기 대신 다시 충돌을 알린다.
- 실패/미적용 RPC: 입력을 유지한다. 예전 전체 JSON 쓰기로 우회하지 않는다.
- 늦은 수동 저장 응답: 다른 계정/자료에서 전역 승격하거나 다른 단어의 편집창을 닫지 않는다.
- 직접 입력과 사전/문맥 후보 선택이 같은 서버 비교 저장을 사용한다. 전역 적용은
  기존 체크박스를 명시 선택한 경우, 자료 저장이 성공한 다음에만 수행한다.

## 구현과 기존 부품 선택

| 대상 | 선택 | 근거 |
|---|---|---|
| PostgreSQL 행 잠금·JSONB 부분 갱신 | 채택 | 이미 사용하는 DB 트랜잭션 안에서 소유권·최신값 비교를 수행. 신규 저장 서비스 불필요 |
| 기존 source-passage 비교 RPC | 보존/선례 활용 | 발췌의 원본 보호 규약을 일반 자료용 함수로 우회하지 않음 |
| 기존 React Query·수동 편집·후보 패널 | 재사용 | 사전 조회와 개인 단어 저장의 의미를 바꾸지 않음 |
| 기존 Playwright·PGlite | 재사용 | 실제 ViewerPage 두 창과 일회용 SQL/RLS로 재현. 새 의존성 없음 |
| CRDT/자동 필드 병합 라이브러리 | 제외 | 같은 단어의 뜻·발음·품사를 임의 합치지 않고 사용자가 판단해야 함 |

마이그레이션은 `20260924114728_viewer_token_correction_atomic.sql` 한 파일이며
새 `viewer_correct_token(bigint,text,jsonb,jsonb,text)` 함수와 실행 권한만 추가한다.
`SECURITY INVOKER`, RLS, `auth.uid()` 소유권 확인을 모두 유지한다. 원문 변경,
분석 진행, 토큰 삭제/재식별, 발췌 전용 자료는 거부한다. 허용 수정은 문자열
meaning/furigana/pos뿐이며 원문·소유권·metadata를 클라이언트가 바꿀 수 없다.

행 잠금의 선례는 [PostgreSQL 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html),
함수 권한은 [Supabase DB 함수 문서](https://supabase.com/docs/guides/database/functions)를
확인했다. PGlite의 직렬 처리 결과를 실제 두 원격 접속의 잠금 시간 측정으로 표현하지 않는다.

## 검수 기록

- SQL/전송/기존 편집·사전 승격 계약 4파일 47개 통과. 다른 토큰/같은 토큰,
  응답 유실 재시도, 원문·토큰 변경, 분석 중, 잘못된 필드, 소유권·비로그인·권한 회수,
  발췌 거부 및 개인 단어 보존을 검사한다.
- 첫 전체 단위 실행은 기존 문자열 계약 1개가 이전 onSave 서명을 기대해 실패했다
  (4,604 통과/1 실패/기존 1 skip). 새 입력 스냅샷 전달을 검사하도록 계약을 갱신했다.
  최종 전체 검사 결과는 아래 최종 후보 기록/CI에서 확인한다.
- 첫 로컬 UI 시도는 샌드박스의 포트 바인드 거부와 실행 중 테스트 파일 변경으로 실패했다.
  같은 제품 빌드를 사용한 디버그 실행에서는 Chromium·WebKit 각각 10체크,
  기존 화면 기준 3개와 오류 0/정리 완료를 확인했다. 최종 재검수로 합산하지 않는다.
- 충돌 확인 이후 키보드 초점, 직접 입력 충돌, 서버 반영 후 응답 유실까지 보강했다.
  검사 스크립트 형식을 마무리하는 동안 시작한 빌드 한 건은 중단했다.
  최종 소스가 고정된 뒤 새 빌드와 두 엔진 검수를 수행한다.
- 전체 단위를 2 worker로 제한한 재실행도 로컬 빌드와 자원 경합이 생겨 중단했다.
  해당 실행의 건너뛴 테스트를 정상 skip이나 PASS로 세지 않는다. 전체 필수 결과는
  독립 원격 CI로 확인하며, 제품/검사의 시간 제한을 늘려 실패를 숨기지 않는다.
- 최종 제품의 새 빌드 `pjzqT9EVeCX8DRiPzs2GJ`와 `qa:reader-app` 두 엔진이 통과했다.
  각각 11체크, 기존 화면 기준 3개, 브라우저 오류 0, 모든 자원 정리 완료.
  `.qa/runs/2026-09-24T12-09-02-207Z-50937/`의 입력 지문은
  `db820afc14972ce65b0c1bb056285a76eba66ebe9273c65d9e62dcb5afc9f10c`이다.
  이후 **검사만** 직전 성공 알림의 실제 해제를 기다린 뒤 화면을 찍도록 바꿨다.
  직전의 2.7초 고정 대기는 기존 4초 알림이 화면에 남을 수 있었다. 제품 코드·화면
  허용치는 불변이며 동일 앱 빌드로 다시 확인하고 최종 원격 CI에는 이 검사까지 포함한다.
- 빌드와 분리해 다시 실행한 전체 단위는 431파일/4,607개 PASS(기존 1 skip).
- 최종 화면 직접 확인에서 **새 충돌 버튼의 글자 대비 2.56:1**을 발견했다.
  기존 ghost 글자색 규칙과 footer의 진한 배경 규칙이 겹친 원인이다. 새 접근성 검사가
  수정 전 실제 앱에서 `color-contrast` serious 실패를 내는 것을 재현했다. 버튼에
  기존 primary 변형을 사용해 흰 글자를 유지하고, 충돌 안내 접근성 검사를 필수로 추가했다.
  이 보완 이후의 새 빌드/두 엔진/전체 CI를 최종 근거로 요구한다. 기존 비교 기준·오차는 그대로다.
- 운영 DB는 읽기 전용으로 사전 확인했다. reading_materials의 bigint ID/jsonb 분석,
  RLS, authenticated SELECT/UPDATE, 기존 원본/발췌 보호 트리거 3개를 확인했다.
  새 함수는 아직 없으며 기존 행을 읽거나 변경하지 않았다. 보호 트리거의 조건은
  일반 토큰 부분 갱신과 충돌하지 않으며 발췌 자료는 새 함수에서도 거부한다.

최종 자동 검사·실제 화면 증거·정확한 head는 PR #1321 및 해당 head의 #150 인계,
로컬 `qa:closeout` 기록이 정본이다. 앞선 디버그나 과거 제품 검수로 대체하지 않는다.

## 적용 순서와 한계

1. 최종 코드·SQL·검수 결과를 draft PR에서 검토한다.
2. 별도 오너 승인 후 위 함수 한 건만 DB에 적용한다. 미적용 목록과 함수 정의·권한을
   다시 비교하고, 이력 파일명이 달라지면 실제 이력과 정합화한다. 다른 migration을 묶지 않는다.
3. DB 준비 뒤 새 Preview를 검수하고 고정 QA 주소를 갱신한다. DB가 없는 채 새 UI를
   현재 사용 중인 QA alias나 운영으로 전환하지 않는다.
4. 실계정의 자체 검수 자료로 저장/재접속/다른 창 확인을 마친다. 통합 수업 출시의
   교사·학생 및 물리 iPad/Pencil 확인은 별도이며 이 후속으로 자동 완료되지 않는다.

이번 보호는 업데이트된 교정 경로에 적용된다. 이전 배포의 전체 JSON 저장, 일반 자료의
재분석 완료 등 다른 작성 경로까지 모두 원자화했다고 주장하지 않는다. 개인 단어 수정과
공개 사전 승격은 별도의 명시 동작이다. 기존 교정 로그도 종전처럼 최선 노력 기록이며
자료 변경과 로그 추가를 한 트랜잭션으로 바꾼 것은 아니다.

## 결과 리뷰와 다음 방향

핵심은 새 기능 수가 아니라 기존 읽기 → 뜻 확인/수정 → 저장 → 본문 복귀의 신뢰성이다.
수정하려던 입력과 다른 창의 최신값을 동시에 보존하고 선택권을 남긴다. 자동 검사와
운영 적용을 분리하며, DB 미적용 상태를 완료로 표시하지 않는다.

다음 우선순위는 이 함수의 승인된 DB 적용·실계정 검수다. 그와 독립적으로 진행 가능한
교재 작업은 [N5 감사](n5-edition-audit-20260924.md)에서 선정한 42과/긴 과 학습 경로와
누적 복습의 새 판본 초안이다. 새 음성·PDF·전체 목차 재작성은 이번 범위에 포함하지 않는다.
