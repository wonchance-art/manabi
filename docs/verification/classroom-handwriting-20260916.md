## 적용

- 교사 설명판 선택 메뉴에 필기 인식 진입점을 연결한다. 개인 노트와 동일한 선택 PNG 생성, 명시적 Google Gemini 전송, 인식 결과 정규화를 재사용한다.
- 서버는 쿠키 세션과 팀 루트 소유권으로 교사 권한을 확인한다. 클라이언트가 보낸 언어 대신 실제 팀 언어를 사용하고 완료 시 소유권·언어를 다시 확인한다. 학생용 팀 암호나 전역 관리자 역할은 이 권한을 대신하지 않는다.
- 설명판은 기기에 저장된다. 서버가 가지지 않은 판의 revision 검증을 흉내 내지 않는다. 클라이언트는 원래 선택 요소의 fingerprint와 버전을 요청 전/후 및 배치 직전에 확인한다.
- 인식 중 선택 밖에는 필기를 계속할 수 있다. 닫기/취소·원문 변경·페이지 이동 후 도착한 결과는 적용하지 않는다.
- 원문, 한자 후보와 한국어 뜻을 함께 검토한다. 첫 AI 후보·의미가 자동 확정되지 않는다. 직접 수정·원문 표기 유지·여러 후보 선택을 제공한다.
- 기존 표현 요소를 그대로 사용한다. 읽기 위·훈음 아래·뜻 오른쪽·테두리 옵션 및 원래 자유 필기는 보존한다.
- 배치 후 결과 패널은 작은 버튼으로 접히며 원래 후보를 다시 열 수 있다. 모바일에서 배치한 표현을 결과창이 가리지 않게 한다.
- 현재 화면의 빈 공간에 배치한다. 부족하면 명시적으로 새 판을 선택하게 한다. 인식 결과의 출처 식별자를 기기에 보관해 같은 영역 재인식 시 기존 표현을 선택한다.
- 판에 놓기는 학생용 수업 기록이나 개인 어휘 저장을 하지 않는다. 기존 ‘수업에 남기기’를 별도로 실행해야 한다.

## 실계정 개인 노트 검수

기존 1uoqwksoa 미리보기에서 오너 로그인 후 확인했다.

- 검수용 비공개 개인 노트 생성, 가나 글상자 `はし` 입력·서버 저장.
- 실제 Gemini 응답: 箸/젓가락, 橋/다리, 端/끝·모퉁이. 이는 입력 글자의 이미지 검수이며 자연 필체 정확도 검수와 다르다.
- 사용자가 검토하는 흐름으로 箸/젓가락 선택 → 실제 개인 단어장에 새 단어 1개 담기 성공.
- 원래 필기 복귀 → 새로고침 후 `はし` 원문 및 저장된 箸/젓가락 유지. 실제 단어장에서 箸 상세의 출처를 누르면 기존 viewer 주소에서 개인 노트로 복귀하며 원래 가나와 펜 획이 유지되는 것도 확인했다.
- 펜 도구의 세 획으로 그린 大만 선택 → 실제 Gemini가 大/だい/크다로 인식. 기존 가나는 선택 이미지 밖에 있었다. 이 획은 에이전트가 마우스로 만든 검수 표본이다.
- 중국어 노트에서도 펜 획 大 → 大/dà/크다 응답을 확인했다. 동시에 大夫의 뜻인 의사를 大 후보에 넣는 과잉 해석을 발견했다. 공통 프롬프트에 보이지 않는 합성어의 뜻을 부분 글자에 붙이지 않도록 보강했다. 이 보강의 실제 모델 재검수는 최종 배포에서 확인하며, 모델 정확도를 보장하지 않는다.
- 여러 실제 필체의 정확도·정량 응답 시간·물리 iPad/Pencil·다른 기기 동시 편집은 이 결과로 검증했다고 주장하지 않는다.
- 검수 노트/새 단어는 오너 계정에 비공개로 보관되어 있다. 기존 공부 자료는 수정하지 않았다. 공개 문서에는 계정이나 개인 노트 주소를 포함하지 않는다.

## 자동 검수 진행

- 공통 개인 노트 인식 기존 테스트 10개 통과.
- 신규 교사 권한/후보/배치 + 기존 노트/디자인 계약 5파일 62테스트 통과.
- 변경 JS 및 JSX 명시적 ESLint 오류·경고 0.
- 전체 Vitest/최종 build/브라우저 흐름은 실행 결과를 아래 갱신한다. 빌드와 첫 전체 테스트 동시 실행에서 기존 studiesRefs 준비 단계가 60초를 넘겼다. 첫 전체 실행은 399파일/4,253테스트 통과, 해당 1파일/4테스트 준비 시간 초과로 종료했으며 순차 재실행한다. forks 실행에서 같은 준비 시간 초과를 재현했다. threads pool·4GiB 힙의 단독 검사는 14.63초/4테스트 통과했다. 기존 테스트 코드는 바꾸지 않는다.
