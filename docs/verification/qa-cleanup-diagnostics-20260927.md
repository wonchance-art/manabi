# 수업 검수의 브라우저 종료 진단

2026-09-27 KST · PR #1321의 승인된 검수 자동화 후속.

## 문제와 결과

N5 교정본 `440a4966`의 CI 첫 실행은 수업 WebKit 48항목·앱 오류0 이후
browser 종료에서 30초를 넘겼다. context36ms·DB4ms, 같은 코드 재검수는 통과했다.
앞선 후보에도 같은 종류의 실패가 있어 재실행만 반복하지 않고 증거 누락을 보완했다.

기존 `finishQa`는 화면 단언 실패가 없으면 trace를 버린 다음 자원을 닫았다.
따라서 종료에서만 실패하면 직전 화면·호출의 추적 파일이 남지 않았다.
작은 재현 fixture에서 이전 코드의 추적 파일 부재를 확인했고, 수정 후 동일 실패의 파일을 보존했다.
최종 보고서 기록만 실패할 때도 파일이 남도록, 기록을 확정한 뒤 추적 파일을 지운다. 이 순서의 전후 재현도 확인했다.

- 활성 context의 trace를 종료 전에 내보내고, 검사와 모든 정리가 성공한 경우에만 삭제.
- 기존 보고서에 진행 중인 종료 단계·자원별 시간·종료 전후 연결 여부와 context/page 개수 기록.
- RSS는 검사 Node 프로세스의 값이며 브라우저 전체 메모리 사용량으로 해석하지 않음.
- 기존 `writeJson`으로 보고서를 원자적으로 기록. 기록 실패나 한 자원 종료 실패에도 나머지 정리 시도.
- 진단에는 URL·본문·쿠키·저장소·프로세스 인자를 읽거나 넣지 않음.
- 기존 30초/15초 제한과 실패 판정·증거 재사용 거절 유지. 자동 재시도·새 프레임워크 없음.

| 기존 수단/선례 | 적용 판단 |
|---|---|
| 공통 qa-runtime·writeJson·아티팩트 수집기 | 재사용. 보고서와 기존 failure-trace.zip 형식 유지 |
| Playwright 공개 tracing/context/browser API | 채택. context를 browser보다 먼저 닫는 기존 순서 유지 |
| 제한 시간 상향·종료 실패 무시·private process 필드 접근 | 배제. 원인 증거가 없고 실패를 숨기거나 버전 의존성을 늘림 |

[Playwright tracing 문서](https://playwright.dev/docs/api/class-tracing)는 종료 전에 trace를 파일로 내보내는 API를 제공한다.
[Browser 문서](https://playwright.dev/docs/api/class-browser)는 명시적 context를 browser보다 먼저 닫도록 권장한다.
외부 사례를 실제 CI 실패의 근본 원인 증거로 사용하지 않았다.

## 결과 리뷰와 로드맵

닫힌 조건은 **종료 실패에서 진단 증거가 사라지는 문제**다.
WebKit 지연의 근본 원인·OS 프로세스 종료 보증·실계정 출시 조건을 해결했다는 의미가 아니다.
실패가 다시 발생하면 연결/창 수/단계/trace를 근거로 원인을 좁히며, 녹색 결과만 얻으려 반복 실행하지 않는다.

제품상 다음 최우선은 정상 Preview 로그인과 실제 노트 복구·교사 설명판 재사용·별도 학생의
직접 저장→복습→출처 복귀다. 접근 조건이 그대로이면 같은 콘솔 확인이나 승인 질문을 반복하지 않는다.
이 보강 후 추가 근거 없이 검수 도구나 작은 문구 수정을 연달아 늘리지 않는다.
운영 출시·N5 별도 발행·독립 감수·물리 기기 확인은 계속 구분한다. PDF/새 음성은 보류다.
