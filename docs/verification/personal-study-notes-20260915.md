# 개인 학습 노트 → 단어 정리

2026-09-15 KST. 사용자 요청: 수업을 가르칠 때뿐 아니라 참여하면서 적은 노트를 바탕으로 개인 단어를 한 번에 정리한다. 승인한 설계의 개인 보관·글자/표현 정리 단계를 구현했다.

## 적용

- `/materials/add`의 ‘필기 노트로 작성’, 읽기 뷰어의 학습 메뉴에서 개인 노트 생성. `/notes/new`, `/notes/{id}`.
- 기존 Excalidraw 설명판을 공통 캔버스로 추출. 개인 노트는 교사·팀 권한 없이 사용하며 수업 기록에 자동 게시하지 않는다.
- 여러 표현, 자유 필기, 글자 도구, 페이지, 표시 토글, 기존 내 단어 검색을 유지한다.
- ‘단어 정리’는 입력된 표현 요소와 글상자 여러 줄을 모은다. `표현 → 뜻` 형식을 인식하고 원래 위치·필기는 보존한다.
- 원래 필기와 후보를 함께 보면서 표기·읽기·뜻·기본형을 수정한다. 저장된 가나 색인과 사전에서 한자 후보를 찾고 사용자가 선택한다.
- 검토한 항목만 기존 어휘 저장 API로 보낸다. 뜻 충돌은 명시적으로 확인하며 성공·기존 연결·실패 결과를 나눠 표시하고 실패분을 재시도한다.
- 단어 출처에서 해당 개인 노트·페이지·요소로 돌아간다. 모바일의 원래 필기 동작은 정리 패널을 닫고 캔버스를 보여준다.

## 저장·권한

새 테이블, 운영 DB 변경, 환경 변수 변경은 없다.

- 기존 `reading_materials`의 소유자 전용 `visibility=private`, `direction=write` 행을 사용한다. `processed_json.metadata.studyNote`에 캔버스와 정리 목록을 보관한다. 생성 재시도는 기존 importAttempt 고유 색인을 재사용한다.
- API는 로그인과 소유자·비공개 상태를 명시적으로 검사한다. 캔버스 형식, 노트 용량, 후보 개수·언어·식별자를 검사한다. 일반 자료를 노트로 덮어쓰지 않는다.
- 서버 수정은 이전 revision을 조건으로 비교 후 갱신한다. 요청 응답이 사라지면 서버 내용을 다시 읽어 JSONB 키 순서와 무관하게 같은 내용인지 확인한다.
- 기기 초안은 기존 IndexedDB의 계정+노트 식별자 및 원자적 revision 비교를 재사용한다. 충돌 시 다른 기기 내용을 덮어쓰지 않고 내 초안을 JSON 백업하거나 새 개인 노트로 보관한다.
- 기존 어휘의 뜻·복습 일정·학습 등급은 수정하지 않는다. 서버는 클라이언트 단어 본문 대신 자기 노트의 검토 완료 후보를 다시 읽어 출처와 저장 내용을 결정한다.
- 기존 고급 보관 도구에서 개인 학습 노트의 공개 전환 버튼을 제외했다.
- 원래 교재는 기존 접근 검사를 통과한 읽기 자료만 연결한다. 학생·팀 자료 권한을 새로 부여하지 않는다.

## 검수

자동 테스트와 브라우저 픽스처는 합성 계정·합성 필기만 사용했다. 운영 계정 검수로 간주하지 않는다.

- 전체 Vitest: 396개 파일, 4,238개 테스트 통과. 추가된 순수 모델/API 테스트 17개 포함.
- 변경 JSX/JS 범위 ESLint: 오류·경고 0. 저장소 기본 설정이 JSX를 제외하므로 임시 검사 설정으로 JSX도 포함했다.
- 저장소 `npm run lint` 통과. 기존 익명 default export 경고 2개는 이번 변경 범위 밖이다.
- `npm run build` 통과(Next 15.5.21, Node 24.20.0, QA용 공개 변수와 폰트 fixture). 최초 기본 힙 한도에서는 메모리 부족으로 실패했으며 `NODE_OPTIONS=--max-old-space-size=6144`로 재실행했다. 운영 환경 변수나 Node 버전은 변경하지 않았다.
- Chromium 개인 노트 흐름: 학생 계정 생성, 가나→한자 선택, 뜻 충돌 확인, 부분 실패 재시도, 기존 FSRS 불변, 원문 필기 좌표 보존, 새로고침, 중복 정리, 모바일 전체 화면, 키보드 이동, 응답 유실 복구, 충돌 백업·새 노트 보관.
- PostgreSQL: 폐기용 PGlite에서 기존 `save_vocabulary_context` 실제 SQL을 실행했다. 기존 카드 전체 행이 바뀌지 않고 새 단어/문맥만 늘어남을 검사했다. Next UI의 HTTP 응답은 해당 픽스처로 제공하고, 실제 API 권한·CAS·위조 입력 방어는 별도 테스트했다.
- 기존 교사 설명판 회귀: 교재 출처, 여러 표현+필기, 표시·정렬·확대, 다시 열기, 교재 변경, 늦은 사전 응답, 수업 기록 저장, 태블릿/모바일, 기존 단어 창 동작 통과.
- WebKit: 동일 기능 흐름과 글자 도구의 여러 줄 정리까지 수행. 고의로 끊은 저장 응답은 예상된 전송 오류로 별도 기록한다.
- 모바일 정리창은 뒤쪽 캔버스의 초점을 차단하고 Tab 순환을 유지한다. 닫으면 단어 정리 버튼으로 돌아가며 Escape로도 닫을 수 있다.

## 남은 범위

- 자유 필기 획의 자동 문자 인식은 미구현이다. 이번 구현은 구조화된 표현과 입력된 글자를 정리한다. 화면에도 이 차이를 명시한다.
- 외부 Gemini로 필기 이미지/텍스트를 전송하는 인식 API 추가는 자동 승인 검토에서 거절되었다. 사용자 개인 노트 payload와 목적지에 대한 명시 승인이 없다는 이유다. 해당 API는 추가하지 않았으며 외부 AI 대체 경로로 우회하지 않았다.
- 인식 기능을 추가하려면 사용자가 선택한 영역의 이미지·글자만 Gemini에 보내는 범위와 목적지를 먼저 승인받아야 한다. 문서 전체·다른 노트·교재를 자동으로 함께 보내지 않는 설계를 권장한다.
- 물리 iPad/Pencil의 획 품질, 손바닥 접촉, OS 일본어 필기 입력, 실제 두 기기의 동시 편집은 별도 실기기 검수가 필요하다. 브라우저 에뮬레이션을 실기기 확인으로 표시하지 않는다.
- 외부 PDF·이미지·노트 앱 파일 반입, 문장 전체의 자동 형태소/의미 분류는 후속이다.
- 운영 병합·운영 배포는 이번 문서 작성으로 수행된 것이 아니다.
