오너의 “다음 할 일 진행” 후 “권장대로 ㄱㄱ”로 같은 언어·단어의 계정 전체 제외를 선택했다. 최신 main `9eb7a788df77c974c6a334e9f3469fa438c65b10` 기반 `codex/vocabulary-exclusion-20261001`, 작업 공간 `/private/tmp/manabi-vocabulary-exclusion-20261001`에서 구현한다. 이 승인은 구현·로컬 검수이며 새 운영 DB·Preview·실계정·병합/배포 승인이 아니다.

## 동작

```
얼마나 알겠어요?                         제외
[ 다시 ] [ 어려움 ] [ 알맞음 ] [ 쉬움 ]
```

제외 후 같은 자리는 `제외 해제`로 바뀌고 네 등급은 비활성화한다. 원문과 발음·뜻은 계속 읽는다. 새 단어·저장된 도래/미도래 카드 모두 같은 위치를 사용한다. 미저장 제외는 가짜 단어/점수/SRS를 만들지 않고 단어장의 작은 접힌 제외 목록에서도 해제할 수 있다. 개인 뜻·출처·과거 평가·일정은 변경하지 않는다. 해제는 원래 일정으로 재개하므로 지나간 예정일은 정상 도래한다.

언어와 기존 저장 기본형/이합사·NFC 정규화만 대조한다. 저장 카드 ID를 우선하고 같은 언어·기본형의 별칭도 제외한다. 여러 기존 카드의 뜻/행을 병합하지 않는다. 모호한 새 연결은 자동 선택하지 않는다. 연결 카드의 표기/언어 편집은 제외 항목의 키에도 반영하고 삭제 후에는 미저장 제외로 보존하고, 삭제한 카드 ID도 제외 기록에 남겨 오래된 오프라인 평가를 차단한다. 언어 미상 카드는 ID로 제외하되 기존 언어 열을 추측/수정하지 않는다.

## 기존 흐름에 적용

- 뷰어/단어장/교재 범위의 복습 대상과 홈·자료 목록·완독 뒤의 대기 수를 맞춘다. 저장 총계/읽기 적합도/과거 통계는 그대로 둔다.
- 기존 일일 Study의 도래·약점·산출·만남/레벨 어휘 후보에서도 제외한다. SQL active view가 조회 LIMIT 전에 필터를 적용한다. 기존 월드 QuestReview의 어휘 조회만 같은 view로 변경하며 신규 월드/자산 작업은 없다.
- 오프라인 대기 기록 중 현재 제외된 것은 삭제하거나 성공 처리하지 않는다. 다른 기록은 전송하고, 제외 해제 후 재시도할 수 있게 보존한다. 제외 상태 조회 실패를 빈 목록으로 처리하지 않는다.
- 오래된 탭의 평가/SRS 쓰기는 DB에서 차단한다. `55000 vocabulary_excluded`는 오프라인 성공으로 위장/재등록하지 않는다.
- 소유자별 캐시와 클릭 당시 계정 ID를 사용한다. 계정 변경·중복 클릭·다른 단어 선택 후 늦은 응답/실패가 현재 카드에 적용되지 않는다.

## SQL 후보와 적용 순서

[검수 SQL 후보](../sql/vocabulary-exclusion.sql)는 단어/SRS와 분리한 owner 테이블, invoker view/RPC, 본인 RLS, 오래된 쓰기 보호 및 삭제/표기 변경 트리거다. 기존 자료·단어·의미·일정·학습 기록을 이관하거나 삭제하지 않는다. 본인 범위의 짧은 어휘 쓰기를 행 잠금 전에 직렬화하여 새 단어 저장과 미저장 제외의 경쟁을 막는다.

운영 실행이나 migrations 편입은 아직 하지 않았다. 승인 후에는 대상 DB의 기존 열/제약·역할·트리거 및 Supabase invoker view 지원을 먼저 대조하고 정확한 SQL을 적용/검증한 뒤 같은 코드의 Preview를 배포한다. 이 순서를 거꾸로 하면 제외 상태를 확인할 수 없어 평가가 비활성화된다. 기존 서버 알림 경로의 view 읽기 권한도 대상 DB에서 확인해야 하며 관리자 계정을 확대하지 않는다. 환경 변수 변경은 없다.

앱을 이전 코드로 되돌릴 때에도 DB의 제외/쓰기 보호를 남겨 기존 제외 상태를 잃거나 다시 채점하지 않게 한다. 신규 객체 삭제를 기본 복원으로 제시하지 않는다. 운영 적용 전 SQL 실패/카운트/소유권 점검과 호환 복원 후보를 준비한다.

## 검수 기록

일회용 PGlite는 기존 의미/출처/SRS 열 보존, 저장·미저장·언어·삭제·표기 편집·구형 별칭·중복·본인 RLS·익명/다른 계정 거부를 확인한다. 실제 운영 SQL 검수나 동시 다중 세션 부하 검수를 대체하지 않는다.

새 실제 앱 합성 브라우저 검사와 기존 반응 속도 회귀 검사는 정상 계정의 학습 기능/발음 청감/물리 기기 증거가 아니다. 폰트와 음성은 로컬 fixture다. 최종 후보 head와 실제 검사 입력, 기대/실제·반례·남은 한계·다음 방향은 기존 qa-closeout 마무리 기록과 보드 자기 영역에 남긴다.

첫 전체 검사에서 기존 뷰어 문자열 앵커·테이블명 검사와 구형 오프라인 fixture가 새 계약과 달랐다. 네 등급/키보드/undo/전체 단어 행·오프라인 보존 주장은 유지하고 새 조회/제외 상태에 맞춰 fixture/앵커를 조정했다. 구형 스냅샷을 상태 없음으로 판단하지 않는 반례 검사를 추가했다. 첫 빌드는 로컬 Node 기본 heap 한도로 실패하여 8GiB heap으로 재검수한다. 제품 설정/검사 timeout/기존 뜻을 바꿔 우회하지 않는다.
