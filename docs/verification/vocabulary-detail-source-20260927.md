# 단어 상세 → 저장한 출처 복귀

## 문제와 변경

실제 개인 노트 검수에서 단어에 유효한 noteCandidate/page 문맥이 저장돼 있어도 상세창은
단순 `/viewer/:id` 주소만 열었다. 노트 자체는 보였지만 저장한 표현·페이지·정리 패널로
돌아갈 수 없었다. 기존 복습 카드의 `VocabularyContexts`와 `sourceHref`를 상세창에도
사용해 개인 노트, 일반 읽기, 수업 원본, PDF, 불변 교재 판본의 위치를 그대로 전달한다.

- 개인 뜻·학습 지표는 유지하고 중복된 출처 렌더러만 제거했다.
- 문맥을 조회하는 동안 구형 자료 링크가 먼저 나타나지 않는다. 실패 시 재시도와 유효한
  구형 출처를 제공한다. 출처가 없으면 빈 제목을 만들지 않는다.
- 여러 문맥은 접어서 보인다. 상세창에서는 출처 삭제를 제공하지 않는다.
- 새 탭으로 원문을 열고 상세창을 유지한다. 접힌 문맥의 숨은 링크는 키보드 초점 순서에서
  제외한다. WebKit의 기본 링크 건너뛰기에도 창 안의 링크까지 순서대로 이동하며,
  펼치기와 Tab/Shift+Tab/Escape 후 초점 복귀를 보존한다.
- 320px 검사에서 함께 발견한 기존 단어 목록의 고정 열 넘침을 수정했다. 작은 목록에서는
  뜻·예문을 다음 줄에 배치한다. 기존 화면 규약에 맞춘 이름 있는 container query를 사용한다.

기존 TanStack Query·React·공통 출처 해석기를 채택했다. 추가 의존성/중복 API/저장 모델은
필요하지 않다. API·DB·권한·개인 뜻·FSRS·노트 저장·교재 판본·발행 포인터는 변경하지 않았다.
