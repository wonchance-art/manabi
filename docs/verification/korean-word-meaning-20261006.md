## 사용자 결과와 보존 계약

새 한국어 카드에는 기본형의 어휘 뜻만 저장한다. 현재 모델 계약은 `lemma / lemmaStatus / lexicalMeaning` 3필드이며 캐시 버전은 `korean-word-meaning-v2`다. 문맥 뜻·문법 설명은 기존 `useViewerExplanation` 경로를 그대로 사용하고 새 생성 결과로 덮어쓰지 않는다. `가다`의 어휘 뜻 `去`와 표면형 `갔어요`의 문맥 뜻 `去了`를 구분한다. 기존 저장 뜻은 별도 영역에 그대로 표시한다. 모델이 기본형을 확정하지 못하거나 요청이 실패하면 자동 저장을 막고 읽기 도움을 유지한다.

본문·목록은 원문의 등록 토큰/UTF-16 범위를 사용한다. 목록에서 같은 기본형의 서로 다른 출현을 합치지 않는다. 원문 revision·계정·설명 언어·출현 위치별 후보를 캐시하며, 예전 문맥 뜻 캐시를 새 후보로 승격하지 않는다. 목록의 별표는 후보 생성부터 저장까지 한 번의 클릭으로 진행한다. 선택/계정/원문이 바뀌면 이전 요청으로 저장하지 않는다.

서버는 새 후보 봉투의 기본형·뜻·원문 revision·범위를 기존 소유권/원문 검사와 함께 확인하고 RPC 전에 봉투를 제거한다. 이는 구조·일관성 검사이며 의미 정답 판정이 아니다. 기존 클라이언트/수동 저장 계약은 유지한다. 기존 뜻·출처·일정·평가 이력·원문을 일괄 수정하지 않으며 DB/환경/FSRS 계약도 바꾸지 않는다.

## 현재 어휘 전용 후보의 의미 검수

기존 읽기 설명과 저장할 어휘 뜻의 생성 책임을 분리했다. 통합 후보의 문맥·문법 실패를 통과로 바꾸거나 생략해 합격률을 다시 계산하지 않는다. 문맥·문법은 기존 구현/캐시의 결과를 유지하므로 그 정확성을 새 어휘 출력으로 보증하지 않는다. 이 설계 조정으로 생성 출력 5필드가 3필드가 됐고, 기존 읽기 설명 경로의 보존을 별도의 브라우저 계약으로 확인한다.

어휘 전용 v1에서는 한국어 뜻에 `모듬하다`라는 부적절한 말이 나왔다. v2는 각 설명 언어로 간결한 풀이를 요구한다. v3의 추가 제약은 `vertical` 혼입과 오탈자를 만들었고, 한국어 추가 교정 호출도 근거 없는 세부사항을 덧붙여 채택하지 않았다. 따라서 현재 비교 가능한 최선의 후보인 v2를 draft로 보존하며 의미 gate를 FAIL로 유지한다.

v2는 개발 D 30건 + 회귀 H 18건 + 최초 미사용 N 18건, 총 66건을 생성했다. 구조 유효/기본형 일치는 66/66이고, M00의 판정표 대조에서는 65건 수락, N05 ko 1건 실패/미판정이다. 별도 잘못된 기본형 W01은 세 언어 모두 uncertain으로 판정했다. 같은 모델에게 점수를 매겨 승인받은 결과가 아니다.

남은 실패: `거미줄에 파리가 걸렸어요`의 `파리`를 `파리목에 속하는 곤충을 통틀어 이르는 말`이라고 풀이했다. 일상어의 뜻보다 넓고 학습자에게 불필요한 분류다. [국립생물자원관의 분류](https://species.nibr.go.kr/home/mainHome.do?contCd=009002&cont_link=009&ktsn=120000021520&subMenu=009002)에서도 파리목 아래 깔따구류를 확인할 수 있어 그대로 합격 처리하지 않았다. 특정 실패 단어의 기대값을 코드에 하드코딩하지 않았다.
