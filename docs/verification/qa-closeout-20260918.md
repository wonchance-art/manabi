방향 결정을 포함한다. 기존 #1321 검수 자동화의 후속이다.

## 적용

- AGENTS.md·CLAUDE.md에서 최종 재검수 → 결과 리뷰 → 다음 방향을 공통 마무리로 연결했다.
- `qa:closeout init/check`로 깨끗한 최종 후보를 기록하고, 체크/관찰/증거/반례/미해결/다음 방향을 검사한다.
- head/입력 변경, 수정된 증거, 사라진 근거, 필수 미실행, 불완전 리뷰, 의존 조건 누락을 거절한다.
  이전 성공 파일을 남겨 놓은 상태에서 코드가 달라져도 check가 이를 지우고 실패한다.
- 합성 QA 요약에도 후속 마무리를 표시했다. 합성 CI PASS를 실사용 또는 출시 완료로 올리지 않는다.
- 다음 후보는 우선순위·선택 이유·완료 조건·승인 상태를 가진다. 명령은 다음 작업을 실행하지 않는다.
- `.qa/closeouts`는 로컬 기록이며 기존 합성 아티팩트 업로드 범위 밖이다. 시크릿·Auth 상태를 넣지 않는다.

## 검증 범위

- 테스트는 최종 후보 변경, 증거 변경, 필수 실패/미실행, 선택 검사의 알려진 실패,
  재사용 사유 누락, 근거 없이 다음 과제 확대, 차단된 작업 선택을 다룬다.
- 임시 Git 저장소에서 init → 증거 작성 → review → 후속 필요 → 코드 변경/새 head 거절을 직접 실행한다.
  기존 기록 덮어쓰기와 심볼릭 링크도 거절한다.
- 관련 3파일 25개 PASS, 변경 실행 파일 ESLint·diff 검사 PASS.

  `.qa/closeouts/process-closeout-20260918`에 기록하고 정확한 최종 head/원격 결과는 #150에 남긴다.

## 결과 리뷰

이전 절차는 합성 실행 결과를 잘 모았지만, ‘그래서 사용자의 문제가 해결됐는가’와 ‘다음에
무엇을 할 것인가’는 인계 문장의 품질에 의존했다. 이제 작업 규약과 실행 가능한 마무리 기록에
두 항목을 연결했다. 최종 수정 이후의 재검수와 증거 보존을 함께 요구한다.

한계: 이 도구는 증거 무결성과 리뷰 누락을 검사한다. 에이전트가 적은 관찰의 진실성,
번역의 의미 정확성, 사용자의 만족을 자동 인증하지 않는다. 실제 동선 확인·독립 의미 검토·
필요한 기기 검수는 계속 필요하다. 아직 사용자 재지적 감소 효과를 관측하지 않았으므로
‘품질 상승 완료’나 점수 개선을 주장하지 않는다.
