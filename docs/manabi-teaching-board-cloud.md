2026-09-16 KST. 오너가 승인한 ‘설명판 계정 저장·복구·지난 판 열기’ 구현. 선행 #1316 head240e32d7 기반, 독립 `codex/teaching-board-cloud-20260916`. 개인 노트·학생 수업 기록·교재 주의점·SRS·필기 인식 공급자는 변경하지 않는다.

## 동작

- 기존 Excalidraw 판을 기기 IndexedDB에 먼저 보관한다. 변경 페이지를 비공개 Storage에 불변 해시 경로로 직접 업로드하고, 교사 계정 판의 작은 manifest만 revision 조건으로 갱신한다.
- 기존 6MiB/20판 한도를 유지한다. Vercel Function 요청/응답으로 큰 필기 JSON을 전송하지 않는다. 계정 저장 완료는 파일 업로드와 원자적 head 갱신 모두 성공한 뒤 표시한다.
- 기기별 확대·스크롤은 계정 문서에서 제외한다. 최초 복원 시 현재 기기의 카메라를 유지한다. 문서 내용·페이지·표현 출처·요소 식별자는 보존한다.
- 연결 실패 시 기기 초안, 저장 응답 유실 시 서버 내용 재확인, 동시 수정 시 별도 기기 복구본을 사용한다. 충돌 해결 버튼은 복구본을 만든 뒤 최신 판을 열며 복구본을 새 페이지로 가져올 수 있다.
- 같은 교사·불변 팀 루트 ID·수업일로 판을 찾는다. 기존 owner/team-key/day 기기 판과 기존 복구본도 읽고, 원본을 삭제하지 않은 채 계정 저장으로 옮긴다. 주소가 다른 Preview의 IDB는 접근할 수 없으므로 기존 JSON 백업/가져오기를 이용한다.
- 도구의 구름 아이콘은 저장 상태를, 전체 메뉴의 시계 아이콘은 지난 설명판 목록을 연다. 최근 100개 수업을 날짜로 찾고 같은 뷰어 경로에서 날짜만 바꿔 연다. 이전 수업에 사용한 과를 추정해 자동 변경하지 않는다.
- 학생 공개는 기존 ‘수업에 남기기’만 사용한다. 계정 백업·날짜 이동·필기 인식은 학생 기록에 쓰지 않는다.

## 저장 구조를 조정한 이유

기획에서는 reading_materials의 별도 유형을 우선 검토했다. 실제 classIndex는 서비스 권한으로 교사 원본을 읽고 metadata.team/book 관계로 학생에게 내주므로, 새 판을 그 조회 경로에 결합하는 비용과 공개 실수 위험이 크다. **class_teaching_boards**에는 저장 식별자·manifest만 둔다. 새로운 콘텐츠/단어 저장 체계는 만들지 않는다. 필기 엔진, 기기 CAS/복구, 계정 저장의 revision/응답 유실 처리, Supabase 클라이언트를 재사용한다.

- 새 테이블: 소유자+팀 루트+날짜 유일성, root FK 인덱스, RLS. 인증 역할은 자신의 유효한 교사 판 SELECT만 허용하고 직접 INSERT/UPDATE/DELETE 권한은 주지 않는다.
- 두 RPC는 의도적으로 좁힌 SECURITY DEFINER 쓰기 경로다. PUBLIC/anon 실행을 회수하고, auth.uid 및 실제 팀 루트 소유권을 매번 확인하며 고정 search_path를 쓴다. 익명·학생·다른 교사·권한 회수 후 호출은 거부한다. 커밋 시 행 잠금+expected revision으로 경쟁 쓰기를 막는다.
- 새 비공개 버킷 teaching-board-pages: JSON 전용 6MiB, owner/board/hash 경로와 교사 소유권을 검사한다. UPDATE/DELETE 정책 없이 기존 객체를 보존한다. 같은 이름의 버킷이 공개이거나 설정이 다르면 마이그레이션을 중단한다.
- API는 페이지 크기·내용 해시·board 스키마를 검증한 뒤 SQL 커밋한다. SQL도 manifest 크기·페이지 수/중복/총량·실제 업로드 존재/크기·작업 ID를 검사한다. 최근 직전 manifest를 보존한다.
- 교사 판은 reading_materials·학생 사본·서재 목록에 들어가지 않는다. 사용자 비밀키나 새 환경 변수는 추가하지 않는다.
