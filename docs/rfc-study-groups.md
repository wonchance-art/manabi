# RFC — 학습 그룹: 함께 읽는 소그룹 v1 (설계 준비 — 구현은 승인 후)

- 상태: **채택 — R1·R2 구현** (2026-08-23 오너 픽 "1번 소셜 설계 준비 ㄱㄱ"로 게시,
  같은 날 "1 승인, 나머지도 권고대로 ㄱㄱ"로 §9 전 항목 권고안 확정 — 방향 승인·정원
  8/1인 3그룹·초대 코드 전용·cohorts 존치·홈 카드·R3 무보상·주간 합계만.)
- 기준: `origin/main` `e2e2607`
- 근거: evaluation-and-strategy Phase 4 잔여 ❌ **"학습 그룹 — 같은 레벨/목표의
  학습자끼리 소규모 그룹. 공동 읽기 챌린지"**(★★★, 난이도 높음). §5 소셜 진단:
  "학습과 소셜이 연결되지 않음 · 학습 파트너/그룹 스터디 없음 · 포럼이 범용
  게시판이라 학습 맥락 희석".

## 1. 결론 (권고안 한 줄)

**"같은 자료를 함께 읽는 초대 코드 소그룹"** — 그룹이 이번 주 자료 하나를 같이
읽고(진도 나란히), 토론은 각자 읽은 데까지만 열리며(진도 게이트), 주간 거울을
그룹 합계로 나란히 본다(등수 없음). 경쟁·랭킹·연대책임이 아니라 **같이 읽는
독서 모임**이 우리 결이다. 3라운드 분할: R1 그룹 뼈대+주간 우리 → R2 같이
읽기+진도 게이트 토론 → R3 공동 목표(선택).

| 자산 | 상태 | 비고 |
|---|---|---|
| material_comments + ViewerComments | **UI+DB 실가동** | 자료별 플랫 댓글(≤500자, 공개 SELECT) — 현재 학습 소셜의 실재물 전부 |
| forum 4테이블 + notifications | DB만, UI 0 | 2026-03-29. 소비 코드 없음 |
| vocab_decks / vocab_deck_words | DB만, UI 0 | 2026-04-05 social.sql. 공유 덱 스키마 잠들어 있음 |

**진단 — 소셜 스키마 3세대의 무덤**: 포럼(3-29) → 공유 덱(4-05) → 기수제(6-13)가
전부 UI 없이 DB에 잠들어 있다. 공통점은 **학습 순환과 연결되지 않은 범용 소셜**을
스키마부터 만든 것(evaluation §5의 자체 진단과 일치). 이번 설계의 제1 제약:
**네 번째 무덤을 만들지 않는다** — 읽기 순환에 직접 꽂히는 최소 기능을 UI 목업
승인부터 시작하고, 스키마는 승인된 라운드 것만 신설한다.

## 3. 설계 원칙

1. **읽기 순환 직결** — 그룹의 중심 활동은 '같은 자료 읽기'다. 범용 게시판·피드 금지.
2. **압박 배제** — 등수·증감색·연대책임(멤버가 안 읽으면 그룹이 손해 보는 구조) 없음.
   주간 리포트의 "거울이지 성적표가 아니다" 결 그대로.
3. **원장 비공개, 합계만 공유** — 타인이 내 review_events·단어장을 읽는 RLS 확장은
   하지 않는다. 공유는 내가 스스로 밀어 넣는 주간 스냅샷(합계 숫자)뿐.
4. **결정적 계산만** — LLM 없음. 집계는 weeklyReport·growthStats 정본 재사용.
5. **UI-first 최소 스키마** — 라운드별 목업 승인 → 그 라운드의 테이블만 신설.

## 4. 설계 (권고안)

### 4.1 그룹 모델

- **초대 코드 전용 소그룹**(기본 8인, 상한 15 — StoryGraph 버디 리드 실증 규모).
  공개 탐색·자동 매칭 없음(모더레이션 인프라 비용, §8).
- 그룹 속성: 이름(≤40자)·언어(ja/fr/zh/en)·초대 코드. 유저 생성 텍스트는 그룹명
  하나로 최소화.
- 개설·참가·탈퇴는 누구나(cohorts의 관리자 전용 쓰기와 다른 지점). join_code
  검증·본인 행 삽입 RPC는 cohorts의 `join_cohort` 패턴 차용.

### 4.2 R1 — 그룹 뼈대 + "이번 주 우리" (주간 거울 합본)

- 그룹 만들기/코드 참가/나가기 + 멤버 목록.
- **이번 주 우리**: 각 멤버가 자기 주간 리포트 수치(buildWeeklyReport 산출 5축)를
  그룹 스냅샷 행으로 push(own-only upsert) → 멤버는 그룹의 스냅샷을 select해
  **그룹 합계**를 본다. 개인 축은 기본 비표시(합계만), 등수·정렬 없음.
- 무해성: 스냅샷 push 실패는 조용히 — 그룹 화면이 안 뜰 뿐 개인 학습 무영향.

### 4.3 R2 — 같이 읽기 + 진도 게이트 토론

- 그룹이 **이번 주 자료 1개**를 지정(서재에서 선택 — 그룹원 수준 참고용으로
  materialFit(i+1) 밴드를 선택 화면에 병기: "멤버 4명 중 3명에게 fit").
- 멤버별 진도 바: 각자 reading_progress 위치를 스냅샷에 동봉(material_pct) —
  나란히 보이되 순위 없음, "아직 안 읽음"도 담백하게.
- **진도 게이트 토론**(StoryGraph 메커니즘 자체 구현): 코멘트에 작성 시점의 내
  진도(%)가 찍히고, 내 진도보다 앞선 코멘트는 "🔒 3장 이후 댓글 2개 — 거기까지
  읽으면 열려요"로 접힌다. 스포일러 걱정 없이 완독 전에 토론 참여 가능 — 토론이
  본문으로 데려가는 **본문 귀환 정거장**이 된다.
- 토론 테이블은 material_comments 개조가 아니라 **그룹 스코프 신설**(공개 댓글
  RLS(SELECT true)와 혼선 방지 — 멤버만 select). 게이트는 v1 클라이언트 필터
  (원문이 멤버에게 이미 보이는 자료라 보안 아닌 UX 게이트 — RLS 강제는 후속 옵션).

### 4.4 R3 — 공동 목표 (선택 라운드)

- Duolingo Friends Quest 구조의 협동판: 주간 그룹 목표 1개(예: "함께 복습 300문항"
  — weeklyReport 축 재사용), 기여 비율 자유, **미달 페널티·보상 없음**(달성 시
  카드에 조용한 체크만). 보상 설계는 오너 결정 항목(§9-6).

## 6. 스키마 초안 (구현 승인 후 마이그레이션 코드로 — 하드리밋 준수)

```
study_groups         (id uuid, name ≤40, lang, join_code unique, capacity int default 8,
                      created_by, created_at)
study_group_members  (group_id, user_id, joined_at, PK(group_id,user_id))
study_group_reads    (group_id, week_start date, material_id, PK(group_id,week_start))   -- R2
study_group_snapshots(group_id, user_id, week_start, reviews, accuracy, added, met,
                      reads, material_pct, updated_at, PK(group_id,user_id,week_start))
study_group_comments (id, group_id, material_id, user_id, content ≤500, progress_pct,
                      created_at)                                                        -- R2
```

- RLS: 그룹·읽기·스냅샷·코멘트 select는 멤버만(`is_group_member` SECURITY DEFINER —
  cohorts 헬퍼 패턴), 스냅샷·코멘트 쓰기는 본인 행만, 참가는 RPC(`join_group`)로만.
- **개인 원장(review_events 등) RLS는 일절 건드리지 않는다** — 공유되는 것은 위
  스냅샷 숫자뿐(§3-3).

**cohorts 재사용 판단**: 테이블 직접 개조는 배제 권고 — 목적(관리자 개설 기수제
클래스·주차 커리큘럼) 자체가 다르고, lang CHECK 개조·팀 구조 제거 등 개조 비용이
신설보다 크다. 대신 **패턴 3종을 차용**한다(join_code + 참가 RPC + SECURITY
DEFINER 멤버십 헬퍼). cohorts 자체의 거취는 오너 결정(§9-4).

## 8. 비목표

- DM·팔로우·피드·공개 그룹 탐색·자동 매칭 (모더레이션 인프라 전제)
- 경쟁 리더보드·등수·연대책임 페널티 (압박 배제)
- 그룹 실시간 챗 신설 (world 챗은 게임 전용 존치 — 토론은 비동기 코멘트로 충분)
- 이메일·푸시 알림 발송, notifications UI 부활 (후속 gate — R1~R3 무알림으로 성립)
- LLM 개입 일체 (토론 요약·추천 문구 등)

## 9. 오너 결정 항목 (번호로 회신 가능)

1. **방향**: §4 권고안(R1 뼈대+주간 우리 → R2 같이 읽기+게이트 토론 → R3 공동 목표)
   승인 여부. R2를 1라운드로 당기는 축소판(그룹=자료 하나 중심)도 가능.
2. **규모**: 그룹 정원(권고 8, 상한 15) · 1인 가입 그룹 수(권고 v1은 3개 상한).
3. **공개성**: 초대 코드 전용(권고) vs 공개 그룹 탐색 추가.
4. **cohorts 거취**: 존치(추후 '클래스' 기능 후보로 보류 — 권고) vs 폐기 마이그레이션.
5. **진입 표면**: 홈 카드(권고) vs 프로필. (목업 B)
6. **R3 보상**: 없음(권고 — 달성 체크만) vs 소소한 보상(스탬프류 — 게임 루프 연동은
   별도 설계 필요).
7. **주간 우리 표시 단위**: 그룹 합계만(권고) vs 멤버별 병기(등수 없이 나열).

| 단계 | 내용 | 게이트 |
|---|---|---|
