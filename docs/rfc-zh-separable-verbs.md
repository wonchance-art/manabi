# RFC — 중국어 이합사(离合词) 인지: base_form 합류

- 상태: **승인·R4a 구현 완료**(오너 "ㄱㄱ" 2026-08-30 — 권장안 A+B·수동 시드 50.
  뷰어 문구(§6-3)는 R4b) · 분석 개선 로드맵 R4 (R1~R3 완료 후속, 2026-08-29)
- 소유: Claude · 선행: R1 zhTokenFix(#1169) · R2 경성 CEDICT층(#1170) · R3 HSK 계층(#1171)

## 1. 문제

이합사(吵架·见面·睡觉·洗澡…)는 사이에 조사·수량구가 끼면(吵过架·见了一面) 형태가
갈라진다. 우리 파이프라인은 중국어를 무굴절로 보고 **base_form = 표면형**을 계약으로
삼아 왔는데, 이합사 삽입형에서는 이 계약이 학습 순환을 끊는다: 학습자가 吵过架를
만나면 저장·만남 기록·FSRS가 吵(또는 通짜 토큰)에 붙고, 어휘의 실체인 **吵架**로는
아무것도 쌓이지 않는다.

## 2. 현행 실측 (2026-08-29, jieba-wasm — R1 후처리 반영 후)

| 입력 | 토큰열(실측) | 문제 |
|---|---|---|
| 他们吵架了 | 吵架/v · 了 | 연속형은 온전 — 문제 없음 |
| 从来没吵过架 | 从来/没/吵/过/架 (R1 되가름 후) | 吵 저장 — 吵架 미합류 |
| 他们吵了一架 | 吵/v · 了 · **一架/m** | O(架)가 양사구에 흡수 |
| 昨天见了一面 | 见/v · 了 · **一面/m** | 동상 (见面) |
| 睡了一觉 | 睡/v · 了 · **一觉/d** | 동상 (睡觉) + 오태그 |
| 洗过澡 / 结过婚 | **洗过澡/v · 结过婚/v (통짜!)** | 삽입형 자체가 사전 등재 — 뜻·저장 키가 삽입형 |
| 帮个忙 | **帮个/x** · 忙 | x-병합 쓰레기(R1 계열) |
| 我们明天见面 | 见面/**n** | 연속형 오태그(동사인데 n) — R3 수확 대상과 별개 건 |

세 가지 양상: ① V…O 분리형(O가 단독 또는 양사구 말미) ② 삽입형 통짜 토큰
③ x-병합 쓰레기. 저장 키 규약은 "기본형 우선"(ViewerPage `normalizeWordText`
— base_form 있으면 기본형, 없으면 표면형 폴백)이라, **base_form만 바로잡으면
단어장·만남·FSRS가 코드 변경 없이 합류한다** — fr 굴절 대응(§4.8, 활용형
base_form=원형)과 같은 모형이다. 계약상 이 RFC는 "base_form = 표면형"의
**첫 명시 예외**를 만든다(계약 테스트 문구 갱신 동반).

정본 형식: `src/lib/server/data/zhSeparable.json` — `{ "吵架": 1, ... }`(연속형 키).
V·O는 키에서 유도(첫 글자 = V, 마지막 글자 = O — 2자 이합사가 절대다수, 3자 이상은
v1 배제). 생성기 + 우주·형식 계약 테스트(R2·R3 선례).

## 4. 설계 — 감지 3계층 (전부 zhTokenFix 후처리, 스키마 무변경)

토큰열 후처리(fixZhTagged 뒤, 병음 배분 전)에서:

- **A. 통짜 삽입형 재지정**: 토큰이 `V + (过|了|着) + O` 3자이고 `VO`가 이합사
  사전에 있으면(洗过澡→洗澡) — 분할하지 않고 **base_form만 VO로** 재지정.
  표면·병음·조판 불변, 저장 키만 합류.
- **B. 분리형 근접 탐색**: V(1자) 토큰 뒤 **3토큰 이내**에 O가 오면
  (O 단독 토큰이거나, 수량구 캐리어(≤4자)의 **말미 글자**가 O — 一架·一面·一觉·
  一会儿天) V 토큰의 base_form을 VO로 재지정. 사이 토큰은 화이트리스트(상조사
  过/了/着·조사·수량구)만 허용 — 밖이면 즉시 중단·무개입(오탐 방지). O 토큰은
  건드리지 않는다(이중 계상 방지 — 한 만남은 한 단어).
  《구현 실측 보정 2026-08-30》 창 2→3: jieba가 수량구를 융합하면(吵了一架) O가
  +2, 융합하지 않으면(抽了 一根 烟) +3에 온다. V 태그는 v-계열 외에 고립 기본값
  실측 4종(x 되가름 조각·上下/f·理照/n·点/m)을 허용하되 시드 가입+회랑이 게이트.
  32문 오탐 스위프 0 확인.
- **C. x-병합 보수**: 帮个/x류는 R1의 x-조각 규칙 확장(개/量词 꼬리 분리)으로
  帮+个로 되가른 뒤 B가 잡는다(帮…忙).

실패 시 현행 수렴: 사전 밖·패턴 밖은 전부 무개입. 소급 없음(신규 분석부터 —
경성 사전과 동일 경계). 뜻 조회(fetchMeanings)는 base_form 키라 吵架의 뜻이
따라온다 — 별도 배선 불요.

## 5. 게이트·라운드

- 계약: 사전 우주·형식 전수 / 감지 정탐 스팟(표 2의 전 행) / 오탐 가드(화이트리스트
  밖 무개입 — 我吵他架 같은 비이합 구문 불변) / base 계약 예외 문구 갱신
  (tokenizeZh.test "base_form = 표면형" → "이합사 삽입형만 예외").
- 라운드: **R4a** 사전+감지 엔진+base 연결(이 RFC 승인 시) → **R4b** 뷰어 확인
  (단어 카드 기본형 병기 — fr 선례 UI 재사용, 필요 시 목업).

## 6. 오너 결정 항목

1. **감지 범위 v1** — A+B(상조사·수량구 삽입)까지인지, A만 보수적으로 시작할지.
2. **데이터 시드** — Wiktionary 3,121 전량 조달을 기다릴지, HSK 교차 수동 시드
   (상용 30~50)로 먼저 출발하고 대량은 후속할지. (권장: 수동 시드 선행 — 조달
   리스크와 분리, 상용 이합사가 학습 텍스트 출현의 대부분)
3. **뷰어 문구** — 삽입형 탭 시 카드에 "吵过架 → 기본형 吵架" 안내를 명시할지
   (fr 활용형 병기와 동일하게 자동 표기만 할지).

승인 회신 예: "R4a ㄱㄱ (A+B, 수동 시드)".
